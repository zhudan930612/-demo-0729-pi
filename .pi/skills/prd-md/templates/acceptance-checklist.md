# 验收清单（B3/B4 导出）

> 由 prd-md 技能定稿时与需求文档同时产出。
> 验收项编号与需求文档 B3/B4 一一对应，是唯一可执行的验收依据。
> 用途：验收 agent 的输入 + 验收执行记录。需求变更时必须与本清单同步。

## 验收清单

| 编号 | 验收项（行为断言） | 验证层级 | 验证方式 | 证据标准 | 状态 | 证据/备注 |
|------|-------------------|----------|----------|----------|------|-----------|
| 1.1 | 点击 X 出现 Y | [单测] | pytest 命令 | 命令 + 实际输出 | ☐ | |
| 1.2 | …… | [E2E-人工] | 用户操作 | 验证人 + 步骤 + 观察记录 + 确认 | ☐ | |

- 编号规则：功能模块.序号（1.1、1.2…），与需求文档 B3/B4 完全一致
- 状态取值：通过 / 失败 / 未执行；未执行 = 不通过
- 每条验收项必须含异常/边界路径的覆盖说明（数据为空/缺失/失败/无权限等）

## 测试边界（seams，需求定稿时冻结）

| 模块 | seam（公共接口/边界） | 说明 |
|------|----------------------|------|
| 模块1 | …… | 测试只在这些 seam 上写，不测内部实现 |

编码 agent 写测试时按此 seam 执行（配合 tdd 技能），不得另选 seam；验收 agent 核对测试是否按 seam 落地。

## 验证层级与证据标准约定

| 验证层级 | 证据标准 |
|----------|----------|
| [单测] | 测试命令 + 实际输出 |
| [数据脚本] | 命令 + 真实数据跑通输出 |
| [E2E-自动化] | 启动服务 + 浏览器/接口自动化操作 + 输出/截图 |
| [E2E-人工] | 验证人（用户或指定验收人）+ 操作步骤 + 观察结果 + 记录 + 确认 |

- 未执行不算通过；AI 无资格自称人工验证（AI 自跑 UI 点验只能算冒烟，不能算人工验证）
- 自动化优先：主观视觉/审美、真实渲染目视确认、真实交互体验与真实环境、业务合理性、最终用户接受（UAT）才允许 [E2E-人工]
- 需求文档定稿时每条验收项必须判定验证路径归属（自动化或人工），归属不清的验收项须改写

## 编码 agent 自测边界（供开发流程引用）

- 编码 agent 自测跑 [单测] / [数据脚本] 类验收项；[E2E-真实操作] 可冒烟（启动服务基本验证），但最终证据由验收 agent 出具
- 完成一个独立模块且该模块自测通过 → 提交（checkpoint）
