# 地块成片区划规则

> 适用范围：参保村地块按用户标注区域（红框）划分大户/团单/未参保。**以后有地块需要区划，直接按本规则执行**。
> 版本：v1.0（2026-08-19，基于龙江/大钱/清潭/新魏家庄/新三联 5 村实践固化）
> 关联：需求《docs/requirements/地块成片划分-V1需求.md》（A4 逐村确认记录）；程序化流程见技能 `parcel-region-annotation`。

## 一、核心原则

1. **用户标注区域为权威归属**：用户在地图上画的红框（区域）决定地块归属，算法指标（覆盖率、面积上限、50 亩分类）不覆盖标注。
2. **大户成片**：大户区域空间连续，区域内不允许出现团单地块；团单不得出现在红框区域内。
3. **规则按村确认**：归并阈值（mergeMeters）、未参保处理、红框范围每村单独与用户确认，不沿用上一村假设。
4. **确定性可复现**：固定配置（区域多边形）+ 固定输入 → 相同产物；产物为版本化只读 JSON。

## 二、区划规则（每村执行）

### R1 用户标注区域（红框）→ 大户
- 用户发参考图（红框标注大户区域），红框数量 = 大户数量（可 0 个：整个村一个团单）。
- 红框检测：原始红色像素簇**外轮廓**（cv2 findContours + approxPolyDP），**禁止骨架化/侵蚀收缩**；用户画的长方形可用 bbox 矩形。
- 红框像素 → 经纬度多边形（Web Mercator 反投影，校准 zoom/center 后），落盘 `scripts/data/{村代码}-regions-2025.json`。

### R2 区域内全部地块（含未参保）归大户
- 区域内（多边形内）的**全部参保地块归该大户**；区域内未参保块**转参保**归该大户。
- 大户之间空间连续：两个红框之间不允许夹团单/未参保地块。

### R3 归并规则按村确认（mergeMeters）
- 区域外与区域内地块质心距离 < mergeMeters 的块**级联归并**进最近区域（红框临近纳入）。
- mergeMeters 每村确认：龙江村 100（用户"红框临近纳入"）、大钱/新魏家庄/新三联 0（用户"黑框外的都是团单"）。
- 归并不得破坏大户成片判定（归并后同户最近邻仍 ≤200m）。

### R4 区域外参保地块 → 团单（一块一户）
- 红框外的参保地块每块独立 party，一块一户进唯一一张团单（同村同年同产品一张分户清单保单）。
- **团单不得出现在红框区域内**（硬约束）。

### R5 未参保处理按村确认
- 一般规则：区域内/归并的未参保 → 转参保归大户；区域外未参保 → 保留未参保。
- 每村保留清单（含 >50 亩块）随方案图给用户确认，不假设上一村标准（例：龙江村 83 全转参保；新魏家庄村 55.55 亩块 425 保留）。

### R6 区域模式忽略 50 亩单独出单规则
- 区域模式下按区域划分决定归属，**忽略 50 亩单独出单规则**：区域外 >50 亩单块也一块一户进团单（团单池）；聚类村（未标注村）保留 50 亩分类。

### R7 无红框模式（整个村一个团单）
- 用户可直接指示"整个村改成一个团单"（regions 为空）：全部参保地块一块一户进唯一团单，未参保按用户决定，覆盖占比 0 记录不报错。

### R8 红框范围以用户看图反馈为准
- 用户看图后要求扩展/收缩红框是常态（"下方/右侧/上面都要包含"）。按用户指示调整多边形边界（像素外扩/多边形扩展），重新归属并给用户确认。

### R9 判定标准
- 大户成片：同一大户任意地块到同户最近邻质心距离 ≤200m（链式连通，isolatedParcelIds 为空）；不限制整体跨度。
- 团单严格一块一户；大户片区间无重复归属；任一参保地块恰好归属一个大户或团单。
- 无覆盖率硬指标：报告记录每村大户覆盖参保面积实际占比。

## 三、执行流程（每村）

1. **收图与确认**：用户发参考图 → 确认村代码、红框数量；文字复述规则（R2/R3/R4/R5/R6 本村取值）获用户确认。
2. **红框检测**：外轮廓/bbox 提取红框像素；叠加图验证与用户红线重合。
3. **映射校准**：检测地块点 + label 网格搜索匹配 zoom/center；**project-check 强制验证**（label 投影 vs 图中地块，无系统性偏移才继续）。
4. **归属计算**：R1-R7 规则计算大户/团单/未参保归属。
5. **可视化确认**：PIL 生成划分图（大户色/团单/未参保 + 红框），给用户确认（红框对齐、区域完整、团单范围、未参保保留清单、数量）。
6. **固化**：区域多边形落盘 `scripts/data/{村代码}-regions-2025.json`（regions + mergeMeters），`prepare-policy-confirmation.py` 区域模式生成确认/fixture。
7. **验证并提交**：unittest、validate-policy-fixture --all、validate-data、check-codes、web test 全过；确定性两轮哈希一致；web/src 零改动；git 提交。
8. **同步文档**：需求文档 A4 记录用户确认与最终统计。

## 四、检查清单（每村必过）

- [ ] 规则复述已获用户确认（区域/团单/未参保/归并阈值/50 亩取舍）
- [ ] 红框用外轮廓/bbox 检测（无骨架收缩），叠加图验证重合
- [ ] project-check：label 投影与图中地块重合、无系统性偏移
- [ ] 归属定量验证：区域内 0 团单、大户成片（最近邻 ≤200m）、团单一块一户、无重复归属
- [ ] 未参保保留清单（含 >50 亩块）随方案图用户确认
- [ ] 可视化给用户确认后再固化（不要先固化再返工）
- [ ] 生成后：validate-policy-fixture --all / validate-data / check-codes / web test 全过、确定性两轮哈希一致、web/src 零改动
- [ ] 需求文档 A4 同步最终统计
- [ ] 新增区域村后同步：prepare REGION_CONFIGS、validate REGION_MODE_VILLAGES、聚类测试 OTHER 参考村（换成仍为聚类模式的村）

## 五、常见问题与坑（实践教训）

1. **红框骨架化/侵蚀会严重收缩**（实测 47~95px ≈ 200~400m 偏移）——必须用原始像素簇外轮廓。
2. **每张截图视图（zoom/center）不同**，必须独立校准，不能复用其他村的校准参数。
3. **像素→经纬度未做 project-check 前不要用于归属**（假设村级 fitBounds 会错）。
4. **cv2 approxPolyDP 对碎片化轮廓输出乱序顶点**，in_poly 会大面积判错——用户画的长方形用 bbox 矩形最稳，多边形须验证绕序。
5. **200m 链式延伸会把 99% 地块吸进大户**（用户否）；归并阈值（mergeMeters）先量化给用户确认。
6. **未参保处理不能假设**（龙江 782 转参保 vs 新魏家庄 425 保留，均用户拍板）——每村确认。
7. **红框范围常需按用户反馈扩展**（下方/右侧/上方）——先出方案图。
8. **用户可能直接指示特殊模式**（整个村一个团单）——prepare 支持 regions 空。
9. **检测点质量差时**（红框内农田色未检出、山体/居民区误检），缩小匹配范围到红框内检测点再校准。
10. **视觉模型判断颜色/对齐不可靠**（色觉误判）——对齐与归属用定量统计（框内色点计数、成片最近邻 ≤200m）。
