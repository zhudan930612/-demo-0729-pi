## 1. 文档目的

本文档独立记录本次新增的灾害风险需求，不修改或替代原有地图、下钻、影像和地块需求文档。

本期优先规划“查看台风”。后续用户提出的每个台风子功能，都必须先对照 APIHz 台风接口文档和真实返回结果判断支持程度，再决定是否纳入实现：

- API 直接支持；
- API 数据可由应用层组合实现；
- API 文档未确认；
- API 不支持，需要其他数据源或调整需求。

## 2. 功能范围

## 3. 查看台风总体流程

```text
灾害风险
└── 查看台风
    ├── 查询当前活动台风
    │   ├── 一个或多个活动台风：同时展示全部台风
    │   └── 没有活动台风：显示“当前无活动台风”
    └── 用户主动进入历史台风
        └── 默认查看当前自然年度
        ├── 底部历史时间轴
        ├── 历史台风逐点动画
        └── 右上角实时/历史台风列表
```

### 3.1 实时台风

- 用户点击“查看台风”后，系统首先查询当前时刻的全部活动台风；
- 当前存在一个或多个活动台风时，地图同时展示全部活动台风；
- 选择某个台风只改变右侧详情面板和地图高亮，不隐藏其他活动台风；
- 当前没有任何活动台风时，仅显示：

> **当前无活动台风**

- 无活动台风时不得自动切换或自动绘制历史台风，但保留用户主动进入历史台风查看的入口。

### 3.2 多台风独立性

每个活动台风必须独立保存和渲染：

```text
台风 A
├── 实际历史路径
├── 当前点
├── 未来预测路径
├── 风圈
├── 时间节点
└── 台风详情

台风 B
├── 实际历史路径
├── 当前点
├── 未来预测路径
├── 风圈
├── 时间节点
└── 台风详情
```

不得：

- 把多个台风的路径点合并成一条路径；
- 让多个台风共用当前台风详情；
- 因选中一个台风而隐藏其他活动台风；
- 用一个台风的风速、风圈或预测节点渲染另一个台风。

### 3.3 右侧台风路径面板

右侧显示“台风路径”信息面板和活动台风列表：

- 列表展示全部活动台风；
- 每个台风可独立展开或选择；
- 选中台风后展开该台风的时间节点和详情；
- 其他台风可以保持折叠，但地图图层继续保留；
- 选择时间节点后，只高亮对应台风的对应位置和信息，不影响其他台风显示；
- 当前选中台风使用更明显的路径、标签、风圈或中心点高亮。

每个台风详情至少包含：

- 台风编号；
- 中文名称和英文名称；
- 当前时间；
- 中心位置；
- 中心气压；
- 最大风速/风力；
- 移动方向；
- 移动速度。

### 3.4 实时台风图层

当前存在活动台风时，每个台风均展示：

- 实际历史路径和当前台风位置；
- 未来预测路径；
- 台风风圈；
- 固定的 24 小时定位警戒线；
- 固定的 48 小时定位警戒线。

图层必须通过图例、线型、颜色或填充明确区分，不得只依赖颜色传达含义。

## 4. 历史台风

- 历史台风查看由用户主动进入，不与实时台风状态混淆；
- 查看范围限定为当前自然年度，即当年 1 月 1 日 00:00 至当前时间；
- 数据查询直接使用当前年份参数 `year=当前年份`，不再合并前一年数据，也不使用滚动 365 天；
- 历史列表支持选择某一个台风；
- 选中后地图展示该台风的完整历史实际轨迹；
- 选择历史时间节点后，可查看该节点的位置、时间、中心气压、最大风速/风力、移动方向和移动速度；
- 历史台风列表、年份/时间范围选择、台风选择、地图路径和时间轴的组织方式参考用户提供的台风路径截图；
- 截图仅作为交互和信息呈现参考，不作为系统内的图片查看功能需求；
- 历史台风的预测路径、历史时刻风圈及历史定位警戒线，仅在数据源提供对应历史版本时展示；不可用估算图层冒充历史官方数据。

多台风历史查看时，所有已加载台风的全部历史点和路径均显示：

- 不抽稀；
- 不隐藏；
- 不合并；
- 不因为路径接近或重叠而删除任何点。

## 5. 历史台风时间轴、动画与列表

### 5.1 时间范围和数据查询

- 历史台风只查看当前自然年度，范围为当年 1 月 1 日 00:00 至当前时间；
- 数据查询直接使用 APIHz 的 `year=当前年份`，不合并前一年数据，不使用滚动 365 天；
- 按 `list.type` 分类：`type=start` 为实时台风，`type=stop` 为历史台风；
- 每条列表记录通过 `list.no1` 查询详情，使用 `datas[]` 获取历史节点；
- 历史时间轴只纳入当前自然年度内有历史节点的月份；
- 当前月份只展示到当前时间，不展示未来日期。

### 5.2 时间轴月份压缩和台风标签

底部使用日期时间轴展示当前自然年度的历史台风。时间轴不是固定显示完整 1—12 月，而是只显示实际存在历史台风节点的月份：

- 某月份没有任何历史台风节点时，不显示该月份；
- 空月份不占用时间轴展示空间；
- 月份刻度按有数据月份排列；
- 隐藏空月份后，月份之间的视觉距离不再严格等于真实日历距离，以紧凑和可读为优先。

每个历史台风标签的时间范围由其详情 `datas[]` 计算：

```text
开始时间 = datas[] 最早的 time_ymdh
结束时间 = datas[] 最晚的 time_ymdh
周期长度 = 结束时间 - 开始时间
```

- 标签沿台风实际起止时间放置；
- 标签长度与台风生成至结束的周期长度成正比；
- 周期越长，标签越长；周期越短，标签越短；
- 只有一个有效节点时使用最小可读宽度；
- 标签不得因为台风名称不同而使用相同固定宽度；
- 台风跨越自然年度时，时间轴只显示当前年度范围内的部分，详情路径是否展示接口返回的完整历史节点按选中展示规则处理。

### 5.3 时间轴展开和左右切换

需要评估时间轴展开后在桌面和窄视口下的长度。不得通过无限缩小字体或压缩标签解决拥挤问题。

V1 时间轴应支持在内容超出可用宽度时横向查看：

- 宽屏下尽可能展示当前自然年度内的全部有数据月份；
- 标签发生重叠或总宽度超出容器时，支持左右箭头或横向拖动切换时间轴视口；
- 左右切换只改变时间轴视口，不改变地图当前图层和选中台风；
- 月份刻度和台风标签随时间轴视口同步移动；
- 时间轴的当前选中台风始终保持可定位和可回看。

### 5.4 历史台风逐点动画

点击底部时间轴上的历史台风标签，地图对该台风执行从首节点到末节点的逐点路径动画。API 只提供完整 `datas[]`，动画由前端实现。

动画过程：

```text
显示第 1 个历史节点
→ 显示第 1 段路径和第 2 个节点
→ 显示第 2 段路径和第 3 个节点
→ ……
→ 显示最后一个节点和完整路径
```

规则：

- 节点按 `datas.time_ymdh` 升序播放；
- 每一步新增一个实际历史节点和与前一节点的路径线段；
- 节点颜色、直径和路径样式遵循历史路径点规则；
- 播放速度由前端控制，不按真实日期间隔等比例播放；
- 动画播放过程中可暂停、继续、重播；
- 播放结束后保留完整历史路径；
- 点击另一台风时停止当前动画，切换目标台风并从其首节点开始播放；
- 动画不改变 API 原始节点、不插值、不生成额外业务节点。

### 5.5 右上角实时/历史台风列表

右上角列表同步展示实时台风和历史台风：

```text
实时台风
├── type=start 的台风
└── 始终展示，不可移除

历史台风
├── type=stop 的台风
└── 可从当前地图展示中隐藏
```

- 实时台风始终保留在地图和列表中，不显示删除/擦除操作；
- 历史台风可以从当前地图和时间轴展示中隐藏；
- 隐藏历史台风只改变当前可见性，不删除 API 原始数据；
- 隐藏后可通过恢复入口重新展示；
- 隐藏历史台风不影响实时台风和其他历史台风；
- 列表展示、时间轴标签和地图图层必须同步。

三者同步规则：

- 点击右上角历史台风：时间轴高亮对应标签，地图选中该台风并开始逐点动画；
- 点击底部时间轴标签：右上角列表同步高亮，地图开始该台风动画；
- 点击地图上的历史路径或节点：右上角列表同步高亮，时间轴定位到对应台风；
- 隐藏历史台风：列表、时间轴和地图同步隐藏；
- 选择一个台风只改变对应详情和高亮，不隐藏其他实时台风。

## 6. 历史路径点视觉规则

### 6.1 点的基本含义

历史实际路径由按时间排列的固定观测点组成，每个点代表一个时间节点。点的颜色和基础直径由该节点的最大风速决定。

API 字段对应：

```text
datas.time_ymdh       时间点
datas.lat              纬度
datas.lon              经度
datas.wind_speed_ms    中心风速，单位米/秒
datas.intensity_code   强度代码
datas.intensity_text   强度中文名称
datas.intensity_desc   强度完整描述
```

### 6.2 固定颜色和尺寸

| 风速范围 | 强度 | 颜色 | HEX | 点直径 |
|---:|---|---|---|---:|
| `< 17.2 m/s` | 热带低压 | 蓝绿色 | `#14B8A6` | **5px** |
| `17.2–24.4 m/s` | 热带风暴 | 蓝色 | `#3B82F6` | **6px** |
| `24.5–32.6 m/s` | 强热带风暴 | 黄色 | `#FACC15` | **7px** |
| `32.7–41.4 m/s` | 台风 | 橙色 | `#F97316` | **8px** |
| `41.5–50.9 m/s` | 强台风 | 粉色 | `#E879F9` | **9px** |
| `≥ 51.0 m/s` | 超强台风 | 红色 | `#EF4444` | **10px** |

所有路径点统一使用：

```text
边框颜色：#334155
边框宽度：1px
```

上表中的点直径不包含选中态外圈、当前点光晕或其他交互叠加。

### 6.3 时间快照规则

每个路径点是一个固定时间快照：

```text
时间 T1 → 风速 V1 → 颜色 C1 + 大小 S1
时间 T2 → 风速 V2 → 颜色 C2 + 大小 S2
时间 T3 → 风速 V3 → 颜色 C3 + 大小 S3
```

- 点生成后颜色和直径固定；
- 不因后续节点或当前风速变化而重算历史点；
- 只有到达下一个时间节点时，才使用该节点风速新增并计算新点；
- 不使用当前风速统一刷新全部历史点；
- 不对历史点平滑、插值、抽稀或重新分级；
- V1 假设每个路径点都有有效风速；
- 若接口返回缺失或无效风速，属于数据异常，不使用其他字段猜测，也不套用默认颜色或大小。

### 6.4 当前点和选中点

颜色和基础直径表达风速强度，交互状态使用额外视觉叠加表达：

- 当前最新点：增加白色外圈或光晕；
- 用户选中点：增加高亮外圈；
- 普通历史点：仅显示对应颜色、尺寸和边框；
- 交互叠加不得改变风速对应的基础颜色和直径。

## 7. 多台风路径重叠

当多个台风路径接近或完全重叠时：

- 仍按各自真实经纬度和自身节点风速独立绘制；
- 不人为平移；
- 不人为错开；
- 不合并；
- 不删除重叠点；
- 不改变真实坐标。

通过以下方式解决辨识问题：

- 右侧台风列表独立选择；
- 选中台风的路径、路径点、中心点和标签置于更高层级并高亮；
- 未选中台风保留显示，但可降低显示优先级；
- 点击某台风或其时间节点时，只高亮和展示对应台风的对应节点；
- 完全重叠的点不做视觉偏移，使用台风列表和选中置顶作为独立选择入口。

## 8. 固定定位警戒线

### 8.1 业务定义

24 小时和 48 小时线采用中央气象台台风网使用的固定地理业务边界，正式名称为：

- **24 小时定位警戒线**：台风中心进入后，表示预计 24 小时内可能对我国有显著影响，并可能于 24 小时内登陆我国；
- **48 小时定位警戒线**：台风中心进入后，进入 48 小时定位警戒业务范围。

两条线：

- 不是台风风圈；
- 不是预测路径；
- 不是预测概率范围；
- 不是动态缓冲区；
- 不随台风中心移动；
- 不由台风 API 返回。

系统使用静态经纬度折线绘制，并可据此判断台风中心是否进入对应警戒区。

### 8.2 固定坐标

坐标顺序为 `[纬度, 经度]`，取中央气象台台风网当前前端 `guardLine()` 实现：

```ts
const guardLine24 = [
  [34.005024, 126.993568],
  [21.971252, 126.993568],
  [17.96586, 118.995521],
  [10.97105, 118.995521],
  [4.48627, 113.018959],
  [-0.035506, 104.998939],
]

const guardLine48 = [
  [-0.035506, 104.998939],
  [-0.035506, 119.962318],
  [14.96886, 131.981361],
  [33.959474, 131.981361],
]
```

### 8.3 目标样式

最终呈现参考用户提供的警戒线截图：

- 24 小时定位警戒线：黄色实线，靠近东经 127 度处纵向标注“24 小时警戒线”；
- 48 小时定位警戒线：蓝色虚线，靠近东经 132 度处纵向标注“48 小时警戒线”；
- 两条线为折线，不绘制填充区域；
- 两条线固定在地图上，与实际路径、预测路径和风圈分层显示；
- 图例和文字同时说明业务含义。

参考来源：

- [中央气象台台风网](https://typhoon.nmc.cn/web.html)
- [中国气象局：我国台风24小时警戒区涵盖中国南海全海域](https://www.cma.gov.cn/2011xzt/2013zhuant/2013tfzt/2013tfkjjz/201407/t20140721_253072.html)

## 9. APIHz 台风接口能力边界

文档地址：<https://www.apihz.cn/api/tianqitaifeng.html>

### 9.1 已确认支持

- 使用 `year` 获取一个年份的多个台风摘要列表；
- 每条列表记录包含唯一编号 `list.no1`、中英文名称和状态 `list.type`；
- 使用每条记录的 `no1` 分别查询单个台风详情；
- `datas`：单个台风的历史观测节点，包括时间、经纬度、气压、风速/强度、移动方向和移动速度；
- `forecast_babj`：单个台风的未来预报节点，包括预测时间、经纬度、气压、风速/强度和预报描述；
- `wind_radius`：单个台风的风圈数据，包括风圈等级及东北、东南、西南、西北四个象限半径。

因此，APIHz 支持：

```text
多个台风摘要列表
  → 按 no1 分别查询多个台风详情
  → 应用层同时展示多个台风
```

一次 `no` 详情请求只对应一个台风，不能一次获取所有台风的完整路径、预测路径和风圈。

### 9.2 尚未确认

APIHz 文档尚未确认：

- `year=当前年份` 是否直接等于全部当前活动台风列表；
- `list.type` 的 `start/stop` 是否严格等于“当前活动/已结束”；
- 台风活动状态的判定时间窗口；
- 数据更新时间和实时刷新频率。

正式接入前必须使用真实接口响应确认这些规则。在确认前，不得把年度列表直接当作实时活动列表，也不得仅凭 `start` 宣称台风当前仍在活动。

### 9.3 接入安全和查询规则

- API `id`、`key` 等凭据不得放入浏览器端代码或提交到仓库；
- 正式接入应通过受保护的服务端代理或同等安全中间层；
- 历史台风直接查询当前自然年度 `year=当前年份`，不合并前一年数据，不按滚动 365 天过滤；
- 24/48 小时定位警戒线使用系统内置固定坐标，不从 API 获取，不用风圈或预测路径缓冲代替。

## 10. 最新节点风圈与悬停弹窗

### 10.1 最新节点风圈

对每个实时台风，取其 `datas` 中时间最新的观测节点作为该台风的最近一次发布节点。最新节点以 API 返回的 `time_ymdh` 排序确定，不使用浏览器当前时间推算。

每个实时台风的最新节点独立展示：

- 当前中心标记；
- 当前节点对应的路径点颜色和基础直径；
- API 实际返回的各级风圈；
- 中心点悬停详情弹窗。

风圈数据来自该最新节点的 `datas.wind_radius`。优先使用四象限半径生成不规则风圈：

```text
ne_radius_km：东北
se_radius_km：东南
sw_radius_km：西南
nw_radius_km：西北
```

不得用 `avg_radius_km` 画成普通圆替代四象限风圈。`avg_radius_km` 只作为辅助统计值。API 未返回某个风圈等级时，只显示实际返回等级，不自行推算，不用其他等级或平均半径填充缺失数据。

### 10.2 中心点悬停弹窗

鼠标移动到实时台风最新中心图标时，展示该台风最新节点的完整弹窗；移出中心图标并进入风圈区域时，切换为对应风圈弹窗。多个台风各自拥有独立中心点和弹窗，不能混用字段。

中心点弹窗至少展示：

- 台风中文名称、英文名称和最新节点时间；
- 中心位置；
- 风速风力；
- 中心气压；
- 移速移向；
- 七级、十级、十二级半径；API 缺失的等级显示 `--`；
- 参考位置；
- 未来趋势。

参考展示结构：

```text
白海豚（DOLPHIN） 8月1日20时
中心位置       156.20° / 21.60°
风速风力       58米/秒，17级（超强台风）
中心气压       925百帕
移速移向       24公里/小时，西北西
七级半径       200-400公里
十级半径       120-160公里
十二级半径     70-90公里
参考位置       距离某地某方向约2940公里
未来趋势       将以每小时20-25公里的速度向西北方向移动，强度变化不大
```

### 10.3 风圈区域悬停弹窗

鼠标移动到某个风圈区域时，展示当前风圈等级和四象限半径信息，参考用户提供的风圈悬停截图：

```text
十级风圈
西北       东北
160km      160km
西南       东南
120km      160km
```

规则：

- 移入七级、十级或十二级风圈区域时，展示对应等级弹窗；
- 弹窗默认展示四个象限的全部半径，鼠标所在象限可额外高亮但不隐藏其他象限；
- 风圈重叠时，优先识别最内层、等级更高的风圈：十二级 > 十级 > 七级；
- 移出风圈区域时关闭风圈弹窗；
- 移入中心图标时切换为完整中心点弹窗；
- 风圈弹窗只展示当前实时台风、当前最新节点的数据。

### 10.4 参考位置

参考位置不得固定使用那霸市或任何单一地点。它应随台风的当前中心位置和数据源内容动态确定，不同台风或同一台风的不同时间节点可以使用不同参考地点。

优先级：

1. 如果数据源返回官方位置描述、公报原文或包含参考地点的自然语言，直接展示原始文案；
2. 如果数据源只返回经纬度，由应用层根据台风中心动态选择合适的地理参考地点，再计算相对方向和地表距离，生成系统计算文案；
3. 如果没有足够数据生成可靠文案，显示“暂无参考位置”，不得编造。

应用层计算文案格式：

```text
距离{参考地点}{方向}约{距离}公里
```

计算规则：

- 参考地点来自可维护的地点库，范围可包括菲律宾、台湾、日本琉球群岛、中国沿海及相关海域；
- 地点选择不能简单固定为最近城市，需要结合台风所在海域、相对位置、业务区域和公众熟悉度；
- 距离使用地表大圆距离，取整到公里；
- 方向使用台风中心相对参考地点的方位，转换为中文八方位；
- 应用层生成的文案必须标识为系统计算结果，不得冒充官方公报原文；
- APIHz 当前已确认经纬度字段，但未确认直接提供官方参考位置文案、动态参考地点、距离或方向字段。

### 10.5 未来趋势

未来趋势优先使用 API 原始预报描述，不得凭空编造：

1. 优先展示 `forecast_babj.forecast_desc`；
2. 没有完整预报描述时，使用 `move_desc`、`move_dir_text`、`move_speed_kmh` 及预测节点生成应用层文案；
3. 只有预测点时，根据预测节点的方向、速度和强度变化生成结构化文案；
4. 数据不足时显示“暂无预报信息”。

API 原文与应用层生成文案必须在数据来源上可区分。未来趋势可参考：

```text
将以每小时20-25公里的速度向西北方向移动，强度变化不大
```

### 10.6 API 能力边界

| 弹窗/风圈需求 | APIHz 状态 |
|---|---|
| 最新节点时间、中心位置 | 直接支持：`datas.time_ymdh`、`lat`、`lon` |
| 风速风力、中心气压、移速移向 | 直接支持：`wind_speed_ms`、`intensity_text`、`pressure_hpa`、`move_speed_kmh`、`move_dir_text` |
| 各级风圈和四象限半径 | 直接支持：`wind_radius` 及 `ne/se/sw/nw_radius_km` |
| 中心点悬停完整弹窗 | 应用层实现 |
| 风圈区域悬停弹窗 | 应用层实现 |
| 参考位置官方原文 | APIHz 文档未确认 |
| 参考位置距离和方向 | APIHz 文档未确认；仅有经纬度时由应用层计算 |
| 未来趋势原文 | 优先使用 `forecast_babj.forecast_desc`，真实字段内容需接入时确认 |
| 未来趋势结构化文案 | 应用层根据预测字段生成 |
| 缺失风圈等级显示 `--` | 应用层实现，不自行推算 |

## 11. 未来预测路线

### 11.1 数据来源和预测范围

V1 只展示 APIHz 台风接口提供的中国预测路线 `datas.forecast_babj[]`，不展示日本、中国台湾或美国预测路线。APIHz 文档和示例显示，预测节点可覆盖发布时刻之后最多 120 小时，即 5 天；例如发布为 8 月 1 日 23 时，最远预测节点可到 8 月 6 日 23 时。

120 小时是当前文档示例能确认的预测范围，不在需求中承诺每次响应永远返回 120 小时。实际展示范围以本次接口响应中 `forecast_hour` 的最大值为准：

- 最大值为 120：展示到 120 小时；
- 最大值小于 120：只展示 API 实际返回的范围；
- 不自行补足到 120 小时；
- 不根据历史路径或首尾点自行推算更远预测。

### 11.2 API 直接提供预测节点

未来预测点由 API 直接提供，应用层不负责生成未来位置、风速、气压或强度。`forecast_babj[]` 每个元素对应一个预测节点，包含：

```text
forecast_hour        未来第几小时
lat                  预测纬度
lon                  预测经度
position_text        预测位置
target_time_ymdh     API 时间字段
pressure_hpa         预测气压
wind_speed_ms        预测风速
intensity_code       预测强度代码
intensity_text       预测强度名称
forecast_desc        预测描述
```

前端按 `forecast_hour` 升序排序（若时效相同则保留 API 顺序），保留本次响应返回的全部预测节点，并依次连接形成一条预测路线：

```text
最新实际点
   │
   └── 虚线 → 12小时预测点
                 │
                 └── 虚线 → 24小时预测点
                               │
                               └── 虚线 → 后续 API 预测点
```

### 11.3 中间节点不自行插值

API 返回多少预测节点就展示多少预测节点。若响应包含 12、24、36、48、60、72、84、96、108、120 小时节点，全部保留；若只包含 12、24、48、72 小时，也只展示这些节点。

允许连接相邻 API 节点形成路线，但不允许：

- 只保留首尾点；
- 删除 API 已返回的中间节点；
- 自行补充 API 未返回的 18、36、60 等业务预测点；
- 对中间位置、风速、气压或强度做业务插值；
- 将插值结果冒充 API 预测节点。

V1 不做预测路径平滑或业务插值。地图线段直接连接相邻 API 原始节点。

### 11.4 预测点颜色和大小

预测点使用自身 `forecast_babj.wind_speed_ms`，沿用历史路径点同一套固定风速映射：

| 风速范围 | 颜色 | 点直径 |
|---:|---|---:|
| `< 17.2 m/s` | `#14B8A6` | 5px |
| `17.2–24.4 m/s` | `#3B82F6` | 6px |
| `24.5–32.6 m/s` | `#FACC15` | 7px |
| `32.7–41.4 m/s` | `#F97316` | 8px |
| `41.5–50.9 m/s` | `#E879F9` | 9px |
| `≥ 51.0 m/s` | `#EF4444` | 10px |

- 预测点统一使用 `#334155`、1px 边框；
- 预测路径使用虚线，历史实际路径使用实线；
- 颜色和点大小表达该节点的预测风速/强度，虚线和实线表达预测/实际状态；
- 预测点不使用当前实际风速统一渲染，也不使用历史点风速代替。

### 11.5 预测路线实时刷新

每次成功获取新的 `forecast_babj[]` 时，将其视为一整套最新预测快照，整体替换上一版预测路线：

```text
获取新 forecast_babj[]
    ↓
校验完整数据
    ↓
按本次响应整体生成新预测点和路线
    ↓
一次性替换旧预测图层和详情数据
```

新旧发布之间以下字段均可能变化：

- 预测点数量；
- 预测时效和最远时间；
- 预测位置；
- 预测风速；
- 预测气压；
- 预测风力和强度；
- 预测描述；
- 预测路线形状；
- 预测点颜色和直径。

因此不得把两次发布的节点合并，也不得只更新部分字段。新数据加载失败时，保留上一版完整预测快照，不清空、不显示部分新路线、不用部分新数据覆盖旧数据。

### 11.6 预测节点转为实际节点

当未来预测时效到达且新的 `datas[]` 返回对应实际观测节点时，使用实际数据替换预测数据：

- 位置使用 `datas.lat/lon`；
- 风速使用 `datas.wind_speed_ms`；
- 气压使用 `datas.pressure_hpa`；
- 强度使用 `datas.intensity_code`、`datas.intensity_text`；
- 颜色和点直径按实际风速重新计算；
- 路径由虚线切换为实线；
- 旧预测值不保留在当前实时路径中。

### 11.7 时间字段边界

API 文档把 `target_time_ymdh` 定义为“时间段时间”，公开示例中多个预测节点可能出现相同值，因此 V1 以 `forecast_hour` 作为主要预测时效展示字段，例如“12 小时后”“24 小时后”。`target_time_ymdh` 作为原始字段保存，接入真实接口后再确认其究竟是预报发布时间、起报时间还是预测有效时间；确认前不得单独把它当作预测有效时间。

API 未提供预测算法、轨迹推算公式或预测误差计算方法；应用层只读取 API 节点、排序、连接和渲染，不自行生成业务预测结果。

## 12. 台风功能状态

台风查看至少区分：

1. 未打开灾害风险工具；
2. 加载实时台风；
3. 存在一个活动台风；
4. 存在多个活动台风；
5. 当前无活动台风；
6. 查看历史台风；
7. 已选中台风；
8. 数据加载失败。

实时台风与历史台风的路径、状态文案和数据来源必须明确区分。

## 13. V1 验收标准

1. 右下角存在“灾害风险”入口，展开后可看到“查看台风”；“查看天气”保留规划位置但不实现具体功能。
2. 点击“查看台风”后，当前存在一个或多个活动台风时，地图同时展示全部活动台风。
3. 每个台风独立展示实际历史路径、当前点、预测路径和风圈；右侧列表可独立展开每个台风详情。
4. 选择某台风或时间节点只改变对应台风的详情和高亮，不隐藏其他台风。
5. 当前没有活动台风时，显示“当前无活动台风”，不自动展示历史台风。
6. 历史台风只查看当前自然年度，查询 `year=当前年份`；时间轴从当年 1 月 1 日延伸至当前时间，不合并前一年数据，也不使用滚动 365 天。
7. 历史时间轴只展示当前自然年度内存在台风节点的月份；没有台风的月份不显示；历史台风标签长度按 `datas[]` 实际起止周期计算。
8. 选择历史台风后，使用其 `datas[]` 按时间顺序从第一个节点逐点播放到最后一个节点；动画由前端实现，API 只提供历史节点。
9. 右上角列表同时展示 `type=start` 实时台风和 `type=stop` 历史台风；实时台风始终展示且不可移除，历史台风可隐藏但不删除原始数据；列表、时间轴和地图同步。
10. 时间轴展开后超出可用宽度时支持左右箭头或横向拖动；空月份不占用展示空间，标签重叠时不得无限压缩字体。
11. 所有历史路径点全部显示；路径点按风速表使用固定颜色、固定直径和统一边框。
12. 路径点生成后保持时间快照，不因后续风速变化重算；缺失风速按数据异常处理，不猜测、不默认降级。
13. 多台风路径接近或重叠时，各台风仍独立绘制，不抽稀、不合并、不隐藏、不人为平移。
14. 24 小时和 48 小时定位警戒线使用文档中的固定坐标；24 小时为黄色实线，48 小时为蓝色虚线，均有纵向文字标注。
15. 实际路径、预测路径、风圈和定位警戒线在图例、线型、颜色或填充上可明确区分。
16. APIHz 接入不暴露 `id`、`key`；实时/历史分类按 `list.type=start/stop`；正式接入前完成数据更新时间验证。
17. V1 只展示 APIHz 提供的 `forecast_babj[]` 中国预测路线；当前文档示例支持最远 120 小时（5 天），实际展示范围以本次响应 `forecast_hour` 最大值为准，不自行补足。
18. 预测路线展示 API 返回的全部节点，不只保留首尾点，不自行插值或生成未返回的业务预测点；预测点按自身预测风速沿用历史点颜色和直径规则。
19. 每次成功刷新整体替换上一版预测路线；新旧发布之间所有预测节点字段都允许变化，失败时保留上一版完整预测快照。
20. 预测时效到达并有实际 `datas[]` 后，使用实际数据替换对应预测节点，按实际风速重绘并由虚线切换为实线。
