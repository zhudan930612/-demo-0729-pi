# ADR-0007：地块区划区域模式按村配置架构

状态：采纳

## 背景

《地块成片划分-V1需求.md》初稿按算法路线（200m 链式聚类 + 500 亩切分 + 覆盖区间）实现后，用户拍板改为**用户标注区域（红框）划分**：龙江/大钱/清潭/新魏家庄/新三联 5 村已按红框标注完成，其余 8 村（地块少）保持聚类现状。实现层需要一个按村分派的确定性架构支撑两种模式共存。

## 决定

- **按村配置落盘**：每个标注村一个 `scripts/data/{村代码}-regions-2025.json`，含 `villageCode`、`assignmentModel: "user-annotated-regions-v1"`、`mergeMeters`（归并阈值，龙江 100、其余 0）、`regions`（红框多边形 [lng,lat] 列表；**可为空**=整个村一个团单）。
- **prepare 按 villageCode 分派**：`REGION_CONFIGS` 字典（标注村）vs 聚类逻辑（未标注村）；区域模式规则——区域内全部地块（含未参保）归大户 → 区域外 mergeMeters 内级联归并 → 其余参保块一块一户团单 → 区域外未参保保留（R5）。
- **区域模式忽略 50 亩单独出单规则**：用户标注区域为权威归属，区域外 >50 亩单块（清潭 39 号 67.69 亩、新三联 591 号 50.19 亩）也一块一户进团单；聚类村保留 50 亩分类。
- **500 亩上限放开**：区域大户面积由标注决定（龙江 886~1176 亩），不切分；聚类村保留 500 切分。
- **无覆盖率硬指标**：报告记录每村大户覆盖参保面积实际占比。
- **validate 双模式兼容**：`REGION_MODE_VILLAGES` 集合分派 assignmentModel 检查；成片判定（组内最近邻 ≤200m + isolatedParcelIds 空）两种模式均验证。
- **未参保集合可变化**：区域内/归并未参保转参保、区域外保留（龙江 83→0、大钱 37 转/10 保留等），每村经用户确认。

## 原因

- 用户以红框标注表达业务划分意图（大户成片、区域外团单），算法指标（覆盖率/500 上限/50 亩分类）与业务期望冲突，标注为权威。
- 按村配置保证确定性可复现（固定配置+固定输入→相同产物），产物为版本化只读 JSON。

## 被否方案

- **算法路线（200m 链式 + 500 切分 + 60~80% 覆盖）**：200m 链式延伸吸光 99% 地块（用户否）；覆盖区间与用户期望不符，全部推翻。
- **前端渲染区域/红框**：需求 C2 明确前端零改动，仅数据修正。

## 触发重开

- 新增标注村：落盘 regions 配置 + REGION_CONFIGS/REGION_MODE_VILLAGES/聚类测试 OTHER 参考村同步。
- 归并阈值、50 亩规则、未参保口径变更需需求变更流程。
