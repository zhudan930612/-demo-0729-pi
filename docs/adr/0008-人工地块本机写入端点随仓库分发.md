# ADR-0008：人工地块经本机写入端点落盘仓库静态文件并随仓库分发

状态：采纳（2026-08-24 拷打确认）

## 背景

人工地块（用户本机绘制的 `source:'manual'` Polygon）曾仅存浏览器 `localStorage`（key `agri-map:manual-parcels:v1`）。这带来三类问题：

1. 不入仓库 → 克隆者看不到已录入的人工地块；
2. 浏览器按 origin 隔离 localStorage → `http://localhost:5173` 与 `http://127.0.0.1:5173` 被当两个站点，人工地块各自一份、互相不可见，反复"地块不见了/不一致"；
3. 数据落单机浏览器 → 清缓存/换机器/换浏览器即丢，无版本追踪。

用户预期：**编辑保存的人工地块直接进仓库静态文件，加载也从静态文件读**——刷新不丢、克隆即见、克隆者也可编辑。

## 决定

- **人工地块改为可版本化、可分发数据**：存于 `web/public/business/manual-parcels.json`（运行时经 `/business/manual-parcels.json` 加载，与保单/种植档案同级），镜像副本 `web/src/data/manual-parcels.json`。
- **编辑经本机写入端点落盘**：前端编辑保存由「写 localStorage」改为「POST 本机写入端点 → 校验 → 覆盖写该村记录到静态文件」；前端加载从静态文件读。**刷新不丢、克隆即见**。
- **彻底弃用 localStorage 作为人工地块读取/保存来源**（消除人工地块本体的 origin 分叉）。
- **克隆者也可编辑**：编辑写入各自本机副本，靠 git 提交/合并让修改互相可见。
- **同村冲突策略**：多人改同一村后合并以「整村覆盖、后提交者为准」，不做按地块级合并。
- **写入端点边界**：仅监听 `127.0.0.1` loopback、demo 用途、无外部鉴权；**不算后端同步/多人协作**。写入失败保留本机草稿并提示。

## 原因

- 浏览器 JS 无法直接写服务器/本地磁盘的 json 文件，`fetch` 只读不写；故"编辑即落盘"必须经一个**本机写入端点**（node 接口 / vite dev 中间件）中转落盘。
- "编辑即落盘 + 随仓库分发 + 克隆者可编辑"三者同时满足，最贴合用户预期；跨人共享靠 git 承担，符合"不提供后端同步/多人协作"的既有边界。
- 可公开：人工地块作为演示样例坐标非敏感，放 `public/business/` 克隆即见。

## 被否方案

- **仅本机 localStorage（现状）**：origin 分叉 + 克隆不可见 + 清理丢，未解决任何问题。
- **只读静态文件（克隆可见但不可编辑）**：能满足"克隆即见"，但违背"克隆者也可编辑、编辑即落盘"的用户预期。
- **前端内存草稿 + 手动导回脚本**：编辑不自动落盘 → 刷新即丢，用户明确不采用。

## 触发重开

- 若引入真正的后端同步 / 多人实时协作，或要求按地块级合并，则本决定重开。
- 若人工地块随后被判定为受限/敏感数据（不可公开分发），则改用受限目录（如 `.dev-runtime/`）且只本机加载。
