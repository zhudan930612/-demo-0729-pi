# 架构决策记录（ADR）

本目录记录项目的**长期架构决定**：为什么这样选、否掉了什么。供追溯架构演变，新决策先查这里避免重复讨论。

## 判定标准（只记这两种）

- **以后难改的**（重选成本高）：数据治理、凭据架构、外部供应商绑定等
- **有明显取舍的**（存在真实权衡）：选 A 放弃 B 有明确理由

小选择不记；行为规则、验收标准在需求文档，本目录不重复。

## 格式

每条一个文件 `NNNN-<slug>.md`，编号递增。**两档任选**，按决定复杂度：

**轻量档（简单决定，2-3 句）**：

```
# <标题>
状态：采纳 / 已替换（替换时指向新 ADR）
<决定>。<为什么>。<什么触发重开或需要新 ADR>。
```

**完整档（有明显取舍、被否方案有据可考）**：

```
# <标题>
状态：采纳 / 已替换（替换时指向新 ADR）
背景（要解决什么问题）
决定（选了哪个方案，落到哪）
原因（为什么）
被否方案（否掉了什么、为什么）
```

轻量档示例（源自 relationship-compass 仓库的 ADR 实践）：

```
# 保持关系数据本地化且免权限
关系笔记异常敏感。首发版把数据存在用户自选的本地 JSON 文件中，只导入用户显式选择的文件，不申请通讯录权限、不做网络调用。云同步与系统通讯录集成需后续隐私评审与新的 ADR。
```
