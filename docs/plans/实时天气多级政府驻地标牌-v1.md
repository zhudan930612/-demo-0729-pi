## 1. 目标与已确认范围

将当前“一个默认行政天气点”的实时天气模式改为按地图层级展示多个、可点击的政府驻地天气标牌；省级自身不显示天气标牌。

| 当前地图层级 | 常驻标牌 | 坐标来源 | 乡镇/村/地块按点查询 |
|---|---|---|---|
| 浙江省 | 11 个市 | 经核验市政府驻地 | 不适用 |
| 市 | 当前市全部区县 | 经核验区县政府驻地 | 不适用 |
| 县 | 当前县全部乡镇 | 经核验乡镇政府驻地 | 不适用 |
| 乡镇、村、地块 | 无 | 无 | `Ctrl + 左键` |

每个常驻标牌沿用当前视觉：左侧天气图标块，右侧显示行政名称和未来 24 小时最高/最低温（整数）。

### 明确不做

- 不在省级展示“浙江省”天气标牌。
- 不在乡镇、村、地块预置默认天气点或伪造乡村、地块天气点。
- 不使用行政几何中心、代表点、`bbox` 中心、地图中心或浏览器地理编码替代政府驻地。
- 不预加载常驻标牌的地址、分钟降水或完整详情；这些仅在点击对应标牌或 `Ctrl` 点选后请求。
- 不改变预警、台风、行政下钻、影像或地块功能的既有职责。

## 2. 当前实测与约束

1. 当前 `MapView.vue` 调用 `defaultWeatherQuery(store.current, …)`，只请求一个行政/地块天气点；`WeatherRepository` 同时只能维护一个活动请求，因此不能直接循环复用它加载多标牌。
2. `server/src/weather-service.js` 对 `target=admin` 使用 `weather/index-v2.json` 的 `representativePoint`，不是政府驻地；多级标牌必须另建政府驻地查询链路。
3. `server/data/government-seats-v1.json` 已包含乡镇条目。实测示例：`330102001000`（清波街道）、`330102003000`（湖滨街道）均为 `township` / `candidate`，带坐标和评分。
4. `scripts/generate-government-seats.mjs` 已定义乡镇人民政府/街道办查询规则，并为乡镇候选记录设定 `score >= 60` 门槛；现有预警索引只消费省、市、县，不能直接扩展后复用。
5. 服务端天气缓存已有 `upstreamConcurrency`（默认 6），但代理全局按 IP 有 `60/min` 限流；浏览器逐图标发 `/api/weather` 会放大同机请求并产生限流风险。
6. 现有天气标牌为 `108×42px`；县级乡镇密集时会发生屏幕重叠，不能通过丢弃、合并、缩小至不可读规避。
7. 未跟踪受限数据和产物不得提交；尤其不得提交 `.env.local`、Token、`web/public/data/`、`web/public/tiles/`，也不得公开复制影像或 AI 地块数据。

## 3. 目标架构

```text
行政层级变化 / 打开实时天气
  -> 前端请求一次 /api/weather/markers?contextLevel=…&contextCode=…
  -> 服务端按可信层级选择子级目标并校验政府驻地表
  -> 首个响应：全部目标的骨架清单
  -> 服务端受控并发：每个目标仅 current + hourly 摘要
  -> 逐项事件：ready / error
  -> 前端按行政代码增量替换 Leaflet 标牌

点击常驻标牌
  -> /api/weather?contextLevel=目标层级&contextCode=目标代码&target=seat
  -> 服务端自行取同一个可信政府驻地坐标
  -> 单个完整 WeatherBundle（实时 + 分钟降水 + 24 小时 + 地址）
  -> 现有 WeatherPopup 展示详情

乡镇、村、地块
  -> 无常驻标牌
  -> Ctrl + 左键继续走 target=picked
```

### 3.1 服务端职责

- 新建实时天气政府驻地索引（建议 `server/src/weather-seat-index.js`）：
  - 读取 `server/data/government-seats-v1.json` 与已验证的天气空间索引；
  - 仅接受 `status='candidate'` 的记录；
  - 省/市/县维持 `score >= 99`，乡镇采用已确认的 `score >= 60`；
  - 校验名称、层级、代码、坐标有限性、位于自身行政面、父级链与浙江省界内；
  - 提供按当前节点返回 `city` / `county` / `township` 子级目标的方法；无有效目标安全返回空列表和诊断分类。
- `weather-service.js` 新增受控 `seat` 目标：浏览器只传目标行政代码与层级，服务端从可信驻地索引取坐标，不接受 `lat/lon`。
- 新增多标牌摘要服务：一次请求返回骨架清单，并按已有缓存与上游并发阈值逐项请求 `current`、`hourly`。不得请求地址和分钟降水。
- 推荐使用 `application/x-ndjson` 或 SSE；首个事件必须是目标列表，之后每一项发送 `ready` 或 `error`。客户端取消、层级切换和模块退出必须中止任务并释放订阅。
- 复用现有缓存键、两位坐标舍入、上游超时、数据尺寸限制与模块级错误脱敏；不允许浏览器传入任意目标列表、坐标、URL、并发量或上游参数。

### 3.2 前端职责

- 新建独立的 marker 流状态/仓储与 repository，例如：
  - `web/src/features/weather/weatherMarkerRepository.ts`
  - `web/src/stores/weatherMarkers.ts`
  - `web/src/map/weatherMarkerLayerController.ts`，或在现有 `weatherLayerController.ts` 内保持明确的多标牌职责分区。
- 现有 `WeatherStore` 与 `WeatherRepository` 保持用于单个完整浮窗和 `Ctrl` 临时点，不承担集合加载，以免新请求取消已打开浮窗的详情请求。
- 打开实时天气或层级变化时：立即渲染当前层级所有骨架标牌，再用流事件逐项更新成功/失败状态；离开层级即清理旧标牌、取消旧流，旧事件不得污染新层级。
- 点击常驻标牌：请求 `target=seat` 的完整详情；不改变中心、缩放、面包屑或下钻状态。浮窗随标牌移动，点击空白、关闭按钮或 `Esc` 关闭。
- 乡镇、村、地块：清空常驻标牌，保留顶部 `Ctrl + 左键` 提示；按点临时标牌采用现有紫色状态并保持单实例。
- 标牌密集避让：先以 `108×42px` 真实尺寸计算碰撞。若发生重叠，采用确定性、可逆的屏幕偏移布局，保留所有独立标牌和原始政府驻地查询语义；禁止静默丢弃、聚合或缩小到不可点。

## 4. 分阶段任务

### 阶段 A：事实与数据验证

1. 检查 `government-seats-v1.json` 中 city/county/township 的总量、候选量、未解析量、评分分布和代码是否能与 `weather/index-v2.json` 一一匹配。
2. 对每一个候选驻地执行自身边界、完整父级链和省界内校验；生成仅统计、不含敏感坐标明细的检查结果。
3. 确认省→市、市→县、县→乡镇的子级总量；记录最大单县乡镇数，作为流式并发与碰撞验收基线。
4. 将可执行的数据检查纳入 `scripts/`，并将其加入 README 数据准备说明（若新增 Python/Node 依赖，同时更新 README）。

### 阶段 B：服务端索引与接口

1. 实现并单测政府驻地实时天气索引；覆盖非法文件、重复编码、错误层级、低分、名称不符、越出自身边界、越出父链、省外、目标层级不匹配等拒绝分支。
2. 扩展 `WeatherQuery`、`parseWeatherRequest`、客户端 schema，使 `seat` 成为严格受控目标；保持 `admin`、`parcel`、`picked` 的兼容语义与现有测试。
3. 实现 `/api/weather/markers` 路由、固定参数白名单、事件格式、断连取消、摘要缓存、并发限制和脱敏错误。
4. 对普通请求、首次失败、部分失败、缓存命中、取消旧层级流、非法参数、无候选子级和全量空结果分别建立服务端测试。

### 阶段 C：前端集合状态与地图呈现

1. 定义 marker 摘要类型：`code`、`level`、`name`、可信 `location`、`phase`、`condition`、`high/low`、错误摘要；不向前端返回政府驻地表中的查询词、评分、来源原文或任何未白名单字段。
2. 接入 marker repository：打开天气和 `store.path` 变化时按层级选择流；加载中显示全部骨架，成功/失败独立替换。
3. 将当前仅一个默认标牌的 `MapView.vue` 装配替换为调用 map/controller 的集合 API；不把解析、流处理或布局算法堆入视图组件。
4. 标牌点击建立完整 `seat` 天气详情，保存“选中标牌代码”以支持浮窗跟随和重绘后的稳定选中反馈。
5. 更新 `WeatherPopup` 的地址降级：常驻标牌详情优先 APIHz 地址；地址不可用时显示该标牌的完整行政路径/名称，而不是父级当前地图路径。

### 阶段 D：碰撞、响应式与刷新

1. 使用实测最大单县乡镇数构造密集 fixture；验证 108×42 标牌不遮挡到无法点击。
2. 实现确定性碰撞偏移，按稳定行政代码排序；图标移动或地图缩放后重新计算容器点偏移，浮窗继续锚定被选标牌的实际显示位置。
3. 桌面端继续优先右侧、空间不足左侧的浮窗避让；窄屏保持近全宽，标牌布局可横向分层但不得覆盖关闭操作。
4. 10 分钟自动刷新仅刷新当前层级常驻摘要；已打开详情按既有单点逻辑刷新；切换层级或退出时取消对应定时任务和流。

### 阶段 E：需求、测试与验收

1. 更新 `docs/requirements/天气查看与和风天气API接入需求.md`：删除“一默认天气点”的现役表述，写入本计划第 1 节层级矩阵、可信驻地规则、流式渐进状态、常驻/完整详情分离、碰撞规则、刷新和失败策略。
2. 更新 `DESIGN.md`：标牌集合、骨架、失败、选中、密集避让与小屏规则。
3. 单元测试：层级目标选择、政府驻地校验、`seat` 参数、marker 状态、流事件排序/取消、避让偏移、温度整数格式。
4. 服务端测试：接口参数、首事件骨架、逐项 ready/error、并发上限、缓存重用、断连取消与错误脱敏。
5. E2E：
   - 省级 11 市骨架及分批完成；
   - 市级区县标牌；县级乡镇标牌；乡镇/村/地块无常驻标牌；
   - 点击不导航、浮窗跟随、空白/Esc 关闭；
   - 失败标牌独立且其他标牌可用；
   - `Ctrl` 点选不受影响；
   - 密集县标牌无重叠且均可键盘/鼠标触达；
   - 旧层级流不会更新新层级图层。

## 5. 验收清单与防作弊约束

必须满足：

- [ ] 省级只显示 11 个市级标牌，不显示浙江省自身标牌。
- [ ] 市级只显示当前市的区县标牌；县级只显示当前县的乡镇标牌。
- [ ] 乡镇、村、地块没有预置标牌，只可 `Ctrl + 左键` 按点查询。
- [ ] 所有常驻标牌坐标可回溯到已边界校验的政府驻地表；任何缺失/无效记录不以面中心或代表点降级。
- [ ] 浏览器不逐标牌调用完整 `/api/weather`，不直接请求第三方天气或地理编码服务。
- [ ] 首屏先显示完整骨架集合，再分批更新；部分失败不清空成功标牌、不伪装为无数据。
- [ ] 点击标牌不改变地图相机或行政层级；浮窗随标牌移动，空白/关闭/Esc 关闭。
- [ ] 任何密集区不丢弃、合并或使标牌不可点击；偏移不改变实际天气查询坐标。
- [ ] `target=seat` 不能由浏览器自报坐标，服务端严格校验代码、层级和驻地索引。
- [ ] 无秘密、Token、受限数据、影像、瓦片或 AI 地块产物进入 Git。
