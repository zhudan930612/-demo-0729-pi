## 1. 目标与产品定位

灾害过后，保险公司需要快速掌握三个数字：**受损多少亩、涉及多少户、预估赔多少**。本模块提供"水稻倒伏评估"功能，基于受灾数据逐级汇总展示，帮助保险公司快速形成理赔预判。

**业务口径（2026-08-19 用户明确）**：不是"看哪里倒了"的遥感产品，而是"给定当前气象条件，预判承保责任敞口"的评估工具。Demo 阶段数据为模拟，逻辑框架先行。

**粒度决策（用户确认）**：地块级判定，逐级汇总到村→镇→县→市→省。

**v2.0 优化方向（2026-08-21 确认）**：v1.3 使用气象信号模拟受损率（离散 4 值），v2.0 改为基于实际受灾面积计算受损率（连续值），演示数据直接给出地块级受损面积，并引入空间连片生成策略使演示数据更接近真实灾害分布。

### 3.2 Choropleth 填色图

- **渲染对象**：当前 drilldown 层级的行政区划面（省→市→县→镇→村）；

| 受损率 | 颜色 | 语义 |

| [30%, 60%) | 黄（warning-yellow） | 中度 |

### 3.3 统计区结构（v2.0 重新设计）

v2.0 将概览卡片改为**两部分结构**：受损统计 KPI + 区域统计表格。省、市、区县、乡镇、村 五级结构同构，仅下级区域名称不同。

#### 3.3.1 通用结构（省→市→区县→乡镇 四级适用）

每级统计区包含上下两部分：

**上半部分：受损统计**（统计当前层级的整体受损情况）

| 指标 | 说明 |
|---|---|
| 受损面积 | 当前层级所有受灾地块的承保面积之和（口径 A：地块只要受灾算整块面积） |
| 受损户数 | 按投保人去重（只要该投保人有 ≥1 个地块受灾，算 1 户） |
| 预估赔付 | 当前层级所有受灾地块的赔付金额之和 |

**下半部分：区域统计**（统计当前层级下各子区域的整体受损情况）

| 排名 | 区域 | 受损程度 | 受损率 | 受损面积 |
|---|---|---|---|---|
| 1 | {子区域名} | 重度 / 中度 / 轻度 | xx% | xxx 亩 |
| 2 | ... | ... | ... | ... |

各层级"区域"的含义：

| 当前层级 | "区域"列展示 | 说明 |
|---|---|---|
| 省级 | 各市 | 统计省下各个市的整体受损情况 |
| 市级 | 各区/县 | 统计市下各个区/县的整体受损情况 |
| 区/县级 | 各乡镇 | 统计区县下各个乡镇的整体受损情况 |
| 乡镇级 | 各村 | 统计乡镇下各个村的整体受损情况 |
| 村级 | 各地块 | 见 §3.3.2 村级特殊处理 |

**排序规则**：
1. 第一优先级：受损程度（重度 > 中度 > 轻度）
2. 第二优先级：受损率（降序）
3. 第三优先级：区域名称（字典序，保证排序稳定）

**零受损区域**：受损率为 0% 的区域仍展示，受损程度标记为"—"，排在列表末尾。

### 3.4 评估逻辑（v2.0 更新）

#### 3.4.1 数据来源

**演示模式**：
- 从 `DEMO_DAMAGE_MAP` 直接获取每个地块的**受损面积（亩）**；
- 地块受损率 = 受损面积 / 该地块承保面积（连续值 0~100%）；
- 不再使用气象信号模拟（v1.3 的信号分档 + 木桶原理链路在演示模式下移除）；

**真实模式**：
- 本期仅定义数据接口契约（输入规范），不做实际接入；
- 接口契约：输入为每个地块的受损面积（亩），格式与演示模式一致；
- 未来接入时只需替换数据源，汇总计算层复用；

#### 3.4.2 核心公式

**受损率**（地块级）：
```
地块受损率 = 地块受损面积(亩) / 地块承保面积(亩)
```

**区域受灾率**（区域级，用于区域受损程度分档）：
```
区域受灾率 = 区域内所有受灾地块的承保面积之和 / 区域参保总面积
```
- "受灾地块"：受损面积 > 0 的地块；
- "参保总面积"：该区域内所有承保地块的承保面积之和（含未受灾地块）；

**受损面积口径**（v2.0 确认）：
- **口径 A**：地块只要受灾（受损面积 > 0），整块承保面积计入"受损面积"；
- 区域受损面积 = 该区域内所有受灾地块的承保面积之和；

**赔付公式**（沿用 v1.3）：
```
赔付 = 受损面积(亩) × 单位保额(元/亩) × 赔付比例
赔付比例（按地块受损率，左闭右开）：
  - 0%         → 0%（未受损，不赔付）
  - (0%, 30%)  → 50%
  - [30%, 60%) → 80%
  - [60%, 100%] → 100%
```
- 单位保额：¥1250/亩（`UNIT_SUM_INSURED_CENTS_PER_MU = 125000` 分），产品为"政策性水稻完全成本保险"；

#### 3.4.3 逐级汇总

- 地块级结果按行政区划代码前缀聚合到村→镇→县→市→省；
- 汇总规则：
  - 省级 = 行政代码前 2 位
  - 市级 = 行政代码前 4 位
  - 区/县级 = 行政代码前 6 位
  - 乡镇级 = 行政代码前 9 位
  - 村级 = 完整 12 位
- **注意**：村码前缀 ≠ 上级区划代码（章镇镇村码前缀 `330604102` ≠ 镇码 `330604104000`），靠 `VILLAGE_PREFIX_TO_TOWNSHIP` 映射反查（沿用 v1.3）；
- 汇总指标：受损面积、受损户数（按投保人去重）、预估赔付、参保总面积；

#### 3.4.4 区域受损程度分档（v2.0 新增）

区域受损程度基于**区域受灾率**独立分档（与地块赔付分档解耦），阈值可配置：

| 区域受灾率 | 受损程度 | 语义 |
|---|---|---|
| < 10% | 轻度 | 零星受灾，少量地块有影响 |
| 10% ~ 30% | 中度 | 较大范围受灾，需要关注 |
| ≥ 30% | 重度 | 大面积受灾，需要重点响应 |
| 0% | —（无受损） | 该区域无受灾地块 |

- 阈值定义为可配置常量（建议放在 `lodgingCalc.ts` 或配置文件中），便于不同险种/灾季调整；
- 此分档仅用于区域统计表的"受损程度"列展示和排序，不影响赔付计算；

### 3.6 演示模式与真实模式（v2.0 更新）

**模式切换**：
- flyout 菜单底部增加 toggle 开关："演示模式" / "真实模式"
- **默认模式**：演示模式（toggle 开启）
- **切换行为**：切换后立即生效（如果已在评估模式中，重新计算评估结果）
- **不持久化**：刷新页面后恢复为默认的演示模式

**演示模式（v2.0 重新设计）**：

演示数据直接给出每个地块的受损面积（亩），采用**空间连片生成策略**，模拟天灾造成的连续受灾区域。

**生成算法**：
1. 每个受灾村随机生成 **2~4 个灾害中心点**（落在村域范围内）；
2. 以每个中心点做 **Turf.js buffer**（缓冲区），半径 **150~400 米**；
3. 缓冲区内的地块标记为受灾，按距离中心点的远近分档：
   - 0~150m：重度（受损率 60%~100%）
   - 150~250m：中度（受损率 30%~60%）
   - 250~400m：轻度（受损率 5%~30%）
4. 缓冲区外的地块不受灾（受损面积 = 0）；
5. 各村受灾比例：随机 **10%~60%** 的参保面积受灾，保证各村有差异；

**参数可配置**：
- 灾害中心点数量、缓冲区半径、距离分圈阈值、受灾比例范围均为可配置常量；
- 方便演示时调整到视觉效果最佳的状态；

**数据一致性**：
- 地块级受损面积直接由上述算法生成；
- 村级以上的汇总数据由地块数据**自下而上聚合**，保证任意钻取路径数据一致；
- 不预先设定省/市/区县/乡镇级的数据，避免上下级不一致；

**真实模式**：
- 本期仅定义数据接口契约（见 §3.4.1），不做实际接入；
- 真实模式下如无数据输入，等同于所有地块受损面积 = 0，展示空态；

**实现说明**：
- 演示模式数据生成不依赖后端，纯前端逻辑（使用 Turf.js 做空间计算）；
- 模式切换不依赖后端，纯前端逻辑；
- 卡片底部标注需区分模式：
  - 真实模式："评估基于实际受灾数据"
  - 演示模式："评估基于模拟受灾数据，仅供演示"

### 3.7 边界与异常处理（v2.0 新增）

| 场景 | 处理规则 |

    - 参保面积为 0 的区域，受损率显示"—"，不参与排名；

不再使用逐地块随机分桶（旧方案产生零散色块），改为**行政区级别标注受损等级**，每级 drilldown 呈现清晰的区域色块。

#### 数据标注方案

| 层级 | 视图展示 | 标注方案 |
|---|---|---|
| 省级 | 市级 choropleth | 绍兴市=重度、杭州/宁波=轻度、温州=中度 |
| 市级 | 县级 choropleth | 上虞区=重度、嵊州/柯桥=中度、越城/诸暨=轻度 |
| 县级 | 乡镇 choropleth | 章镇镇=重度、道墟/百官=中度、长塘/丰惠=轻度 |
| 乡镇级 | 村级 choropleth | 龙江/新南=重度、大钱/清潭/新魏家庄=中度、4 村=轻度 |
| 村级 | **地块级** choropleth | 基于村整体受损率 + parcelId 种子产生差异化分布 |

#### 村级地块差异化分布

```
重度村（100%）: 50% 重度 / 20% 中度 / 20% 轻度 / 10% 无
中度村（60%）:  20% 重度 / 40% 中度 / 30% 轻度 / 10% 无
轻度村（30%）:  10% 重度 / 20% 中度 / 40% 轻度 / 30% 无
```

每村限制最多加载 **400 个地块**（避免渲染过多）。

#### 区划代码匹配

核心问题：村码前缀 ≠ 上级区划代码（章镇镇村码前缀 `330604102` ≠ 镇码 `330604104000`）。

解决：`VILLAGE_PREFIX_TO_TOWNSHIP` 映射 + `resolveTownshipCode()` 反查真实乡镇代码。

```
province 视图 → villageCode.slice(0,4) + '00' → 匹配市级代码
city 视图     → villageCode.slice(0,6)         → 匹配县级代码
county 视图   → resolveTownshipCode(villageCode) → 匹配乡镇代码
township 视图 → villageCode 精确匹配            → 匹配村级代码
```
