## 1. 目标与产品定位

灾害过后，保险公司需要快速掌握三个数字：**受损多少亩、涉及多少户、预估赔多少**。本模块提供"水稻倒伏评估"功能，基于当前气象条件自动判定每个承保地块的受损程度，逐级汇总展示，帮助保险公司快速形成理赔预判。

**业务口径（2026-08-19 用户明确）**：不是"看哪里倒了"的遥感产品，而是"给定当前气象条件，预判承保责任敞口"的评估工具。Demo 阶段数据为模拟，逻辑框架先行。

**粒度决策（用户确认）**：地块级判定，逐级汇总到村→镇→县→市→省。

## 2. 范围

### 2.1 本期范围

1. **入口**：右侧工具条新增"风险评估"图标按钮（与"查看天气"图标同级），悬停弹出 flyout 菜单，菜单项：水稻倒伏（可用）、小麦倒伏（灰色，即将上线）；
2. **交互**：点击"水稻倒伏"进入评估模式，地图显示当前 drilldown 层级的 choropleth 填色图（受损率），浮动概览卡片显示汇总数据；
3. **评估逻辑**：基于当前气象快照（台风距离 + 降水 + 风力）自动判定，不绑定特定灾害事件；
4. ** choropleth 颜色**：绿→黄→红渐变，按受损率分档；
5. **概览卡片**：参考 `VillageRiskOverview` 风格，显示受损面积、受损户数、预估赔付 + 最严重区域 Top 3；
6. **drilldown 联动**：跟随五级行政下钻，每级自动刷新 choropleth 和卡片数据；
7. **赔付公式**：赔付 = 受损面积 × 单位保额 × 赔付比例（比例按受损率分档）；
8. **模式互斥**：进入评估模式退出其他模式（天气/台风/降水），遵循现有约定；
9. **纯前端实现**：不需要后端改动，所有计算在浏览器完成；
10. **Demo 数据**：使用现有 13 村保单 fixture，气象信号从现有数据取。

## 3. 用户界面与交互

### 3.1 入口与模式

- **入口位置**：右侧工具条 `MapControlStack`，与"查看天气"图标按钮同级（都是 `tool-entry`）；
- **flyout 菜单**：悬停图标弹出左侧菜单（与天气菜单交互一致），菜单项：
  - 🌾 水稻倒伏（可用，点击进入评估模式）
- **进入评估模式**：
  - 退出其他模式（天气/台风/降水），遵循现有模式互斥约定；
  - 地图切回浙江省省级视角（与降水模式一致，需要全省视角）；
  - 关闭已打开的地块详情、种植档案、保单抽屉；
  - 取消任何地块编辑态；
  - **气象数据检查**：任一核心信号不可用时，禁止进入，Toast 提示"评估暂不可用：{缺失信号名}"（3 秒消失）；
- **退出评估模式**：
  - **方式 1**：点击激活图标（toggle 切换），图标恢复非激活状态；
  - **方式 2**：flyout 菜单底部"退出评估"选项；
  - 退出后清除 choropleth、概览卡片、评估状态，恢复正常地图交互；

### 3.2 Choropleth 填色图

- **渲染对象**：当前 drilldown 层级的行政区划面（省→市→县→镇→村）；
- **颜色映射**：按受损率分档填色（受损率为离散 4 值：0% / 30% / 60% / 100%）：

| 受损率 | 颜色 | 语义 |
|---|---|---|
| 0% | 透明 | 无受损 |
| 30% | 绿（success-green） | 轻度 |
| 60% | 黄（warning-yellow） | 中度 |
| 100% | 红（danger-red） | 重度 |

- **无数据区划**：无保单数据或所有地块受损率 = 0% 时，不填色（透明）；

- **pane 层级**：低于天地图文字注记（pane < 450），不遮挡行政边界与地块；
- **下钻联动**：drilldown 到市/县/镇/村，choropleth 自动刷新为该层级的区划面填色；
- **悬停浮窗**：鼠标悬停区划面时显示小浮窗——区划名称 + 受损率（如"章镇镇 · 受损率 60%"）；浮窗跟随鼠标，靠近屏幕边缘时自动翻转（标准 Tooltip 行为）；

### 3.3 浮动概览卡片

- **位置与样式**：浮动在地图**右上角**（与 `VillageRiskOverview` 位置一致），雾白面板风格；
- **加载态**：进入评估模式时，卡片区域显示 loading（骨架屏或 spinner），choropleth 渲染完成后显示数据；
- **内容（自上而下）**：

```text

│ 水稻倒伏评估 · 浙江省                │ ← 跟随 drilldown 层级标题

│ 受损户数           56 户             │ ← KPI 区（等宽数字）

├──────────────────────────────────────┤
│ 最严重区域 Top 3                     │
│ 1. 章镇镇    受损率 85%              │ ← 跟随 drilldown 显示子区划
```

- **drilldown 联动**：drilldown 层级变化时，卡片标题（当前层级名）和 Top 3 列表（当前层级的子区划）自动刷新；
- **Top 3 区域可点击**：列表中的区域名称为可点击链接，点击效果等同于在地图上点击该区划面（触发 drilldown，地图聚焦 + 卡片刷新）；
- **空态**：所有区域受损率 = 0% 时，卡片 KPI 显示 0，下方显示"当前气象条件下无参保区域受损"，choropleth 全透明；

### 3.4 评估逻辑（用户不可见，内部规则）

- **气象信号输入**：
  - 台风距离：最近台风路径点距浙江省界距离（**无台风时该信号跳过，不参与计算**）
  - 24h 降水峰值：全省 0.25° 网格 24h 降水最大值
  - 风力等级：从台风等级推算（或天气 API）
- **信号不可用降级**：任一核心信号不可用时，禁止进入评估模式，Toast 提示"评估暂不可用：{缺失信号名}"（3 秒自动消失）；
- **地块受损判定（木桶原理）**：三个信号各独立分档，取最高档作为地块受损等级。**受损率为离散 4 值：0% / 30% / 60% / 100%**：

| 信号 | 无受损（0%） | 轻度（30%） | 中度（60%） | 重度（100%） |
|---|---|---|---|---|
| 台风距离 | 无台风（跳过） | 100-200km | 50-100km | <50km |
| 24h 降水 | <50mm | 50-100mm | 100-200mm | ≥200mm |
| 风力等级 | <7 级 | 7-8 级 | 9-10 级 | ≥11 级 |

- **赔付公式**：
  ```
  赔付 = 受损面积(亩) × 单位保额(元/亩) × 赔付比例
  赔付比例（左闭右开）：
    - [0%, 30%) → 50%
    - [30%, 60%) → 80%
    - [60%, 100%] → 100%
  ```
  即：受损率 0% → 50%，30% → 80%，60% → 100%，100% → 100%；
- **逐级汇总**：地块级结果按行政区划代码前缀聚合到村→镇→县→市→省；

### 3.5 数据标注与演示边界

- 卡片底部标注："评估基于当前气象快照，Demo 数据为模拟，不构成理赔依据"；
- 评估时间显示计算完成时间（**进入评估模式时计算一次**，格式：`2026-08-20 14:30`），刷新页面后重新计算；
- 不把评估结果描述为实测灾损、定损依据或理赔依据；

### 3.6 演示模式与真实模式

**模式切换**：
- flyout 菜单底部增加 toggle 开关："演示模式" / "真实模式"
- **默认模式**：真实模式（toggle 关闭）
- **切换行为**：切换后立即生效（如果已在评估模式中，重新计算评估结果）
- **不持久化**：刷新页面后恢复为默认的真实模式

**真实模式**：
- 使用实际气象数据（台风路径、降水网格、风力等级）
- 如果气象信号弱（如无台风、降水 <50mm、风力 <7 级），可能导致所有地块受损率 = 0%
- 空态展示：卡片 KPI 显示 0，显示"当前气象条件下无参保区域受损"，choropleth 全透明

**演示模式**：
- 使用硬编码的强气象信号，确保有倒伏数据可展示
- 模拟信号：台风距离 150km（轻度 30%）、降水 80mm（轻度 30%）、风力 8 级（轻度 30%）
- 结果：所有地块至少有 30% 受损率，可以看到倒伏数据和 choropleth 填色
- 用途：Demo 演示、功能验证、用户培训

**实现说明**：
- 演示模式的气象信号值可以配置（建议放在 `.devflow/config.toml` 或前端常量）
- 模式切换不依赖后端，纯前端逻辑
- 卡片底部标注需区分模式：
  - 真实模式："评估基于当前气象快照"
  - 演示模式："评估基于模拟气象数据，仅供演示"

## 4. 数据依赖

**数据范围**：Demo 阶段不做登录和权限控制，所有用户可见所有 13 村数据，从省级开始 drilldown；

| 数据 | 来源 | 用途 |
|---|---|---|
| 13 村保单数据 | `web/src/data/policy-{村代码}.json` | 地块级承保面积、单位保额、被保险人（户数统计）；地块编号字段为 `parcelId`（string，村域内顺序整数如"1006"） |
| 村边界 | `villages/{乡镇码}.geojson` | choropleth 渲染、区划汇总 |
| 行政区划边界 | `boundary/{level}/{code}.geojson` | 各级 choropleth 渲染 |
| 台风路径 | 现有台风代理数据 | 台风距离信号（无台风时跳过） |
| 降水网格 | 现有 `/api/precipitation-grid` 快照 | 24h 降水峰值信号 |
| 风力等级 | 从台风等级推算或天气 API | 风力信号 |

- 服务端无新增接口；所有计算前端完成；
- **不持久化**：评估结果和模式选择不保存到后端或 localStorage，刷新页面后重新计算并恢复为真实模式；
- **不同步 URL**：drilldown 层级状态不同步到 URL，刷新后回到省级视角；

### 核心逻辑

| # | 决策 | 结论 |

### 8.2 演示数据策略：DEMO_DAMAGE_MAP

不再使用逐地块随机分桶（旧方案产生零散色块），改为**行政区级别标注受损等级**，每级 drilldown 呈现清晰的区域色块。

#### 数据标注方案

| 层级 | 视图展示 | 标注方案 |
|---|---|---|
| 省级 | 市级 choropleth | 绍兴市=重度、杭州/宁波=轻度、温州=中度 |
| 市级 | 县级 choropleth | 上虞区=重度、嵊州/柯桥=中度、越城/诸暨=轻度 |
| 县级 | 乡镇 choropleth | 章镇镇=重度、道墟/百官=中度、长塘/丰惠=轻度 |
| 乡镇级 | 村级 choropleth | 龙江/新南=重度、大钱/清潭/新魏家庄=中度、4 村=轻度 |
| 村级 | **地块级** choropleth | 基于村整体受损率 + parcelId 种子产生差异化分布 |

#### 村级地块差异化分布

```
重度村（100%）: 50% 重度 / 20% 中度 / 20% 轻度 / 10% 无
中度村（60%）:  20% 重度 / 40% 中度 / 30% 轻度 / 10% 无
轻度村（30%）:  10% 重度 / 20% 中度 / 40% 轻度 / 30% 无
```

每村限制最多加载 **400 个地块**（避免渲染过多）。

#### 区划代码匹配

核心问题：村码前缀 ≠ 上级区划代码（章镇镇村码前缀 `330604102` ≠ 镇码 `330604104000`）。

解决：`VILLAGE_PREFIX_TO_TOWNSHIP` 映射 + `resolveTownshipCode()` 反查真实乡镇代码。

```
province 视图 → villageCode.slice(0,4) + '00' → 匹配市级代码
city 视图     → villageCode.slice(0,6)         → 匹配县级代码
county 视图   → resolveTownshipCode(villageCode) → 匹配乡镇代码
township 视图 → villageCode 精确匹配            → 匹配村级代码
```
