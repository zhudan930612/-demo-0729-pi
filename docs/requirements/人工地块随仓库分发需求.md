# 人工地块随仓库分发需求

> 版本：v1.3（2026-08-24 拷打后修订：范围扩展为「非影像运行数据随仓库分发」——AI 地块、人工地块、地块可见性、行政边界/村界随仓库分发，村界走 git-lfs，影像瓦片仍脚本生成）
> 状态：需求已确认，进入实现前需先完成形态预检（见 §9）
> 承接：PRODUCT.md「人工地块仅保存在当前浏览器」与功能清单「人工地块…仅保存在当前浏览器」的现状变更；相关决定见 [ADR-0008](../adr/0008-人工地块本机写入端点随仓库分发.md)、[ADR-0009](../adr/0009-AI地块与地块可见性随仓库公开分发.md)、[ADR-0010](../adr/0010-运行数据随仓库分发.md)
> 适用：地块（AI/人工）、地块筛选/可见不可见、行政边界/村界 的存储、分发与加载方式

---

## 1. 文档目的与背景

当前产品**运行数据长期靠脚本在克隆者本地生成**，且部分交互数据只存浏览器 localStorage：

- `web/public/data/`（行政边界、村界、AI 地块、manifest）与 `web/public/tiles/`（影像瓦片）都在 `.gitignore`，**不入 git**，由 `scripts/prepare-all.sh` 从 LFS 源数据（约 2.1G）生成。克隆者**必须 `git lfs pull` + 跑脚本**才有边界/村界/AI 地块/影像，门槛高。
- 人工地块（`agri-map:manual-parcels:v1`）与地块筛选/可见不可见（`agri-map:parcel-edits:v1`）只存浏览器 localStorage：随分发缺失、origin 分叉（`localhost` vs `127.0.0.1`）、清缓存即丢。

本需求把手动绘制的**人工地块**、**地块筛选/可见不可见**、以及**稳定的非影像运行数据（AI 地块、行政边界、村界）**概为**一次性生成后随仓库分发**，克隆者克隆（村界经 git-lfs 拉取）后直接可用，**不再依赖本地跑脚本生成这些数据**；仅影像瓦片（体积大+受限）保留脚本生成。

## 2. 目标

- **非影像运行数据随仓库分发**：AI 地块、行政边界、村界（git-lfs）、人工地块、地块可见性、业务静态数据 —— 克隆者克隆（村界 lfs pull）即见，**无需本地跑脚本生成**。
- **编辑即落盘**：人工地块新增/修形/删除、可见性切换，经**本机写入端点**写入仓库静态文件；加载从静态文件读，**刷新不丢**。
- 人工地块/可见性读取**不再依赖 localStorage**（消除 origin 分叉）。
- **克隆者也可编辑**：编辑写各自本机副本，靠 git 提交/合并；同一村以「整村覆盖、后提交者为准」。
- 保持既有交互不回归：新增、绘制、修形、撤销、删除、面积实时计算、重叠/越界提示、未保存退出保护均维持现状。

## 3. 已确认决策（2026-08-24 拷打确认）

| 决策点 | 结论 |
|---|---|
| 数据性质 | 人工地块、AI 地块、行政边界/村界作为**可公开演示样例**随仓库公开分发（授权合规风险未核实，见 ADR-0009/0010） |
| **分发范围** | **非影像运行数据**随仓库分发；影像瓦片（体积大+受限）仍脚本生成 |
| **村界体量** | 村界 villages（293M）走 **git-lfs**（克隆者 lfs pull，不撑仓库，比跑脚本省事） |
| **行政边界/村界** | 随仓库**公开**分发（放宽原受限约束；保留不得描述为确权/承保/测绘成果的表述纪律） |
| 编辑持久化 | 人工地块编辑经本机写入端点直接落盘仓库静态文件，刷新不丢，克隆即见 |
| 可见不可见范围 | 全部地块（含 AI）随分发，经本机写入端点落盘 |
| 克隆者编辑 | 也可编辑（写各自本机副本 + git 提交合并）；同村整村覆盖、后提交者为准 |
| 写入端点边界 | 本机 demo 写入端点，仅 `127.0.0.1` loopback，非公开服务，不算后端同步/多人协作 |
| 前置输入 | 用户从浏览器导出当前人工地块与可见不可见数据作为首版 |

## 4. 范围

### 4.1 做

- 非影像运行数据随仓库分发（落点分层见 §5）：AI 地块、行政边界、村界（git-lfs）、人工地块、地块可见性、业务静态。
- 前端读取人工地块/可见性由 localStorage 改为加载静态文件。
- 新增**本机写入端点**：接收前端编辑态/可见性，校验后写入对应静态文件。
- 前端编辑保存、可见性切换由「写 localStorage」改为「POST 本机写入端点 → 落盘静态文件」。
- 同步更新相关文档（见 §10）。

### 4.2 不做（边界）

- **影像瓦片仍脚本生成**：tiles（781M，吉林一号影像，受限）不入 git，克隆者看影像仍须本地跑 `prepare-rs-tiles`（因体积与受限，保留脚本生成）。
- **AI 地块几何仍只读**：随分发改变的是分发范围，AI 地块仍只读、只支持隐藏/恢复；人工地块不修改原始 AI GeoJSON。
- **不迁移**种植档案修改（`cultivationStorage`）：仍维持现状。
- **不做后端同步 / 多人实时协作**：写入端点只是本机落盘工具；跨人共享靠 git。
- **表述纪律不变**：AI 地块、行政边界仍不得描述为确权、承保或测绘成果。

## 5. 数据方案

### 5.1 落点分层

| 数据 | 落点 | 分发方式 |
|---|---|---|
| AI 地块 | `public/business/parcels/*.geojson`（或随分发静态目录） | 入 git，随仓库分发 |
| 行政边界 | `public/data/boundary/*.geojson` | 入 git，随仓库分发 |
| 村界 | `public/data/villages/{乡镇码}.geojson` | **git-lfs**（293M，避免撑仓库） |
| 人工地块 | `public/business/manual-parcels.json` | 入 git；编辑经写入端点落盘 |
| 地块可见性 | `public/business/parcel-edits.json` | 入 git；经写入端点落盘 |
| 业务静态（保单/种植档案） | `public/business/` | 入 git（现状已如此） |
| 影像瓦片 | `public/tiles/`（781M，吉林一号） | **仍脚本生成**（`prepare-rs-tiles`） |
| manifest / rs | `public/data/manifest.json`、`rs.json` | 入 git（小） |

> 说明：`public/data/` 现被 `.gitignore` 整体忽略；本需求将非影像部分改为跟踪入 git，影像瓦片与村界（git-lfs）单独处理。

### 5.2 数据格式

- **人工地块**：沿用内部结构——顶层 `version` + `villages`（按村分组）+ `next_display_no`；每要素需通过「人工地块要素有效性」校验（几何闭合、必填数值、`source:'manual'`、`village_code`、时间戳），无效不写入。
- **地块可见性**：沿用 `agri-map:parcel-edits:v1` 结构——顶层 `version` + `villages`（per-村 `{ datasetVersion, hiddenIds[] }`）。
- **AI 地块 / 行政边界 / 村界**：GeoJSON，沿用现有生成脚本输出格式。
- 均带校验：坏数据/无效记录不写入且跳过。

### 5.3 本机写入端点

- **职责**：接收前端 POST 的某村编辑态（人工地块要素数组）或可见性（hiddenIds 集合），按 §5.2 校验，校验通过后覆盖写该村记录到对应静态文件（`manual-parcels.json` / `parcel-edits.json`），并按规则生成/更新该村 `next_display_no`。
- **边界**：仅监听 `127.0.0.1` loopback，demo 用途，无外部鉴权；不算后端同步/多人协作。
- **失败处理**：校验失败返回具体原因，不写入；磁盘写入失败保留前端草稿并提示。

### 5.4 派生脚本

- 保留 `scripts/prepare-*.py` 用于**服务器端/维护者**生成随分发的运行数据（AI 地块、边界、村界、manifest）；生成产物入 git / git-lfs。
- 新增**导入/校验**脚本：读取用户导出的导入文件（人工地块 JSON、可见性 JSON），校验后写入对应静态文件并镜像。用于首版数据导入与必要时批量同步。

## 6. 前端行为

### 6.1 读取

- 进入村：从 `/business/manual-parcels.json`（人工地块）、`/business/parcel-edits.json`（可见性）加载对应村记录，不再读 localStorage。
- AI 地块、边界、村界从随分发的静态数据加载（与入库方一致）；人工地块与 AI 地块叠加渲染，维持现有图层层级与交互。
- 文件不存在或该村无记录 → 为空，不报阻断错误；加载失败 → 按现有失败文案提示，不阻塞地图。

### 6.2 编辑与保存

- 新增 / 绘制 / 修形 / 删除 / 隐藏 / 恢复等操作逻辑不变。
- 保存行为变更：人工地块与可见性均不再写 localStorage，改为 **POST 本机写入端点**，由端点校验并落盘到静态文件。
- 保存成功后刷新仍能从静态文件读回（编辑不丢）；保存失败保留本机草稿并提示。

### 6.3 显示序号 / 6.4 可见不可见

- 每个有效人工地块要素持有唯一、稳定的展示序号 `display_no`（按村递增）；本机新增序号由写入端点按该村当前最大 `display_no` 递增生成。
- 地块隐藏/恢复经本机写入端点落盘 `parcel-edits.json`，随仓库分发；`hiddenIds` 引用地块 id（含 AI 与人工），需与随分发的 AI 地块 id 一致方可对应。

## 7. 写入与协同机制

- **本机编辑**：编辑/可见性保存 → 前端 POST 本机写入端点 → 校验 → 覆盖写该村记录到静态文件。本机落盘，非共享服务。
- **克隆者协同**：克隆者同样可编辑，写入其本机副本；通过 git 提交/合并让修改互相可见。
- **同村冲突**：以「整村覆盖、后提交者为准」约定处理合并，不做按地块级合并（demo 范围）。

## 8. 验收标准

1. 克隆仓库（村界经 `git lfs pull`）而非本地跑脚本，进入有数据的村能看到 **AI 地块 + 人工地块 + 行政边界/村界** + 既有**可见不可见**状态（克隆即见）。
2. 先后用 `http://localhost:5173` 与 `http://127.0.0.1:5173` 打开，人工地块与可见不可见**一致且均可加载**（不再是 localStorage 分叉）。
3. **编辑/可见性即落盘**：新增/修形/删除/隐藏/恢复并保存后，对应静态文件更新；刷新后再进入该村仍正确（不丢）。
4. 克隆者编辑后经 git 提交/合并，他人拉取可见；同一村冲突按「整村覆盖、后提交者为准」。
5. 写入端点校验：无效要素/坏数据拒绝写入并给出具体原因；磁盘写入失败保留本机草稿并提示。
6. AI 地块随分发与人工地块 id 对应关系正确；AI 地块几何只读、不修改原始 AI GeoJSON。
7. 人工地块绘制/修形/撤销/删除/未保存退出保护，行政边界/村界/AI 地块加载均无回归（`web test` + 定向 e2e）。
8. `web build` + `pnpm --dir web test` 全绿；touch 共用面板/下钻时按 AGENTS.md 全量层跑 `test:e2e`。

## 9. 形态预检与产物目视预检（数据形态类需求，强制环节）

- **形态预检（编码前）**：用导入的待入库数据（人工地块 + 可见性 + 随分发边界/村界/AI 地块）向用户展示某村的**可目视形态样例**，确认形态后再编码；不符先回需求变更。
- **产物目视预检（编码后）**：实现后先向用户目视预检（前端该村渲染 AI+人工地块、边界/村界、可见性、编辑保存落盘效果），确认形态符合；不符先回需求变更，再进自动化验收（§8）。

| 问题 | 说明 | 当前建议 |
|---|---|---|
| 写入端点运行方式 | 复用 server 代理加接口，还是独立小服务 / vite dev 中间件 | 复用现有 server，加 loopback 写接口 |

| **数据授权合规** | **AI 地块、行政边界随仓库公开分发，真实农田/行政边界数据公开授权合规未经核实** | 已在 ADR-0009/0010 显著记录；若后续合规审查发现不可公开，应重开并撤回 |

## 12. 前置输入（实现前必须到位）

- 用户从浏览器 localStorage 导出的当前**人工地块** JSON 与**可见不可见** JSON（导入文件），用于生成首版静态文件与形态预检样例（§9）。
