# 农险双精准地图 Demo —— 天气查看与和风天气 API 接入需求

> 版本：v1.0（2026-08-03 首期范围确认）
> 状态：已实现（2026-08-04 完成四个和风天气接口脱敏探针与真实 Chrome 关键链路验收）；可选 APIHz 地址线路未配置，其真实地址链路未验收，当前按既定行政对象/地块/地图点选位置文案降级
> 适用范围：右下角“灾害风险”工具及其“查看天气”子功能

---

## 1. 文档目的

本文档是“查看天气”用户行为、数据口径、接口范围、安全约束和验收标准的事实来源。它与现役的[灾害风险与台风查看需求](./灾害风险与台风查看需求.md)并列，不修改台风专题自身的数据快照、图层和交互规则。

天气能力仅用于浙江省全域，在浙江省、省内市、县、乡、村或地块上下文中辅助查看临近天气风险，不建设通用天气 App，也不把天气预报直接解释为地块实测、损失事实或理赔结论。

## 2. 产品目标与业务边界

### 2.1 目标

用户在地图中定位到行政区域、村或地块后，可以在不离开当前空间上下文的情况下回答：

- 当前查询点附近是什么天气；
- 当前是否存在官方生效天气预警；
- 未来两小时是否可能降雨、何时增强或减弱；
- 未来 24 小时的天气现象、温度和降水如何变化。

天气信息主要服务内部技术验证、现场查勘安排和风险态势辅助判断。空间对象与天气查询点必须明确关联，不能让用户误以为一个代表点描述了整块地块或整个行政区域的全部天气。

### 2.2 地理展示范围

首期天气只在浙江省范围内展示，但覆盖本产品全部空间层级：

- 浙江省省级；
- 浙江省内 11 个地市；
- 省内县、乡、村；
- 省内村级页面中的地块。

“只在浙江省展示”不是“仅在浙江省级展示”。用户下钻到省内任一市、县、乡、村或打开地块详情后，天气仍可查看，并按当前层级或地块的代表点更新。

首期不提供浙江省外查询入口，也不接受省外经纬度。天气面板是否可用以当前行政上下文属于浙江省及其后代节点为准，不能只用一个粗略矩形包围盒作为业务授权判断。

### 2.3 首期接口范围

首期接入以下 4 个和风天气接口：

| 能力 | 上游接口 | 首期用途 |
|---|---|---|
| 实时天气预警 | `GET /weatheralert/v1/current/{latitude}/{longitude}` | 查询指定点正在生效的官方天气预警 |
| 实时天气 | `GET /weather/v1/current/{latitude}/{longitude}` | 展示天气现象、温度、体感、降水和湿度 |
| 小时天气预报 | `GET /weather/v1/hourly/{latitude}/{longitude}`，`hours=24` | 展示未来 24 小时变化 |
| 分钟级降水 | `GET /v7/minutely/5m?location={longitude},{latitude}` | 展示中国区域未来 2 小时、每 5 分钟降水临近预报 |

接口文档：

- [实时天气预警](https://dev.qweather.com/docs/api/warning/weather-alert/)
- [实时天气](https://dev.qweather.com/docs/api/weather/weather-current/)
- [小时天气预报](https://dev.qweather.com/docs/api/weather/weather-hourly-forecast/)
- [分钟级降水](https://dev.qweather.com/docs/api/minutely/minutely-precipitation/)

### 2.4 后续范围

[每日天气预报](https://dev.qweather.com/docs/api/weather/weather-daily-forecast/)作为第二期候选，计划展示未来 7 天，不纳入首期开发和验收。确定进入第二期前，应单独确认连续降雨、极端温度和查勘排期的展示规则。

### 2.5 首期不做

- 不接入未来 7 天或 10 天逐日天气预报；
- 不提供历史天气、历史降水或历史预警查询；
- 不提供天气雷达图、卫星云图、等值线或面状天气图层；
- 不做全省、市、县范围的面状天气概览或多点批量扫描；
- 不做短信、电话、浏览器推送或后台预警订阅；
- 不计算地块风险评分、灾损概率、赔付金额或自动处置结论；
- 不把点位天气描述为地块实测、气象站实测或行政区域平均值；
- 不允许浏览器直接持有和风天气 API KEY、项目 ID、凭据 ID 或真实 API Host 配置。

## 3. 入口、模式与总体流程

### 3.1 一级入口

右下角现有工具栈沿用天气与台风两个并列按钮，不新增“灾害风险”父菜单：

```text
查看天气
查看台风
地块工具
底图与图层工具
```

- 当前行政上下文属于浙江省及省内市、县、乡、村或地块时，天气图标按钮从预留禁用状态改为可点击；点击后展开与“地块工具”一致的两项菜单：“气象预警”和“实时天气”；
- 两项天气模块全局互斥：选择任一项立即关闭另一项的面板、浮窗与地图标记，随后加载所选模块；“实时天气”保留当前天气标记、分钟降水和未来 24 小时预报；
- 当前上下文无法确认属于浙江省时，天气工具保持不可点击，并说明“天气当前仅支持浙江省范围”；
- 查看天气与查看台风互斥，同一时间只允许一个灾害查看子功能处于活动状态；
- 已进入查看台风时，不在同一面板叠加天气；用户退出台风后才能进入天气，反之亦然；
- 地块筛选、批量新增、手动画图、人工地块修形或种植档案存在未保存内容时，“灾害风险”入口继续禁用，必须先保存或取消当前操作。

### 3.2 进入天气流程

```text
点击“气象预警”或“实时天气”
→ 保留当前行政层级、地图中心和缩放级别
→ 关闭另一天气模块的面板、浮窗与地图标记
→ 按当前位置上下文确定查询点
→ “气象预警”打开右上天气头部/预警列表并显示骨架状态
→ “实时天气”立即显示可点击的默认位置天气骨架标记
→ 服务端请求所选模块所需数据，地址仅作为实时天气的可降级增强请求
→ 成功模块先展示，失败模块独立显示错误
```

进入天气模式前先确认当前行政节点属于浙江省；校验失败时不打开面板、不请求上游，并显示“天气当前仅支持浙江省范围”。校验通过后：

- 不切回浙江省省级；
- 不自动平移、缩放或适配边界；
- 不隐藏行政边界、天地图、高分影像或地块图层；
- 关闭已打开的种植档案编辑态；无未保存内容的地块详情可以保留，用于确定地块查询点；
- 允许继续进行省、市、县、乡、村五级行政下钻和返回；
- 允许继续查看地块详情，但地块新增、筛选、修形和删除等编辑操作禁用，并明确提示“天气查看中可查看地块，编辑操作暂不可用”；
- 天地图文字注记仍保持最上层。

### 3.3 退出天气流程

右上天气头部提供明确的关闭按钮。关闭后：

- 终止尚未完成的天气请求和刷新计时；
- 清空天气面板的查询位置、模块数据、错误和展开状态；
- 保留退出瞬间的行政层级、地图中心、缩放级别及业务图层开关；
- 恢复地块工具的完整编辑能力；
- 不影响台风功能下一次独立进入时的既有规则。

## 4. 查询位置规则

### 4.1 查询点优先级

天气是点位查询。进入天气模式或空间上下文变化时，先按以下优先级确定默认查询点；用户也可按 4.2 节临时点选一个用于实时天气、分钟级降水和未来 24 小时预报的查询点：

1. 当前打开地块详情：使用该地块已保存的内部标注点；
2. 当前村：使用村面内部代表点，不使用村点生成边界；
3. 当前乡、县、市或省：使用当前行政面内部代表点；
4. 当前行政对象几何暂不可用：阻止位置天气请求并显示“当前区域暂时无法确定天气查询位置”，不得使用地图中心或不存在于现役 manifest 的 `bbox` 降级。

不得使用地图中心点作为默认天气查询点。用户平移地图不改变天气位置，也不触发请求。

### 4.2 默认位置变化与 Ctrl 点选实时天气

以下操作会改变默认天气查询位置并触发新一轮加载：

- 点击行政边界下钻；
- 通过面包屑或“回到上级”切换行政层级；
- 缩放自动进入或退出行政层级；
- 打开另一个地块详情；
- 关闭地块详情后回到当前行政区域代表点。

默认位置变化请求需要防抖，避免快速连续下钻产生无效并发请求；后发请求必须取消或覆盖先发请求，旧位置的响应不得写入新位置面板。

天气查看已开启且不存在地块编辑模式时，桌面用户可按住 `Ctrl` 并在地图上单击，临时查询该点击位置的实时天气：

- 普通单击行为完全不变，继续执行行政边界下钻、地块选择和其他现役地图交互；只有 `Ctrl + 地图左键单击` 触发点选天气；
- 地图根节点优先识别 `Ctrl` 修饰键并阻止该次点击继续传播到行政边界、地块、预警标牌或其他图层，避免同时触发天气查询和业务点击；
- 点击位置必须位于浙江省真实行政面内；前端先快速判断并提示，服务端再使用可信浙江省边界做点面校验。省外或仅落入浙江包围盒但不在省界内的点返回 `WEATHER_LOCATION_OUT_OF_ZHEJIANG`，且不请求和风天气或 APIHz；
- 临时点请求同一坐标的实时天气、APIHz `address`、未来两小时分钟级降水和未来 24 小时预报；不请求该点预警，不改变右上角当前层级预警列表；
- 默认行政/地块天气点及其数据继续保留；临时点使用视觉可区分的单个临时标记，并自动打开第 7–9 节共用的位置天气浮窗；
- 再次 `Ctrl + 单击` 时取消或忽略上一个临时点未完成的地址、实时天气、分钟降水和未来 24 小时请求，移除旧临时标记和浮窗，只保留最后点击的临时点；
- 关闭临时浮窗、按 `Esc`、退出天气查看，或通过现役逻辑切换行政层级/地块上下文时，移除临时点并恢复默认天气点；恢复时不自动打开默认浮窗；
- 临时点不会替换默认点，也不改变地图中心、缩放、行政层级或面包屑；临时浮窗保持打开时，手动刷新、每 10 分钟自动刷新和后台恢复刷新都作用于当前临时点的三类位置天气，关闭临时浮窗后恢复刷新默认点；预警始终按当前行政层级独立刷新；
- 实时天气模式下，地图顶部中央常驻快捷键提示“Ctrl + 左键单击可以按点选查询天气”；提示只作说明，不作为按钮，不拦截地图指针事件；进入天气模式时显示，退出天气模式时隐藏；
- 提示使用 `DESIGN.md` 的紧凑雾白浮层、清晰键帽/文字和低层阴影，不遮挡左上面包屑、右上预警列表或地图中心主要标记；窄视口允许整体缩小或换行，但不得删掉 `Ctrl`、`左键单击` 或 `点选查询天气`；
- `Ctrl` 点选是首期桌面增强能力，不为触屏设备伪造等价的普通点击行为；后续若需要触屏支持，另行增加明确模式入口。

### 4.3 浙江省范围校验

前端和服务端采用双重范围校验：

- 前端以现役行政层级树为业务依据：当前节点必须是浙江省或其后代节点；地块必须属于当前浙江省内村代码；
- 前端校验只控制入口和提示，不能作为服务端安全边界；
- 服务端不能信任浏览器传入的名称、层级或布尔值；聚合请求应携带当前行政代码，服务端校验该代码属于浙江省，并校验查询点与该行政对象的已知范围一致；
- 服务端可使用浙江省合理包围盒做快速拒绝，但包围盒只能作为第一层粗筛，不能把矩形内的省外区域误判为浙江业务范围；
- 校验失败统一返回 `400 WEATHER_LOCATION_OUT_OF_ZHEJIANG`，不访问任何和风天气上游接口；
- 首期仅允许 4.2 节受控的 `Ctrl + 单击` 临时点查询；不提供文本输入经纬度、URL 参数或地图中心查询，也不得用临时点绕过浙江省点面校验。

### 4.4 坐标口径

- 应用内部保持原始空间精度；
- 调用和风天气前由服务端将纬度、经度四舍五入到最多两位小数，以满足上游参数要求并与约 1 公里天气分辨率匹配；
- 实时、逐小时和分钟级降水在单个当前查询对象内使用同一组舍入坐标；天气预警按第 6 节分别使用当前层级直接子区域或当前县的代表点，不与其他三个 API 强制共用单一坐标；
- 常规接口路径顺序为 `{latitude}/{longitude}`；分钟级降水的 `location` 顺序为 `{longitude},{latitude}`，不得混用；
- 查询点必须校验为有限数值，纬度范围 `[-90, 90]`、经度范围 `[-180, 180]`，并通过 4.3 节浙江省业务范围校验。

### 4.5 位置文案与责任提示

面板始终显示查询对象和点位性质，例如：

```text
龙江村 · 地块 DK-330604102014-B-0012
地块内部代表点附近 · 30.04°N, 120.87°E
```

或：

```text
浙江省
行政区域代表点附近 · 29.18°N, 120.10°E
```

面板底部持续显示：

> 天气数据约为 1 公里分辨率的查询点附近信息，仅供风险辅助判断，不代表整块地块或整个行政区域的实测结果，不作为定损或理赔依据。

## 5. 天气总体布局

### 5.1 两个互斥天气模块

天气工具提供“气象预警”和“实时天气”两个互斥模块，不采用页签，不在同一时刻展示两类模块的面板、浮窗或地图标记：

- “气象预警”显示右上天气头部、当前层级预警地区列表与地图预警标牌；点击预警标牌或列表预警打开预警完整浮窗；
- “实时天气”显示默认位置可点击的天气标记，加载完成后不自动打开位置天气浮窗；点击标记后，在同一位置浮窗中依次展示实时天气、未来两小时降水和未来 24 小时预报；
- 选择另一模块时立即清除当前模块的面板、浮窗和地图标记，再加载另一模块；
- 单模块失败只影响本模块；预警模块在头部汇总提示“部分数据更新失败”，实时天气在位置浮窗内提供模块级重试。

### 5.2 右上天气头部与预警列表

桌面端右上容器宽度 360–390px，使用 `DESIGN.md` 的雾白表面、细边界、紧凑间距和系统字体。头部固定展示：

- 标题“天气”；
- “当前范围：当前行政对象名称”；
- 当前聚合状态：加载中、正在更新、部分数据更新失败或上次成功时间；
- 统一刷新按钮；
- 退出天气按钮。

头部下方为第 6.5 节当前层级预警地区列表。乡、村或地块层级不发起预警请求，但头部继续常驻并在预警区域显示“天气预警查看到县级”。

统一刷新同时处理当前行政层级预警和当前可见位置天气：无临时点时刷新默认点，临时浮窗打开时刷新临时点。手动刷新尊重模块缓存，仅过新鲜期的模块访问上游；地址仍新鲜时不重复请求。界面显示各模块数据时间或缓存年龄，不能把点击刷新时间冒充上游数据时间。

刷新期间保留上次成功数据并显示“正在更新”；刷新失败时保留旧数据并标注“更新失败，上次成功获取于 …”，不得先清空整个容器。

### 5.3 地图浮窗与响应式规则

- 地图始终是最大视觉区域；右上容器、预警标牌、天气标记和地图浮窗均不得触发地图相机移动；
- 数值使用等宽数字，状态不能只依赖颜色；不使用营销式大标题、全屏卡片或装饰性渐变；
- 预警标牌组超过地图可用宽度时使用限定宽度的水平滚动条带，所有预警仍保持独立标牌和既定排序，不合并、不丢弃、不动态缩小到不可读；
- 720px 以下减少辅助文案和间距；
- 520px 以下，右上天气头部左右各保留 12px，位置天气或预警浮窗改为左右各保留 12px的近全宽浮层，正文内部纵向滚动、小时卡片内部横向滚动；关闭和刷新始终可达；
- 触屏设备首期可查看默认行政/地块位置天气，但不提供任意点查询；不得用普通点击或长按替代桌面的 `Ctrl + 左键单击`。

## 6. 生效天气预警

### 6.1 已确认的层级与业务口径

天气预警只使用和风天气实时天气预警 API，并接受“行政区域代表点命中预警”的业务口径。预警查看到县级为止，不继续下钻到乡、村或地块：

| 当前地图层级 | 本轮预警查询对象 | 地图呈现 |
|---|---|---|
| 浙江省 | 11 个直属地市各自的行政面内部代表点 | 在命中预警的市级区域显示预警标记 |
| 市 | 当前市下辖各区县各自的行政面内部代表点 | 在命中预警的区县区域显示预警标记 |
| 县 | 当前县行政面内部代表点 | 显示当前县代表点命中的预警列表与详情，不再查询乡镇 |
| 乡、村、地块 | 不发起新的预警查询 | 不展示乡级、村级或地块级预警；其他三个天气 API 的层级范围不因本规则改变 |

统一语义：

- 有结果表示“该市/区县代表点命中官方生效预警”，不表示整个行政区域均处于预警覆盖范围；
- 空结果表示“该市/区县代表点未查询到生效预警”，不宣称该行政区域任何位置都没有预警；
- 地图标记定位在子区域内部代表点，不使用预警颜色填充整个行政面；
- 天气右上容器与预警浮窗均不显示“基于行政区域代表点查询，预警覆盖范围以发布机构原文为准”这段说明；该说明仅保留在需求与数据语义中，不进入用户界面；
- 不生成或使用“乡镇级预警”“村级预警”“地块级预警”等产品表述。

天气预警与三类位置天气按第 5 节同时开启；预警地区列表常驻右上天气容器，预警地图浮窗与位置天气浮窗全局互斥。

### 6.2 查询、去重与状态

进入浙江省、市或县级时按 6.1 节按需查询；不后台预扫描浙江省全部县级及更深层级。

- 省级最多并行查询当前 11 个地市代表点；市级只查询当前市的直接区县；县级只查询当前县代表点；
- 查询结果按行政代码分别缓存，预警缓存新鲜期沿用 5 分钟；同一舍入坐标合并在途请求；
- 同一预警可能被多个相邻代表点命中：地图保留各行政对象自己的命中标记，预警详情数据按 `alerts[].id` 去重存储，但保留全部命中的行政代码；
- 切换行政层级时取消或忽略旧层级未完成响应，旧层级结果不得写入新层级；
- 代表点请求成功且 `metadata.zeroResult=true` 或返回空 `alerts[]` 时，该行政对象不显示地图预警标记；
- 某个代表点请求失败时，不得按“无预警”处理；该行政对象显示加载失败状态和独立重试能力；
- 一个子区域失败不阻断其他子区域已经成功的预警标记。

某个行政对象存在预警时：

- 展示该代表点返回的全部有效 `alerts[]`，按严重程度从高到低、同等级按 `issuedTime` 从新到旧排序；
- 同一代表点存在多条有效预警时，每条预警都生成独立标牌并水平并排，不合并成“主预警 + 数量”，也不纵向堆叠；
- 每条地图标牌至少显示事件名称和预警颜色等级；点击后的预警浮窗严格按 6.7 节 8 项字段展示，不添加发布机构、失效时间或其他字段；
- 更新或取消类预警根据 `messageType.code` 和 `supersedes[]` 处理，不能把被明确取代或取消的旧预警继续作为并列生效预警展示。

县级代表点无预警时可在预警查看区显示：

> 当前县代表点未查询到生效天气预警

省、市级无命中时，地图不显示预警标记，右上角常驻列表显示当前层级统一空状态。请求失败不得降级成“未查询到预警”。

### 6.3 地图预警标牌

地图标牌按用户提供的高温、大风、暴雨参考图组织信息，但只参考结构，不逐像素复制其尺寸、字体和品牌样式：

```text
┌────────┬────────┐
│        │  暴    │
│ 灾种   │  雨    │
│ 图标   │        │
├────────┴────────┤
│    红色预警      │
└─────────────────┘
```

结构规则：

- 标牌锚定在市或区县行政面内部代表点；县级则锚定当前县代表点；
- 上部为左右两栏：左栏显示灾种 SVG 图标，右栏显示 `eventType.name` 中文灾种名称；
- 下部为通栏，只显示“红色预警”“橙色预警”“黄色预警”“蓝色预警”等中文等级，不保留参考图中的英文灾种名；
- 背景、边框和分隔线使用 `color` 返回的预警建议色，图标与主要文字使用满足对比度要求的前景色；白、浅灰等低对比背景自动使用深色文字和边框；
- 颜色不是唯一线索，底栏必须显示中文等级文字，右栏必须显示中文灾种名称；
- 两字灾种按参考图纵向排列；3–6 字灾种允许使用两列紧凑排版或缩小字号，但不得截断；更长名称改为两行中文并保留完整可访问名称；
- 标牌使用紧凑地图尺寸，不照搬参考图的 128×103 像素；最终尺寸以省级 11 市同时可读且不过度遮挡行政边界为验收基准；
- 标牌组以代表点为中心水平排列，按严重程度从高到低、同等级按发布时间从新到旧排序；靠近地图边缘时整体向可视区内偏移，不能裁掉首尾标牌；
- 每个标牌独立可悬停、键盘聚焦和点击，交互只作用于对应 `alert.id`，不得因点击标牌触发行行政边界下钻；
- 选中标牌增加清晰外框或置顶反馈，不改变上游预警颜色本身；
- 查询成功但无预警时不创建标牌；查询失败使用独立的中性异常标记，不使用任何预警等级颜色。

同一代表点多条预警并排是已确认规则。标牌组超过地图可用宽度时，使用锚定代表点的限定宽度横向滚动条带；保留全部独立标牌、排序、键盘操作和首尾方向提示，不静默丢弃、合并或缩小到不可读。

### 6.4 和风天气图标规则

- 预警标牌优先使用 `alerts[].icon` 对应的 QWeather Icons 预警 SVG；`eventType.code` 只用于事件识别和兼容，不冒充天气现象代码；
- [天气现象代码](https://dev.qweather.com/docs/resource/weather-conditions/)中的 `condition.code` 仅用于实时天气和逐小时预报的天气现象图标，不用于天气预警标牌；
- QWeather Icons 中，天气数据 `icon` 可直接对应同名 SVG 或图标字体；预警图标同理按接口返回图标代码映射；
- 首期通过 npm 安装 `qweather-icons` 并在本地构建中使用 SVG/图标字体，不依赖运行时 CDN；
- QWeather Icons 源码采用 MIT License，仓库分发相关资源时保留其版权与许可声明；设计源文件的 CC BY 4.0 与代码图标许可不得混淆；
- 图标代码可能新增、修改或删除，前端不得封闭枚举；未知或缺失图标使用通用天气预警图标，并继续显示完整中文灾种和等级；
- 不把用户提供的三张截图文件直接复制进仓库，它们仅作为结构参考。

### 6.5 右上角常驻预警地区列表

省、市、县三级在预警查看期间都必须在地图右上角显示“当前层级预警地区”常驻列表，列表随当前行政层级和查询结果同步更新，不因地图标牌未被点击而隐藏。

列表结构：

```text
┌ 当前层级预警地区 ───────────┐
│ 浙江省 · 3 个地区 / 5 条预警 │
│                              │
│ 上虞区  [暴雨红] [雷电黄]    │
│ 柯桥区  [大风蓝]             │
│ 嵊州市  [高温橙] [雷电黄]    │
└──────────────────────────────┘
```

- 省级列表按地市分组，只显示代表点命中至少一条预警的地市；市级列表按区县分组；县级列表只显示当前县及其全部命中预警；
- 每个地区行显示行政名称和该代表点命中的全部预警小标牌，不把多条预警折叠成数量；列表小标牌采用紧凑横向结构，固定显示灾种图标、中文灾种和中文等级；
- 地区按其最高严重程度从高到低排序，同等级按该地区最新预警发布时间从新到旧排序；同一地区内预警继续按严重程度和发布时间排序；
- 标题显示“命中预警的地区数 / 去重前标牌总数”；同一预警命中多个地区时，每个地区行仍保留自己的标牌，地区数和标牌数按地图呈现实例统计；
- 当前层级全部代表点成功且均无预警时，列表保持显示并呈现“当前层级各代表点未查询到生效天气预警”；
- 部分子区域失败时，列表在预警地区之后显示中性“数据获取失败”分组及重试入口，不把失败地区计入无预警；
- 加载过程中显示已完成数/总数，成功地区可以逐步进入列表，但列表排序在每次数据更新后保持稳定规则；
- 列表内容过长时在面板内部纵向滚动，不撑高地图页面；520px 以下保持列表标题、关闭/收起和预警选择可达；
- 列表与其他三个天气模块同时开启，并与天气模式标题、统一刷新和关闭共用第 5.2 节右上容器；位置天气通过地图标记和浮窗呈现，不挤入列表滚动区。

### 6.6 列表、标牌与既有行政下钻的职责

点击右上角列表中的具体预警或地图预警标牌，只选择该条预警并打开地图浮窗，不改变行政层级、地图中心或缩放级别。

行政层级和视角切换继续完全复用现役地图下钻逻辑：

- 点击行政区边界：按现役 `flyToBounds` 进入市级或县级；
- 放大/缩小：按现役缩放阈值自动进入或返回行政层级；
- 面包屑和“回到上级”：按现役导航规则切换层级与视角；
- 预警列表、预警标牌和预警浮窗不得调用行政下钻、`flyToBounds`、固定缩放或自动居中；
- 行政层级通过既有逻辑发生变化后，右上角列表与地图标牌才随新层级重新计算：省级显示市、市级显示区县、县级显示本县；
- 点击列表地区行空白只选中并高亮对应地区，不改变视角，不打开第一条预警；只有点击具体预警小标牌才打开其浮窗；
- 地图标牌与列表具体预警的点击行为完全一致，二者互相同步选中；
- 通过既有逻辑下钻或返回时关闭旧层级预警浮窗，恢复新层级常驻列表；缓存仍新鲜时复用，否则只重新请求到期代表点；
- 快速连续点击不同预警时只更新选中项和浮窗内容，不启动或干扰地图动画；最后一次点击生效；
- 列表、地图标牌和浮窗严格按 `行政代码 + alert.id` 同步，不能仅按 `alert.id` 选择地区，因为同一预警可能命中多个行政代表点；
- 选中态需要同时在列表行、具体预警小标牌和地图标牌上体现，不能只依靠颜色。

### 6.7 点击预警后的完整地图浮窗

点击右上角列表中的具体预警或地图标牌后，在对应行政代表点上方一次性完整展示该条预警信息，不设置“查看详细”按钮，也不再打开二级详情层：

```text
┌──────────────────────────────┐
│ 预警标题                   × │
├──────────────────────────────┤
│ 发布时间      YYYY/MM/DD HH:mm│
│ 紧迫程度      ……             │
│ 严重程度      ……             │
│ 确定性        ……             │
│                              │
│ 预警说明                      │
│ 完整说明正文……                │
│                              │
│ 触发标准                      │
│ 完整标准……                    │
│                              │
│ 防御指南                      │
│ 完整指南……                    │
└───────────────▽──────────────┘
```

浮窗规则：

- 浮窗锚定当前预警所属行政对象的内部代表点，箭头指向该代表点；打开浮窗不得自动平移、缩放或切换行政层级；
- 浮窗使用参考图的“有色标题栏 + 白色正文”信息结构，具体颜色、圆角、阴影和字体遵循 `DESIGN.md`，不逐像素复制截图；
- 浮窗严格只展示 8 项：`headline` 标题、`issuedTime` 发布时间、`urgency` 紧迫程度、`severity` 严重程度、`certainty` 确定性、`description` 完整预警说明、`criteria` 完整触发标准、`instruction` 完整防御指南；发布机构、事件名称、颜色等级、预警性质、生效时间、预计开始时间、失效时间和应对方式不得添加到浮窗；
- 标题栏显示 `headline` 和关闭按钮；标题异常缺失时显示“预警标题暂缺”，不得用发布机构、事件名或颜色等级拼接补造标题；关闭只清除当前浮窗和预警选中态，不关闭右上角常驻列表，也不退出天气/预警查看；
- `issuedTime` 或 `description` 异常缺失时对应位置显示 `--` 并记录结构异常；官方可能返回空值的 `urgency`、`certainty`、`criteria`、`instruction` 为空时隐藏对应行或整个区块；`severity` 若异常缺失则显示 `--`；
- `urgency`、`severity`、`certainty` 有值时按官方枚举映射为中文，不显示原始英文代码；未知枚举显示“未知”，不得自行推断；
- 不对 `description`、`criteria` 或 `instruction` 做省略、摘要或字符截断；长内容在浮窗正文区域内部纵向滚动，标题栏和关闭按钮保持可见；
- 浮窗设置不超过地图可用高度的最大高度；滚动只发生在正文内部，不撑高页面、不移动地图相机；
- 浮窗保持在地图可视区域内，靠近顶部、右侧常驻列表或视口边缘时调整自身方向/偏移，不移动地图相机；
- 同一时间只显示一个预警浮窗；点击另一条预警原位切换到对应代表点及完整内容；
- 点击地图空白或按 `Esc` 关闭浮窗；点击浮窗内部、选择文字、滚动正文和操作右上列表不关闭；
- 浮窗内容严格按 `行政代码 + alert.id` 取值，禁止回退到该地区最高等级预警或其他地区同 ID 记录；
- `metadata.attributions[]` 放在天气面板公共底部持续展示，不放入预警浮窗，确保浮窗仍严格只有上述 8 项业务字段；
- 多条并排标牌之间可以切换，最后点击的预警成为当前完整浮窗内容。

### 6.8 官方响应字段与展示用途

字段范围以和风天气官方[实时天气预警 API 文档](https://dev.qweather.com/docs/api/warning/weather-alert/)为准，不根据参考截图补造字段。

预警浮窗严格只展示以下字段：

| 官方字段 | 浮窗用途 | 空值处理 |
|---|---|---|
| `alerts[].headline` | 标题 | 异常缺失时显示“预警标题暂缺”，不组合其他字段 |
| `alerts[].issuedTime` | 发布时间 | 按返回时区解析并以北京时间展示；异常缺失显示 `--` |
| `alerts[].urgency` | 紧迫程度 | 可能为空；为空时隐藏，有值时映射为中文 |
| `alerts[].severity` | 严重程度 | 有值时映射为中文；异常缺失显示 `--` |
| `alerts[].certainty` | 确定性 | 可能为空；为空时隐藏，有值时映射为中文 |
| `alerts[].description` | 完整预警说明 | 不截断；异常缺失显示 `--` |
| `alerts[].criteria` | 完整触发标准 | 可能为空；为空时隐藏整个区块 |
| `alerts[].instruction` | 完整防御指南 | 可能为空；为空时隐藏整个区块 |

其他字段用于地图标牌、常驻列表、数据处理或公共归因，不进入预警浮窗：

- `alerts[].id`：预警唯一标识，用于选择、缓存和去重；
- `alerts[].senderName`：可参与列表辅助信息或诊断，但不进入浮窗；
- `alerts[].messageType.code`、`alerts[].messageType.supersedes[]`：预警性质及被取代/取消的预警 ID，用于生效关系处理，不进入浮窗；
- `alerts[].eventType.name`、`alerts[].eventType.code`：地图标牌和列表中的事件名称及识别映射，不进入浮窗；
- `alerts[].icon`：QWeather Icons 图标代码；
- `alerts[].color.code`、`alerts[].color.red/green/blue/alpha`：地图标牌、列表和浮窗标题栏的辅助颜色计算，不作为浮窗字段；
- `alerts[].effectiveTime`、`alerts[].onsetTime`、`alerts[].expireTime`：保留用于生效判断、排序或诊断，不进入浮窗；
- `alerts[].responseTypes[]`：保留用于数据兼容，不进入浮窗；
- `metadata.attributions[]`：在天气面板公共底部共同展示，不进入浮窗；
- `metadata.tag`：响应数据唯一标识，用于缓存或诊断；
- `metadata.zeroResult`：成功无数据状态判断。

颜色不得覆盖 `DESIGN.md` 的基础语义规则，也不得作为唯一等级线索。界面必须同时显示事件名称和等级文字。官方响应新增未知字段时不得自动呈现，需先确认业务含义和许可要求。

## 7. 当前天气

### 7.1 地图标记与查询点地址

实时天气使用当前天气查询点，在地图上常驻一个紧凑的“天气现象图标 + 温度”标记：

```text
┌──────────┐
│  ☔ 26℃  │
└────▽─────┘
```

- 标记锚定实时天气、分钟降水和逐小时共用的查询点；天气预警继续使用第 6 节自己的行政代表点，不与该标记合并；
- 图标使用 `condition.code` 对应的本地 QWeather Icons 天气现象图标，温度使用 `temperature` 并带上游单位；
- 进入天气模式后立即显示可点击的骨架标记“通用加载图标 + `--`”，加载完成后替换为天气图标和温度，不自动打开浮窗；点击标记后在同一查询点上方打开位置天气合并浮窗；
- 点击标记只打开浮窗，不改变地图行政层级、中心和缩放，不触发现役下钻；
- 天气现象图标不是唯一信息，标记提供可访问名称“当前地址附近，天气现象，温度”；图标未知时使用通用天气图标；实时天气失败时保留“通用天气图标 + `--`”异常标记，仍可点击查看分钟降水、未来 24 小时及实时模块错误；
- 同一查询点的实时天气标记与预警标牌重叠时执行碰撞避让，但不得移动地图相机或合并不同数据语义。

实时天气浮窗标题使用 APIHz“查指定经纬度地址-聚合官方版”接口返回的 `address`，统一显示为“`address` 附近”。

地址请求规则：

- 请求本站服务端地址代理，浏览器不得直接携带 APIHz `id`、`key` 或 `dkey`；
- 地址接口使用与和风实时天气完全相同的原始查询点，经度传 `lon`、纬度传 `lat`，不得使用天气接口舍入后的坐标反查地址；
- 首期只使用 `address` 作为标题，不展示 `address_near`、`poi`、`road`、距离或方向，避免把最近地点误表述为查询点地址；
- `address` 可能只到省、市、县或乡镇/街道，不承诺返回村名、门牌号或精确地址；标题始终加“附近”；
- 地址查询成功但 `hctype=2` 或返回 `jd` 时仍只显示“附近”，不展示为精确定位；
- 地址查询失败、超时、结构异常或 `address` 为空时不阻断实时天气：行政上下文降级为“`当前行政对象名称` 代表点附近”，地块上下文降级为“当前地块查询点附近”；
- 地址独立缓存和合并在途请求，缓存新鲜期固定为 30 天；天气每 10 分钟刷新时不重复请求仍新鲜的地址；查询点变化后使用新坐标重新查询；
- 地址结果和错误日志不得包含 APIHz 凭据，缓存键使用规范化坐标；服务端沿用 APIHz 代理的超时、响应大小、限流和脱敏错误边界；
- 地址增强纳入首轮研发，但不是天气主体的验收门槛：新增可选 `APIHZ_ADDRESS_URL`；未配置请求线路、许可/额度未确认、超时或失败时立即按既定行政/地块/临时点文案降级，不阻断其他天气模块，不绕过授权请求上游。

### 7.2 完整实时天气浮窗字段

点击天气标记后，在一个浮窗中一次性展示全部已选实时天气字段，不设置“更多数据”折叠区或二级详情。

当前天气突出与农险现场风险更相关的信息：

- `condition.text`：天气现象；
- `temperature`：温度；
- `feelsLike`：体感温度；
- `precipitation.amount`：累计一小时降水量；
- `precipitation.intensity`：降水强度；
- `precipitation.type`：雨、雪、冰粒/冻雨、混合降水或无降水；
- `humidity`：相对湿度，接口 `[0,1]` 转为百分比。

实时天气浮窗不展示 `wind.direction`、`wind.speed`、`wind.scale`、`windGust`、`visibility`、`pressure`、`dewPoint`、`cloudCover` 或 `uvIndex`。这些字段即使由 API 返回也不进入实时天气标记或浮窗；未来 24 小时模块同样不展示这些扩展指标，按第 9 节执行。

所有数值连同上游返回的单位展示，不在前端猜测单位。缺失值显示 `--`。

浮窗正文过长时内部纵向滚动，标题和关闭按钮保持可见；打开、关闭或滚动浮窗均不改变地图层级和视角。同一时间只显示一个实时天气浮窗。

### 7.3 文案示例

```text
浙江省绍兴市越城区某街道附近
小雨  26℃
体感 28℃

近一小时降水  1.2 mm
降水强度      0.8 mm/h
降水类型      雨
湿度          86%
```

天气现象文字必须存在；天气图标只作辅助，不得仅用图标表达天气状态。

## 8. 未来两小时降水

### 8.1 浮窗入口与查询点

未来两小时降水不新增独立地图标记，复用第 7 节的实时天气标记和单层浮窗：

- 点击默认实时天气标记后，同一浮窗先展示实时天气字段，再以分隔线接续“未来两小时降水”模块；
- 默认行政/地块点的分钟降水与实时天气使用完全相同的舍入坐标；不能把其他行政对象或旧位置的降水数据放入当前浮窗；
- `Ctrl + 左键单击` 临时点同步请求该点击坐标的实时天气、APIHz 地址和分钟降水，浮窗三个部分必须属于同一原始点位；
- 临时点仍不查询预警；再次点选或清除临时点时，同时取消/忽略旧点的地址、实时天气、分钟降水和未来 24 小时请求；
- 实时天气和分钟降水在浮窗中共享位置标题，但保持独立的加载、成功、空和失败状态；分钟级模块失败不隐藏实时天气，实时天气失败时分钟降水仍可独立显示；
- 打开、关闭或滚动分钟降水区域不改变地图行政层级、中心或缩放。

### 8.2 数据范围

分钟级降水仅用于中国区域，按约 1 公里精度返回未来 2 小时、每 5 分钟的临近降水预报。首期直接使用：

- `updateTime`：该模块更新时间；
- `summary`：上游分钟降水描述；
- `minutely[].fxTime`：预报时间；
- `minutely[].precip`：5 分钟累计降水量，单位毫米；
- `minutely[].type`：`rain` 或 `snow`；
- `refer`：数据来源和许可信息。

### 8.3 柱状趋势图

模块按以下顺序展示：标题“未来两小时降水”、上游 `summary`、`updateTime` 格式化后的“更新于 HH:mm”、雨雪图例和柱状趋势图。

- 使用紧凑柱状趋势图展示全部实际返回时点，每根柱对应一个 `minutely[]` 时点和该 5 分钟累计降水量；不自行插值、不补齐缺失时点；
- 纵轴使用上游降水单位并从 0 起；所有非零柱按本组最大值建立可比较比例，不能因单个极值把其他非零柱压成不可见；具体最小可见高度只作视觉辅助，悬停数值仍以真实值为准；
- 横轴至少标出开始、约 30 分钟、60 分钟、90 分钟和结束时间；标签使用实际 `fxTime`，跨小时或跨日时不得只写相对分钟造成歧义；
- `rain` 和 `snow` 使用不同颜色，并同时显示“雨”“雪”文字图例；只出现一种类型时只显示对应图例；未知类型使用中性色和“其他降水”，不得静默归为雨；
- 颜色不是唯一线索，每根柱提供可访问标签；鼠标悬停或键盘聚焦单个柱时显示具体时间、5 分钟累计降水量和中文类型；
- 图表提供包含全部实际时点的可访问名称或等价数据列表，不能只靠柱高传达信息；
- `summary` 和 `updateTime` 缺失时分别显示“暂无降水摘要”和 `--`，但实际数组合法时仍展示趋势；
- 全部 `precip=0` 时保留整个模块、上游摘要和完整时间轴，柱图显示零线，并明确显示“未来两小时暂无降水”，证明查询成功而非未加载；
- 上游明确表示该坐标无临近预报时显示“当前查询位置暂无分钟级降水预报”，不画零线，避免把无数据误作全零；
- 接口失败或结构异常时显示“未来两小时降水加载失败”和独立重试入口，不影响同浮窗中的实时天气；
- 浮窗内容过高时实时天气与分钟降水共用正文滚动区，位置标题和关闭按钮保持可见，不另开二级详情。

此模块只能描述查询点附近的临近降水趋势，不得表述为地块边界内均匀降雨。

## 9. 未来 24 小时

### 9.1 浮窗入口与查询点

未来 24 小时预报不新增地图标记，继续接在同一位置天气浮窗的分钟降水模块下方。浮窗顺序固定为：实时天气、未来两小时降水、未来 24 小时预报。

- 默认行政/地块点的逐小时预报与实时天气、分钟降水使用完全相同的舍入坐标；
- `Ctrl + 左键单击` 临时点同步请求该点击坐标的地址、实时天气、分钟降水和未来 24 小时预报，四部分必须属于同一原始点位；
- 临时点仍不查询天气预警；再次点选或清除临时点时，同时取消或忽略旧点四部分未完成请求；
- 逐小时模块保持独立的加载、成功和失败状态；逐小时失败只显示自身错误和重试入口，不隐藏实时天气或分钟降水；
- 打开、横向滚动或键盘浏览小时卡片不改变地图行政层级、中心或缩放。

### 9.2 请求与展示字段

逐小时接口固定请求 `hours=24`，不在首期请求或展示 240 小时。每个实际返回时点只展示：

- `forecastTime`：时间；
- `condition.code`、`condition.text`：天气现象图标和文字；
- `temperature`：温度；
- `precipitation.probability`：降水概率；
- `precipitation.amount`：降水量。

不展示 `feelsLike`、`humidity`、`wind.direction`、`wind.speed`、`wind.scale`、`windGust`、`precipitation.intensity`、`precipitation.type`、`pressure`、`visibility`、`dewPoint`、`cloudCover` 或 `uvIndex`；即使 API 返回也不得自动加入小时卡片或展开层。

### 9.3 横向小时卡片

- 使用横向滚动的紧凑小时卡片，保留接口返回的全部实际时点；不使用纵向表格、综合温度折线或二级详情；
- 每张卡片从上到下显示时间、天气图标与天气文字、温度、降水概率和降水量；天气文字必须存在，不能只靠图标；
- 按 `forecastTime` 升序显示；同一时间保持上游顺序；跨日后首个时点明确显示“明天”或月日，不能只显示小时；
- 降水概率由 `[0,1]` 转为 `0–100%`；降水量保留上游单位；缺失字段显示 `--`，不得推测或由相邻小时补齐；
- 首次打开时定位到第一个实际时点；支持滚轮横向转换、触控板横滑、拖动滚动条和键盘左右方向键浏览；不得劫持地图缩放滚轮，指针离开卡片区域后地图滚轮恢复正常；
- 卡片滚动区两侧在尚有隐藏内容时显示轻量方向提示；到达首尾后隐藏对应提示，不额外增加自动轮播；
- 少于 24 个时点时展示全部实际结果，并在模块标题旁显示“数据不完整：共 N 个时点”；不自行补点；
- 返回空数组或结构异常时视为失败，显示“未来 24 小时预报加载失败”和独立重试入口；
- 不从逐小时数据计算未经确认的风险等级、灾损概率或业务建议；
- 不把逐小时预报与分钟级临近预报拼接成一条连续降水序列；两个模块分别标明“每 5 分钟”和“每小时”的时间粒度及各自数据来源；
- 浮窗整体过高时三个模块共用正文纵向滚动区，小时卡片仅在自身区域横向滚动；位置标题和关闭按钮保持可见。

## 10. 加载、刷新与异常

### 10.1 首次加载

进入天气模式或查询位置变化时，服务端并行请求 4 个和风天气能力；实时天气使用的 APIHz 地址反查作为独立辅助请求并行执行，不阻塞任一天气模块。前端模块独立进入以下状态：

```text
loading → success | empty | error
```

- 任一模块成功即可先展示，不等待全部模块完成；
- 天气预警、分钟降水为空是合法业务状态；
- 实时天气和逐小时返回空结构视为异常；
- 旧位置数据在新位置加载时不得继续伪装为新位置数据；可保留但必须明显标注“正在加载新位置”，成功后整体切换。

### 10.2 刷新规则

天气不同于台风会话快照，需要保持时效，但浏览器刷新不等于无条件请求全部上游模块：

- 天气模式打开且页面可见时，每 10 分钟刷新当前可见位置天气：临时浮窗打开时刷新临时点，其他情况刷新默认点；预警始终按当前行政层级刷新；
- 用户可点击右上天气头部刷新按钮立即请求本站代理，目标与自动刷新一致；
- 页面从后台恢复可见时，如果距离上次成功获取已超过 10 分钟，立即请求本站代理；
- 代理按模块缓存时效决定返回新鲜缓存或请求上游，不因一次面板刷新重复获取尚未到期的逐小时数据；
- 手动刷新不绕过服务端仍有效的模块缓存；界面展示各模块实际数据时间或缓存年龄，不能把代理响应时间冒充数据更新时间；
- 同一查询点已有请求进行中时，不重复发起自动或手动请求；
- 位置变化优先于旧位置刷新，旧请求应取消；
- 关闭天气模式或退出页面后停止自动刷新；
- 台风模式继续遵循自己的单次快照规则，不因天气刷新策略改变。

10 分钟是首期浏览器刷新周期，模块缓存时效以 11.3 节为准。正式开发前仍需结合和风天气订阅额度和限流实测复核；若额度不支持，必须调整需求文档和界面时效提示，不能静默取消刷新。

### 10.3 部分失败与重试

聚合接口必须允许部分成功。例如天气预警成功、分钟降水失败时：

- 正常展示成功模块；
- 失败模块显示自身错误和独立重试入口；
- 头部显示“部分数据更新失败”；
- 不把整个面板替换为统一错误页。

服务端统一区分：参数错误、未配置、上游超时、上游限流、上游结构异常和服务繁忙。返回给浏览器的错误不得包含 API KEY、项目 ID、凭据 ID、真实上游请求头或内部堆栈。

重试遵循和风天气[优化请求](https://dev.qweather.com/docs/best-practices/optimize-requests/)建议：

- `400`、`401`、`403` 等参数或认证类错误不自动重试；暂停对应上游请求并暴露可诊断的脱敏错误，修复配置后再恢复；
- `429` 和明确可恢复的临时错误使用带随机抖动的截断指数退避，不进行固定间隔或无限重试；
- 指数计数最大取 `c=10`，单次本站请求不能等待整个退避周期，应及时返回限流状态并让后续请求遵守共享冷却时间；
- `Retry-After` 等上游明确重试提示存在时优先遵循；
- 同一模块、同一舍入坐标共享退避和在途请求，避免多个浏览器同时放大请求量；
- 错误状态下不得由浏览器高频轮询，否则可能触发上游安全策略或账户冻结。

## 11. 服务端代理与安全

### 11.1 代理边界

前端只访问本站代理，首期使用一个聚合入口。请求必须同时携带可信校验所需的当前行政上下文和位置天气目标，不能只传裸经纬度：

```http
GET /api/weather?contextLevel=city&contextCode=330600&target=admin
GET /api/weather?contextLevel=village&contextCode=330604102014&target=parcel&lat=30.04&lon=120.87
GET /api/weather?contextLevel=city&contextCode=330600&target=picked&lat=30.27&lon=120.15
```

参数语义：

- `contextLevel`、`contextCode`：当前地图行政层级和代码，决定预警查询范围及右上列表；必须与服务端行政树匹配；
- `target=admin`：服务端按当前行政对象可信几何的内部代表点生成位置天气坐标，不接受浏览器自报坐标；
- `target=parcel`：浏览器提交已保存地块内部点及所属村上下文；服务端至少验证村代码属于浙江、坐标位于该村可信边界内；
- `target=picked`：`Ctrl + 左键单击` 临时点；服务端验证坐标位于浙江省真实边界内，不要求落在当前行政对象内，但预警仍按 `contextLevel/contextCode` 查询；
- 参数重复、未知参数、层级代码不匹配、缺失必需坐标或多余坐标均返回脱敏 `400`，不请求上游；
- 前端切换行政层级、地块或临时点时使用新的完整请求键；旧响应不得覆盖新上下文。

服务端职责：

1. 从 `WEATHER_DATA_DIR` 读取由现有数据准备流程生成的 `manifest.json`、`boundary/`、`villages/` 及天气空间索引；校验行政代码属于浙江省，并使用可信边界做点面校验，再限制和舍入坐标；边界数据缺失或不可解析时返回服务未配置，不得用包围盒放行；
2. 通过配置的专属 API Host 和 HTTPS 请求上游，并在 `X-QW-Api-Key` 请求头中发送 API KEY；不得同时使用 JWT 或 `key` 查询参数；
3. 使用标准 URL 构造器和百分号编码生成参数，分钟级 `location` 中的英文逗号编码为 `%2C`，不手工拼接包含凭据或用户输入的完整 URL；
4. 按当前层级请求天气数据：实时、24 小时和分钟级降水使用当前查询对象坐标；预警按第 6 节请求市级子区域、县级子区域或当前县代表点，不预抓取未打开层级；
5. 将不同版本接口规范化为稳定的本站响应，并保留上游单位、时间和归因信息；
6. 对相同舍入坐标做模块级缓存、并发合并、超时、退避和响应体大小保护；
7. 对每个模块独立返回成功、空或错误状态；APIHz 地址未配置或失败时返回可降级的地址模块错误，不把整个聚合请求判为失败。

规范化响应至少包含：

```ts
interface WeatherBundleResponse {
  location: {
    lat: number
    lon: number
  }
  fetchedAt: string
  address: WeatherModule<ReverseGeocodedAddress | null>
  current: WeatherModule<CurrentWeather | null>
  alerts: WeatherModule<WeatherAlert[]>
  minutely: WeatherModule<MinutelyForecast | null>
  hourly: WeatherModule<HourlyForecast[]>
  attributions: Attribution[]
}

type WeatherModule<T> =
  | { status: 'success'; data: T }
  | { status: 'empty'; data: T; message: string }
  | { status: 'error'; error: { code: string; message: string } }
```

具体 DTO 字段按第 6–9 节官方字段白名单在适配器中细化，但不得移除模块级状态、位置目标标识和归因信息。响应必须回显规范化 `contextLevel/contextCode/target` 及实际天气查询坐标，前端据此拒绝旧上下文响应。

### 11.2 凭据

首期按用户确认采用和风天气 API KEY 认证。官方仍推荐 JWT，且官方文档说明自 2027 年 1 月 1 日起将限制 API KEY 认证的每日请求数量；因此本方案只用于当前内部技术验证，进入长期运行或对外环境前必须重新评估并优先迁移 JWT。

- API KEY 只通过 `X-QW-Api-Key` 请求头发送，不放入 URL 的 `key` 查询参数，避免被代理日志、历史记录或错误页记录；
- 不得同时发送 API KEY 和 JWT，否则可能认证失败；
- API Host、项目 ID、凭据 ID 和 API KEY 只存在服务端环境变量或未提交的 `server/.env.local`；项目 ID 与凭据 ID只用于配置识别和运维核对，API KEY 请求本身不需要把它们发送给上游；
- 不使用 `VITE_*` 暴露任何和风天气认证信息；
- 不在日志、测试快照、报告、README 示例或错误响应中记录真实 API KEY、完整 `X-QW-Api-Key` 请求头或带 `key` 参数的 URL；
- 仓库只在 `server/.env.example` 提供无真实值的变量名与说明；
- 当前约定变量为 `QWEATHER_AUTH_MODE=api-key`、`QWEATHER_API_HOST`、`QWEATHER_PROJECT_ID`、`QWEATHER_CREDENTIAL_ID`、`QWEATHER_API_KEY`；天气另使用 `WEATHER_DATA_DIR` 指向包含 `manifest.json` 和边界目录的本地数据产物，可选 `APIHZ_ADDRESS_URL` 指向登录后台获得的地址请求线路；示例不得包含真实线路中的凭据；
- 部署环境应通过密钥管理或受限环境变量注入 API KEY，不复制本机 `.env.local`；
- API KEY 一旦出现在聊天、日志或其他非受控渠道，应在控制台轮换，不能只从文件中删除；本项目现有 KEY 已在聊天中出现，代码开发、固定样例和模拟测试可以先行，但任何真实 API 探针、真实浏览器联调及“真实链路通过”结论必须等待用户轮换 KEY 并将新值写入未提交的 `server/.env.local`。

### 11.3 模块级缓存和资源保护

缓存遵循和风天气[缓存你的数据](https://dev.qweather.com/docs/best-practices/cache/)建议，按数据时效分别设置，不能给聚合响应使用一个统一长 TTL。首期默认新鲜期为：

| 模块 | 首期服务端新鲜期 | 官方推荐区间 |
|---|---:|---:|
| 天气预警 | 5 分钟 | 5–20 分钟 |
| 实时天气 | 10 分钟 | 10–30 分钟 |
| 分钟级降水 | 5 分钟 | 5–10 分钟 |
| 逐小时天气预报 | 30 分钟 | 30–60 分钟 |
| APIHz 查询点地址 | 30 天 | 地址辅助数据，不跟随天气刷新 |

规则：

- 天气模块缓存键至少包含模块、舍入后的坐标、`lang`、`localTime` 和影响响应的产品参数；地址模块以未舍入天气点规范化后的经纬度单独建键，不与天气数据共用 TTL；
- 相同缓存键的并发请求合并，同一时间最多发起一个上游请求；
- 聚合响应逐模块判断新鲜度：未到期直接复用，到期模块才请求上游；
- 缓存记录上游数据时间、本站获取时间和到期时间，前端显示数据时间或缓存年龄；
- 跨小时和跨日时重新校验逐小时序列，不能因缓存导致首个时点已过期、日期错位或数据项减少后报错；
- 预警 5 分钟到期后重新获取，及时处理更新、取消和取代关系；
- 上游修正数据时允许下一次到期请求覆盖缓存；不得用长时间 stale 数据冒充成功更新；
- 缓存只覆盖用户实际查询过的天气点位和地址，不预抓取、不提取或批量存储 GeoAPI/地址数据；
- 提供仅限运维或本机管理使用的立即清空天气缓存能力；不得暴露无需保护的公网清缓存接口；
- 代理设置上游连接与响应超时，并限制压缩前网络体积和解压后的响应体大小；
- 日志只记录模块、耗时、HTTP 状态、本站请求 ID 和脱敏坐标，不记录认证材料和完整上游正文；
- 复用现有 `server/` 的资源保护、统一错误和请求 ID 机制，不另起不受保护的天气服务。

正式技术探针需结合账户额度、上游响应和真实更新频率复核上述默认值。调整时应维持分模块策略，并同步本需求和界面时效提示。

### 11.4 Gzip 处理

和风天气 Web API 默认使用 Gzip 压缩。代理遵循官方[处理 Gzip](https://dev.qweather.com/docs/best-practices/gzip/)说明：

- 上游客户端声明支持 Gzip；Node HTTP 客户端若默认自动协商并解压，可以沿用其标准行为，不重复手工解压；
- 若底层客户端返回压缩字节，必须根据 `Content-Encoding` 正确解压后再解析 JSON；
- 解压失败、压缩格式与响应头不一致或解压后超过大小上限时，按上游响应异常处理；
- 响应体大小保护同时覆盖网络接收字节和解压后字节，防止异常压缩包耗尽内存；
- 服务端向浏览器返回本站规范化 JSON 时，由现有 HTTP 层统一决定是否压缩，不透传上游 `Content-Encoding`。

## 12. 数据时间、单位与归因

- 调用常规天气接口时传 `localTime=true`、`lang=zh`；分钟级接口传 `lang=zh`；
- 前端以返回的 ISO 时间和偏移量解析，不通过字符串截断猜测时区；
- 查询对象位于浙江时，用户界面统一按北京时间显示，并保留跨日标识；
- 数值必须使用上游返回单位，本站只做明确、可测试的格式化；
- 湿度、降水概率和云量从 `[0,1]` 转为 `0–100%`，边界值和异常值需校验；
- `metadata.attributions` 和分钟级 `refer` 中要求共同展示的来源或许可信息必须在天气面板底部可见；
- 若来源要求链接，使用可访问链接，不省略必要归因；
- 上游 HTML 或富文本字段按纯文本或受控白名单渲染，禁止直接使用未净化的 `v-html`。

## 13. 真实 API 技术探针

适配器和模拟测试完成后、真实浏览器联调前，必须先轮换已暴露的和风 API KEY，再使用服务端未提交的新凭据做一次脱敏探针，确认：

- 当前账户的专属 API Host 和 `X-QW-Api-Key` 请求头认证能正常访问 4 个首期和风天气接口，且没有同时发送 JWT 或 `key` 查询参数；
- APIHz 地址接口通过本站代理访问，凭据不进入浏览器或日志；使用同一原始查询点按 `lon`、`lat` 顺序请求，并核对 `address`、`hctype`、`jd` 和失败结构；
- 浙江省级查询 11 个市代表点、市级查询直接区县代表点、县级只查询当前县代表点，乡村地块不产生预警请求；
- 各层级预警代表点以及当前天气、分钟降水和逐小时所用当前对象坐标的顺序与两位小数口径正确；
- 4 个和风天气接口及 1 个 APIHz 地址接口的 HTTP 状态、响应体大小和耗时；天气接口另核对时间字段和单位；
- 天气预警“有预警”和“无预警”结构；若测试时没有真实生效预警，使用脱敏固定样例覆盖 UI，不伪称真实覆盖；
- 分钟级降水的有数据、全零降水和无数据结构；未遇到的分支用固定样例测试并明确标注；
- 实时天气可选字段缺失情况；
- 逐小时是否稳定返回请求的 24 个时点，以及少于 24 个时点时的降级行为；
- 归因、许可、缓存和限流相关响应信息；
- 上游是否实际返回 Gzip、Node 客户端是否自动解压，以及压缩前后响应体大小保护；
- 四个模块的真实更新频率与 5/10/5/30 分钟默认新鲜期是否匹配；
- 上游错误、超时、限流和 API KEY 无效的实际错误形态，并验证 `429` 退避、`400/403` 停止重试。

探针报告只保存字段集合、计数、耗时范围、状态码和脱敏结论，不保存真实 API KEY、完整认证请求头、完整请求 URL、精确地块坐标或完整天气正文。探针结果与文档不一致时，先以真实响应修正适配器和本需求，再进入完整界面开发。

## 14. 可访问性与交互细节

- 面板打开后，键盘焦点进入标题或首个可操作控件；关闭后焦点返回“灾害风险”入口；
- 关闭、刷新、模块重试和预警展开均使用原生按钮并提供可访问名称；
- 加载和刷新状态使用 `aria-live` 的非打断式通知；生效严重预警首次加载完成时可使用更高优先级通知，但不得循环朗读；
- 预警等级、降水趋势和天气状态不得只靠颜色、图标或柱高表达；
- 横向逐小时区域支持键盘滚动和聚焦，不捕获页面全部方向键；
- 系统启用“减少动态效果”时，不使用持续天气动画或闪烁预警；
- 不使用天气背景动画、雨雪粒子或大面积动态渐变遮挡地图。

## 15. 验收标准

1. 当前行政上下文属于浙江省或省内市、县、乡、村、地块时，天气工具可点击并提供“气象预警”“实时天气”两项；存在未保存编辑时入口保持禁用并说明原因；天气与台风不能同时处于活动状态。
2. 浙江省外或无法确认浙江归属的上下文中，“查看天气”不可点击并提示“天气当前仅支持浙江省范围”；服务端收到省外行政代码、坐标不一致或任意经纬度请求时返回 `WEATHER_LOCATION_OUT_OF_ZHEJIANG`，且不请求上游。
3. 进入天气后保持当前行政层级、地图中心和缩放级别，不切回省级、不自动移动相机；退出后仍保留退出瞬间视角。
4. 当前打开省内地块时使用其内部标注点；否则按浙江省内当前行政面内部代表点查询实时、分钟降水和逐小时数据。地图平移不改变查询点，省内行政切换或地块切换会更新位置；预警遵循第 6 节独立层级规则。
5. 实时天气、分钟降水和逐小时在当前查询对象内使用同一组最多两位小数坐标；普通接口使用纬度/经度路径顺序，分钟级使用经度、纬度顺序；预警按当前行政层级分别查询直接子区域或当前县代表点。
6. 浏览器只调用本站 `/api/weather`，构建产物、浏览器网络请求、日志和错误中不出现和风天气 API KEY、项目 ID、凭据 ID 或完整认证头；服务端上游请求只通过 `X-QW-Api-Key` 请求头认证。
7. “气象预警”与“实时天气”全局互斥：预警模块显示右上天气头部/当前层级预警列表和预警标牌；实时天气模块显示默认点可点击骨架天气标记但不自动开浮窗，点击后位置浮窗按实时、分钟降水、未来 24 小时顺序展示。切换模块立即清除另一模块的面板、浮窗和地图标记；520px 以下浮窗近全宽，关键操作可达。
8. 省级查询 11 个地市代表点并在命中预警的市显示标牌；市级查询直接区县代表点并在命中预警的区县显示标牌；县级只查询当前县代表点并展示结果；乡、村、地块不发起预警查询。
9. 每条预警使用“左侧灾种图标 + 右侧中文灾种 + 底部中文颜色等级”的紧凑标牌；不显示英文灾种名；同一代表点多条预警必须按优先级水平并排，不合并或纵向堆叠。
10. 预警标牌使用 `alerts[].icon` 对应的本地 QWeather Icons 预警 SVG，未知图标使用通用预警图标；天气现象 `condition.code` 不得代替预警图标；仓库保留 MIT 许可声明。
11. 预警标牌只表示行政区域代表点命中，不填充整个行政面、不宣称全域覆盖；地图标牌展示事件和等级，右上列表展示地区及预警标牌，浮窗严格按第 6.7 节展示 8 项信息；只有成功空响应才能表述“代表点未查询到预警”，失败不得伪装成无预警。
12. 省、市、县三级右上天气容器常驻“当前层级预警地区”列表：省级按地市、市级按区县、县级仅当前县组织全部命中预警；空态、加载进度和失败地区均明确区分。乡、村和地块保留天气头部并显示“天气预警查看到县级”，不发起预警请求。
13. 点击列表具体预警或地图标牌只在对应代表点打开预警浮窗，不切换行政层级、不居中、不缩放；行政层级和视角切换只能继续使用现役边界点击、缩放阈值、面包屑和“回到上级”逻辑。
14. 预警浮窗采用“有色标题栏 + 白色可滚动正文 + 关闭按钮 + 代表点箭头”结构，严格只展示标题、发布时间、紧迫程度、严重程度、确定性、完整预警说明、完整触发标准、完整防御指南 8 项；可空字段为空时隐藏，不提供额外字段、“查看详细”或二级详情；浮窗不得为避让移动地图相机，同一时间只显示一条。
15. 实时天气在共用查询点常驻“天气现象图标 + 温度”标记；点击只打开单层完整浮窗，不下钻、不居中、不缩放；浮窗严格只展示天气现象、温度、体感温度、一小时降水量、降水强度、降水类型和湿度，不展示风、阵风、能见度、气压、露点、云量或紫外线指数，不设置“更多数据”或二级详情，缺失值显示 `--`。
16. 实时天气浮窗标题优先使用同一原始查询点经本站代理请求 APIHz 地址接口返回的 `address + 附近`，不显示最近地点、POI、道路、距离或方向；地址增强首轮实现但可选配置，未配置/许可未确认/失败时不阻断天气，默认点降级为当前行政对象代表点或当前地块查询点附近，Ctrl 临时点降级为“地图点选位置附近”；地址缓存 30 天，凭据不进入浏览器。
17. 实时天气模式下地图顶部中央常驻提示“Ctrl + 左键单击可以按点选查询天气”；按住 `Ctrl` 单击浙江省内地图位置，临时查询同一点的地址、实时天气、分钟降水和未来 24 小时预报，并自动打开单个临时标记及合并浮窗；普通点击维持原交互。再次点选替换旧临时点，关闭浮窗、按 Esc、切换行政/地块或退出天气时移除临时点；临时浮窗可见期间手动/自动刷新作用于临时点，关闭后恢复默认点；预警始终按当前行政层级刷新。
18. 分钟级降水不新增地图标记，接在实时天气浮窗下方；展示标题、上游摘要、更新时间、雨雪文字图例和全部实际时点的柱状趋势图；全零时保留零线和“未来两小时暂无降水”，无数据和失败必须与全零区分。
19. 未来 24 小时预报不新增地图标记，接在分钟降水下方；固定请求 `hours=24`，使用横向小时卡片展示全部实际时点，每张只显示时间、天气图标/文字、温度、降水概率和降水量；少于 24 个时点时说明数据不完整，不补点，不展示风或其他扩展指标。
20. 四个天气 API 的请求、缓存和状态彼此独立；APIHz 地址是辅助状态，失败只触发标题降级。单模块错误不得伪装成空数据或隐藏成功模块；头部显示“部分数据更新失败”，具体列表/浮窗提供模块级重试。实时天气失败时保留通用图标 + `--` 标记，仍可打开分钟降水和未来 24 小时。
