# 异常地块管理设计方案

> 版本：v1.0（设计稿）
>
> 日期：2026-08-21
>
> 状态：待开发
>
> 目标模块：村级地块、地块详情、管理后台、Node 服务端

## 1. 目标与范围

建立服务端异常地块数据库，由人工维护异常记录；地图标记异常地块，点击后展示地块基本信息和异常信息；提供独立的异常地块管理后台，用于查询、维护和跟踪异常状态。

本期仅记录人工确认的异常，不自动识别作物生长或面积异常，不修改原始地块 GeoJSON、保单或种植档案，也不将异常记录作为理赔、定损或承保结论。

### 1.1 本期包含

- 服务端异常地块数据存储与查询、新增、编辑、逻辑删除、状态更新接口。
- 地图异常样式和风险等级标记。
- 在现有地块详情中展示异常信息。
- 地图右上角“管理后台”入口和独立“异常地块管理”列表页。
- 查询区、数据列表、新增/编辑、状态更新和删除操作。

### 1.2 本期不包含

- 自动识别、批量导入导出、图片附件、审批流、通知、操作审计、登录和角色权限。
- 修改地块几何、自动裁剪、地块合并或拆分。

## 2. 数据模型与口径

异常记录独立保存于服务端私有数据目录，以 `parcelNo` 与现有地块关联；不得将异常字段写入前端公开目录或原始地块文件。

| 字段 | 字段名 | 规则 |
|---|---|---|
| 异常记录编号 | `id` | 服务端生成 UUID，唯一且不可编辑 |
| 地块编号 | `parcelNo` | 必填；必须能关联当前可访问地块 |
| 所属行政区域 | `adminRegion` | 必填；由关联地块回填，可人工修正 |
| 农作物 | `crop` | 必填；默认取当前种植档案 |
| 地块面积 | `areaMu` | 必填，单位亩，最多两位小数，必须大于 0 |
| 被保险人 | `insuredParty` | 可为空；沿用项目术语，不使用含混的“承保人” |
| 关联保单号 | `policyNo` | 可为空；有值时必须符合当前保单号格式 |
| 承保开始时间 | `coverageStart` | 可为空；有值时必须为合法日期 |
| 承保结束时间 | `coverageEnd` | 可为空；不得早于承保开始时间 |
| 异常类型 | `anomalyType` | 必填，使用固定枚举 |
| 风险等级 | `riskLevel` | 必填，使用固定枚举 |
| 异常创建时间 | `createdAt` | 必填，由新增时系统写入 |
| 异常状态 | `status` | 必填，使用固定枚举 |
| 异常说明 | `description` | 必填，最多 500 字 |
| 最后更新时间 | `updatedAt` | 服务端在每次写入时更新 |
| 删除标记 | `deletedAt` | 逻辑删除时写入；默认查询不返回 |

初始枚举：

- 异常类型：作物生长异常、地块面积异常、种植信息异常、承保信息异常、其他异常。
- 风险等级：高风险、中风险、低风险。
- 异常状态：待处置、处理中、已关闭。

同一地块可以存在多条异常记录。地图只汇总显示未关闭记录；同一地块有多条未关闭记录时，以最高风险等级标记，详情展示完整记录列表。

## 3. 业务流程

```text
管理人员进入管理后台
        ↓
查询已有异常 / 新增异常记录
        ↓
填写地块编号，系统回填可取得的地块和业务信息
        ↓
提交服务端校验并原子写入异常数据库
        ↓
地图加载未关闭异常摘要并标记对应地块
        ↓
用户点击异常地块
        ↓
地块详情展示基本信息、异常信息、种植档案和保单信息
        ↓
管理人员更新状态、编辑或逻辑删除异常记录
```

### 3.1 业务规则

1. 保存前必须校验地块编号、必填字段、日期范围和枚举值；地块不存在时拒绝写入。
2. 关联保单、被保险人、承保期间可从已有业务数据预填；地块无保单时允许留空。
3. “已关闭”记录保留在详情中，但不再默认显示地图异常标记。
4. 删除只执行逻辑删除；被删除记录不出现在默认列表或地图摘要中。
5. 管理后台保存失败时保留当前表单输入并显示明确错误；地图不展示未成功保存的临时数据。
6. 地块筛选、人工绘制和修形模式仅展示异常状态，不允许在地图上修改异常记录。

## 4. 地图和详情交互

### 4.1 地图标记

| 风险等级 | 表现 | 非颜色辅助 |
|---|---|---|
| 高风险 | 红色加粗边框、半透明填充 | `!` 异常标记 |
| 中风险 | 橙色加粗边框、半透明填充 | `!` 异常标记 |
| 低风险 | 黄色加粗边框、半透明填充 | `!` 异常标记 |

- 异常样式优先于普通地块样式，但不覆盖地块几何。
- 在种植情况、保险状态专题中保留异常边框和标记，避免被专题填色遮挡。
- 单一地块的多条未关闭异常以最高风险等级展示；悬停提示“异常 N 条 / 最高风险等级”。

### 4.2 地块详情

点击异常地块后，沿用现有地块详情抽屉，在基本信息后增加“异常信息”区块：

```text
地块详情
├─ 基本信息：地块编号、行政区域、农作物、地块面积、被保险人、保单号、承保期间
├─ 异常信息：异常类型、风险等级、异常状态、创建时间、异常说明、最后更新时间
├─ 种植档案
└─ 保单信息
```

异常记录排序：未关闭优先，随后按风险等级高→低、异常创建时间新→旧。无异常时不显示该区块。

## 5. 管理后台

### 5.1 页面与入口

- 地图右上角新增“管理后台”入口。
- 进入独立路由 `/admin/exceptions`，一级模块名称为“异常地块管理”。
- 返回地图时保留原行政定位和地图视角。

### 5.2 查询区

支持关键字（地块编号、被保险人、保单号）、市/县/乡镇/村、异常类型、风险等级、异常状态和异常创建时间范围的组合查询；提供“查询”和“重置”。

### 5.3 数据列表和操作

默认按异常创建时间倒序，字段为：地块编号、所属行政区域、农作物、面积（亩）、异常类型、风险等级、异常状态、创建时间、操作。

操作包括：查看详情、编辑、更新状态、删除。列表支持分页，风险等级和异常状态必须有文字标签，不能只用颜色表达。

### 5.4 新增和编辑表单

- 输入地块编号后，回填行政区域、作物、面积、被保险人、保单号和承保期间；回填值可编辑但保存时仍校验。
- 异常类型、风险等级和异常状态使用固定下拉选项。
- 编辑不得变更 `id`；变更地块编号时重新执行关联校验。

## 6. 服务端设计

在现有 Node 服务内新增异常地块模块，数据文件置于服务端私有数据目录。浏览器只能访问本站 `/api`，生产环境继续由同源反向代理转发，Node 服务不直接公开。

| 方法 | 接口 | 用途 |
|---|---|---|
| GET | `/api/exception-parcels` | 分页查询与筛选 |
| GET | `/api/exception-parcels/:id` | 单条详情 |
| POST | `/api/exception-parcels` | 新增记录 |
| PUT | `/api/exception-parcels/:id` | 编辑记录 |
| PATCH | `/api/exception-parcels/:id/status` | 更新异常状态 |
| DELETE | `/api/exception-parcels/:id` | 逻辑删除 |
| GET | `/api/exception-parcels/map` | 返回地图未关闭异常摘要 |

服务端必须执行参数白名单、分页边界、数据类型、枚举和日期关系校验；写入采用临时文件加原子替换，并对写操作串行化，避免并发覆盖或部分写入。错误沿用现有统一错误结构，不返回服务端文件路径或内部异常详情。

## 7. 验收标准

1. 可从地图右上角进入异常地块管理页，并返回原地图视角。
2. 管理页支持规定的组合查询、分页和重置。
3. 可新增、编辑、逻辑删除异常记录，并更新异常状态。
4. 地块不存在、必填项缺失、枚举非法或承保时间倒置时，服务端拒绝写入并返回明确提示。
5. 新增异常后，地图刷新可显示对应地块标记；关闭或删除后不再默认展示。
6. 同一地块有多条未关闭异常时，地图只显示最高风险等级，详情展示全部记录。
7. 点击异常地块时，详情字段与服务端保存数据一致。
8. 异常标记在种植和保险专题中清晰可见，不影响筛选和人工地块编辑。
9. 服务重启后异常数据仍可读取；损坏数据文件不得返回不完整结果。
10. 前端单元测试、服务端接口测试、地图交互端到端测试覆盖新增、编辑、关闭、删除与详情联动。

## 8. 待确认事项

1. 是否允许同一地块、同一异常类型存在多条未关闭记录。
2. 后续是否需要增加巡查人、图片附件、处置说明和关闭时间。
3. 生产环境上线前是否补充登录、角色权限和操作审计。
