## 测试边界（seams，需求定稿时冻结）

| 模块 | seam（公共接口/边界） | 说明 |
|------|----------------------|------|
| R1/R2/R3 数据 | `scripts/prepare-policy-confirmation.py` 的 `generate()`（输出 confirmation 结构）与 `scripts/generate-policy-fixture.py` 的 `generate()`（输出 fixture 结构）；`scripts/validate-*.py` | 测试断言落在确认产物与 fixture 的结构/指标上，不测内部聚类函数细节 |
| R4 前端 | 前端无改动；仅回归验证 `useParcelWorkbench` 的 `selectParcel`/`selectionStyle`（现有单测）与真实浏览器冒烟 | 前端测试不得新增 seam |

编码 agent 写测试时按此 seam 执行（配合 tdd 技能），不得另选 seam；验收 agent 核对测试是否按 seam 落地。

## 验证层级与证据标准约定

| 验证层级 | 证据标准 |
|----------|----------|
| [单测] | 测试命令 + 实际输出 |
| [数据脚本] | 命令 + 真实数据跑通输出 |
| [E2E-自动化] | 启动服务 + 浏览器/接口自动化操作 + 输出/截图 |
| [E2E-人工] | 验证人（用户或指定验收人）+ 操作步骤 + 观察结果 + 记录 + 确认 |

- 未执行不算通过；AI 无资格自称人工验证（AI 自跑 UI 点验只能算冒烟，不能算人工验证）
- 自动化优先：主观视觉/审美、真实渲染目视确认、真实交互体验、业务合理性判断、最终用户接受（UAT）才允许 [E2E-人工]
