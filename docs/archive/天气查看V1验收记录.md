## 1. 验收结论

天气查看 V1 的服务端可信空间索引、聚合代理、四个和风天气适配器、前端天气模式与地图交互、自动刷新、模块级失败处理、QWeather Icons 本地资源、固定响应浏览器回归和四个必需上游接口真实链路均已实现并通过验收。

真实 Chrome 关键联调确认：

- 浏览器只向同源本站 `/api/weather` 发起 1 次天气聚合请求；请求键仅有 `contextCode`、`contextLevel`、`target`；
- 浏览器未直接访问和风天气或 APIHz 主机；
- 位置浮窗显示实时天气、未来两小时分钟降水、未来 24 小时、归因和完整责任说明；
- 进入天气前后地图缩放均为 `Z 7.50`，地图 pane transform 相同；
- 页面错误和 Console error 均为 0。

可选 APIHz 地址增强未完成真实链路验收：本机没有配置 `APIHZ_ADDRESS_URL`，真实探针结果为 `notConfigured`。该情况符合首期可降级规则，浮窗标题使用行政对象、地块或地图点选位置文案，不阻断预警、实时、分钟降水和逐小时模块。

## 3. 脱敏真实探针

用户确认重新轮换本机和风天气与 APIHz 凭据后，执行第二次天气脱敏探针。`pnpm --dir server probe:weather` 退出码为 0，报告为本机 Git 忽略产物，不提交仓库。

| 模块 | 必需 | 结果 | HTTP/压缩 | 数据计数 |
|---|---:|---|---|---:|
| 生效天气预警 | 是 | success | 2xx、Gzip | 1 条 |
| 实时天气 | 是 | success | 2xx、Gzip | 1 组 |
| 未来 24 小时 | 是 | success | 2xx、Gzip | 24 个时点 |
| 未来两小时分钟降水 | 是 | success | 2xx、Gzip | 24 个时点 |
| APIHz 地址 | 否 | notConfigured | 未请求 | 0 |

探针还确认四个和风响应在配置的网络体积和解压后体积上限内；实时与逐小时单位字段、归因字段可被本站白名单适配器识别。报告没有保存精确点位、完整 URL、认证头、正文或原始响应。

为避免触发账户安全策略，没有故意制造真实 `400/403/429`。认证失败停止重试、共享 `Retry-After`/退避与恢复行为由固定 fixture 和服务端自动测试覆盖；这些结果不记为真实上游错误形态观测。

## 4. 固定响应真实 Chrome 回归

`pnpm --dir web test:e2e` 使用系统 Chrome、非敏感固定响应和本站 fixture 服务，7 项全部通过：

1. 进入/退出天气保持地图视角并恢复入口焦点；
2. 成功响应展示预警详情和完整位置天气，两个浮窗互斥；
3. 1280×720 浮窗完整位于视口，标题栏和关闭按钮可达；
4. 首次请求失败显示错误标记、失败浮窗和重试；
5. stale 模块保留成功数据并显示上次成功时间和重试；
6. `Ctrl + 左键单击` 只刷新临时位置，`Esc` 恢复默认标记且不改变层级；
7. 520px 视口部分失败时保留成功模块，重试/关闭可达。

固定响应 E2E 不访问和风天气、APIHz 或天地图，不替代第 3 节真实探针。

## 6. 残余风险与未观测项

1. `APIHZ_ADDRESS_URL` 未配置；地址正常、空值、超时和业务失败由 fixture 覆盖，但真实地址线路、许可与额度尚未验收。
2. 真实 `400/403/429` 未故意制造；对应控制流由固定测试覆盖，不宣称真实错误形态通过。
3. 脱敏探针是单点、单时刻证据；未批量抓取全省天气。省/市/县预警计划及乡/村/地块不请求预警由空间索引与服务端自动测试验证。
4. 天气上游数据、许可和账户配额可能变化；长期运行前应按现役需求重新评估 API KEY 认证向 JWT 的迁移。
