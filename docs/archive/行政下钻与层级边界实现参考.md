# 行政下钻与层级边界实现参考（五级下钻 + 边界数据链路）

> 状态：现役实现记录（2026-08 核对）
> 目的：给后续涉及"行政区划下钻 / 层级边界"的任务当操作参考，按此复现可保证层级树、边界文件、缩放行为与现役效果一致。
> 事实关系：用户可见行为与验收标准以[地图与地块需求](../requirements/需求文档.md)为准；本文档只记录"怎么实现出来的"。

---

## 0. 关键口径（改前先确认）

| 项 | 现值 |
|---|---|
| 层级链 | 省(330000) → 市(6位) → 县(6位) → 乡(12位) → 村(12位，终点) |
| 边界文件 | 每级按父级代码拆分，**村级不存全局文件**（乡级才请求 villages） |
| 缩放进入阈值 | 省 9.5 / 市 11.5 / 县 13.5 / 乡 15.5（放大进入下一级） |
| 缩放退出阈值 | 市 9.0 / 县 11.0 / 乡 13.0 / 村 15.0（缩小退回上级，差 0.5 防抖） |
| 全局最小缩放 | z = 3.5（行政/地块/灾害模式统一）；地块编辑模式固定 z = 15.25 |
| 边界样式 | 统一主题色 `#38bdf8`，线宽随层级递减 3 / 2.5 / 2 / 1.5 / 1.2 |
| 悬停高亮 | 黄色 `#facc15`，线宽 +1.5、填充透明度 0.2 |
| 动效 | Leaflet `flyToBounds` 1 秒；首次渲染瞬时贴合 |

> ⚠️ 修改阈值、路径、属性字段或几何口径会改变用户可见效果，必须同步需求文档并跑 `validate-data.py`。

## 1. 总体数据流

```text
01-行政区划/浙江四级边界加村点/33*-GeoJSON.zip（锐多宝：市/县/乡 3 层）
01-行政区划/浙江四级边界加村点/330000-浙江省-省界.geojson
01-行政区划/浙江村界数据/3浙江村界-备注省市县乡/浙江村界.shp（440MB，EPSG:4490）
   │  scripts/prepare-boundaries.py
   ▼
web/public/data/
  boundary/province.geojson                 ← 省界（1 要素）
  boundary/city/330000.geojson              ← 11 市
  boundary/county/{市代码}.geojson          ← 该市全部县
  boundary/township/{县代码}.geojson        ← 该县全部乡（质心空间归属修正后）
  villages/{乡镇码}.geojson                 ← 该乡全部村界
  manifest.json                             ← 五级层级树（只含 code+name）
   │  前端按需加载（进入某级只请求其子级文件）
   ▼
地图渲染（MapView.vue + mapNavigationController.ts + drilldown store）
```

- **前端不做跨级聚合**：进入省只加载市级文件，进入市加载县级文件……逐级按需。
- 产物全部在 `web/public/data/`；`boundary/` 约 28MB、`villages/` 约 293MB（不提交，见 AGENTS.md）。

## 2. 数据产物规范（效果一致的核心）

### 2.1 文件路径与内容

| 文件 | 内容 | 属性 |
|---|---|---|
| `boundary/province.geojson` | 浙江省界，1 要素 | `code`=`330000`，`name`=浙江省 |
| `boundary/city/330000.geojson` | 11 个地市 | `code`(6位 区划码)、`name` |
| `boundary/county/{市代码}.geojson` | 该市全部区县 | `code`(6位 县级码)、`name` |
| `boundary/township/{县代码}.geojson` | 该县全部乡镇 | `code`(12位)、`name` |
| `villages/{乡镇码}.geojson` | 该乡全部行政村界 | `code`(12位 村代码)、`name` |
| `manifest.json` | 层级树：`{province, cities:[{code,name,counties:[{code,name,townships:[{code,name}]}]}]}` | 只含 code+name，无几何 |

规则：

1. **坐标系**：EPSG:4326（WGS84）。源 SHP 为 CGCS2000（EPSG:4490），与天地图同源，偏差厘米级，**直接叠加不纠偏**。
2. **几何**：面几何必须有效（预处理已 `make_valid` + 圆整后复核）；坐标保留 6 位小数（≈0.1m）。
3. **属性剥离**：锐多宝源含冗余 `geom`（PostGIS WKB，约占文件一半体积）等字段，预处理只保留 `code` + `name`。
4. **村界按乡拆分**：`villages/{乡镇码}.geojson` 内每个 `code` 唯一（同一行政村多要素已溶解为单一可信边界）；只有 `12 位且末三位非 000` 的记录才是村级面（000 结尾是乡级/围垦面，排除）。
5. **村级无全局文件**：村为导航终点，不生成村→村的文件；进入乡级才请求该乡 villages 文件。

### 2.2 编码关联（重要，改前必读）

- 村码前缀 **≠ 乡镇码**：章镇镇乡镇码 `330604104000`，但其村码前缀是 `330604102`；村所属乡镇**必须从 villages 文件按 `code` 匹配**，禁止前缀推导。
- 乡→县 同样做过**质心空间归属修正**：县级是 2023 数据、乡级是 2020 数据，区划调整（撤销下城/江干、新设临平/钱塘/龙港）导致 41 个乡按 code 前缀归错县；预处理改为"乡质心落在哪个县就归哪个县"（射线式 `contains`），无命中的兜底按原前缀。
- 全市共 1379/1390 乡直接匹配编码（99.2%）；11 个中心城区街道在村界源中完全缺失（无村域），另有 27 个乡镇只有 000 尾记录，共 **38 个乡镇无 villages 文件**是预期行为（`validate-data.py` 按此校验）。

## 3. 预处理：`scripts/prepare-boundaries.py`

### 3.1 四级边界（zip → 层级拆分）

1. 省界：读 `330000-浙江省-省界.geojson`，`clean_feature`（键 `省级码`/`省`）。
2. 每个 `33*-GeoJSON.zip`：读 `市级/`、`县级/`、`乡镇/` 三个文件；市级用 `区划码`/`地名`，县级用 `县级码`/`县级`，乡级用 `code`/`name`。
3. **乡镇修正**：`township_corrections.py` 的按 zip 修正规则（脚本内 `scripts/data/weather-township-corrections-v1.json`），`verify_complete()` 强制逐要素处理完。
4. `clean_feature()`：提取 code/name → 剥离冗余属性 → 简化（市/县/乡 `2e-5` 度 ≈ 2m，`preserve_topology=True`）→ `normalize_polygonal_geometry`（`make_valid`、GeometryCollection 提面并 `unary_union`、坐标圆整后**再次校验**，最终必须是有效 Polygon/MultiPolygon）。
5. 乡→县归属：先按 `code[:6]` 命中县，再用县几何 `prep.contains(乡质心)` 修正错配；按目标县码拆分写入 `boundary/township/{县码}.geojson`。
6. 输出 `boundary/city/330000.geojson`（11 市）并构建 manifest 城市树。

### 3.2 村界（SHP → 按乡拆分）

1. 源：`3浙江村界-备注省市县乡/浙江村界.shp`（pyshp 读取，`encoding='gbk'`）+ objectid identity 记录（`utf-8`，用于逐条修正归属），记录数必须一致。
2. 修正：`village_corrections.py` 按 objectid 的逐条修正（`scripts/data/weather-village-corrections-v1.json`），跳过 `None`（剔除），`verify_complete()`。
3. 排除非村级面（`is_village_level_code`：12 位且末三位非 000）。
4. 简化到 `1e-5` 度 ≈ **1m 精度**（决策#15，村级肉眼无损）→ 修复圆整。
5. **按 code 溶解**：同一行政村多要素 `unary_union` 合并为单一可信边界；同一 code 不同 name 直接报错（不允许建立歧义节点）。
6. 按乡镇码拆分写 `villages/{乡镇码}.geojson`。全量处理约 2~5 分钟。

### 3.3 manifest 与幂等

- `main()`：只清理本脚本产物（`boundary/`、`villages/`、`manifest.json`、`weather/`），**不碰 rs.json / tiles**（跨脚本幂等）。
- `--boundary-only` 只重建四级边界跳过村界。
- 同时写天气私有空间索引（`weather_spatial_index.py` → `server` 私有目录），属于天气模块，下钻任务一般不涉及。

## 4. 前端下钻状态：`web/src/stores/drilldown.ts`

- `path: Crumb[]`（栈）；`Crumb = { level, code, name, geometry? }`；`current = path 末尾`。
- 导航动作全部异步且先过守卫：
  - `drill(crumb)`：push（点击子级 / 自动缩放下钻）
  - `back()`：pop（返回上级按钮）
  - `backTo(index)`：截断到指定层级（面包屑回跳）
  - `resetToProvince()`：回到省级
- **守卫**：`setNavigationGuard(guard)` 注册；有未保存地块/档案操作时拦截并弹自定义确认（"离开当前村"），确认后才允许导航。
- `childrenUrl(crumb)`：`province→/data/boundary/city/330000.geojson`、`city→county/{code}`、`county→township/{code}`、`township→villages/{code}`、`village→null`。
- `NEXT_LEVEL`：下一级映射；`LEVEL_WEIGHT`：线宽 3/2.5/2/1.5/1.2。

## 5. 地图导航控制器：`web/src/map/mapNavigationController.ts`

单一控制器持有三个图层：

| 图层 | 作用 | 交互 |
|---|---|---|
| `outlineLayer` | 当前区域轮廓（下钻时被点击要素的几何，虚线黄 `#facc15` 3px `6 4`） | 不响应 |
| `childLayer` | 当前层级的**子级边界** | 悬停加粗置顶 + tooltip 区域名；点击 → `onSelect(feature)` → `store.drill` |
| `imageryLayer` | 吉林一号高分影像瓦片（乡镇/村级与影像相交时） | 独立开关，opacity 0.7 |

- `renderChildren`：`bindTooltip(name, sticky)`；`mouseover` 换 hover 样式并 `bringToFront`；`mouseout` 用 `childLayer.resetStyle` 还原。
- `findChildAt(point, contains)`：**射线法**（`web/src/utils/geo.ts` 的 `pointInGeometry`，支持 Polygon 外环 + 孔排除）遍历子级找"中心点落在哪个区域"，供缩放下钻判定。
- `setImagery(info, opacity)`：`/tiles/rs/{z}/{x}/{y}.png`，`minZoom/maxZoom` 取自 `rs.json`，`zIndex: 3`。
- `clear()`：三图层全清（切级时由 MapView 调用）。

## 6. 缩放下钻：`MapView.vue onAutoLevel()`

触发时机：**仅 `zoomend`**，平移不触发（`map.on('zoomend')` 中先更新 `Z x.xx` 标签再调用）。

```ts
ENTER_ZOOM = { province: 9.5, city: 11.5, county: 13.5, township: 15.5 }  // 放大进入
EXIT_ZOOM  = { city: 9.0, county: 11.0, township: 13.0, village: 15.0 }   // 缩小退回
```

判定逻辑：

1. 前置：`autoLevelAllowed(parcelMode, suppressAutoZoom)` = 地块模式为 `idle` 且未抑制；地块筛选/绘制/修形期间**禁用自动进退**。
2. 放大分支：`z >= ENTER_ZOOM[当前级]` → 取地图中心点 → `findChildAt` 找中心点所在子级 → `store.drill`（`pendingNoFly = true`，自动切换**不重排视野**，只换边界与面包屑）；乡级继续递归进村级。中心点不在任何子级时不做任何事。
3. 缩小分支：**仅当 `z < lastZoom`（真正缩小）且 `z <= EXIT_ZOOM[当前级]`** → `store.back()`。"只按缩小触发"避免下钻后视野仍落在退出区（大区域/小视口 fitBounds 缩放过低）时被误退回上级。
4. 防抖：进入/退出阈值差 0.5 级（9.5/9.0 等）。

抑制机制 `suppressAutoZoom`：点击下钻/返回的 `flyToBounds` 程序化缩放**不触发**自动进退（程序化 zoomend 与 moveend 先后顺序不可靠，用 `map.once('moveend')` 关闭 + 1.5s 兜底超时）；乡村级低于影像 `minZoom` 的抬升同样抑制。

## 7. 视野与动效

| 场景 | 行为 |
|---|---|
| 首次渲染 | `map.fitBounds` 瞬时贴合省界（不播动画），`firstRender` 只此一次 |
| 点击下钻/返回 | `flyToBounds(bounds.pad(0.02), { duration: 1.0 })`（决策#4） |
| 自动缩放下钻 | `pendingNoFly=true`，不移动视野 |
| 初始视野 | `map.setView([29.5, 120.5], 7)`（防 flyTo 前无中心点） |
| 贴合后抬升 | 若 `flyToBounds` 目标缩放低于当前级"退出阈值"（大区域/小视口），自动抬升到 `EXIT_ZOOM + 0.25`，避免随后任意缩放被误判为退回上级 |

地图配置（`L.map` 选项）：

- `minZoom: 3.5`（全局下限，不得低于）、`maxZoom: 19`
- `zoomSnap: 0.25`：允许小数级缩放，`fitBounds` 才能精确贴合（整数级会被迫放松最多 1 级）
- `wheelPxPerZoomLevel: 120`：滚轮步幅放缓（默认 60 一次滚动跳 ~1.7 级导致瓦片爆发重载）
- `renderer: L.canvas({ padding: 0.5 })`：矢量边界/地块默认 Canvas 渲染，百余复杂多边形流畅

## 8. 底图与图层层级

底图（`web/src/api/tianditu.ts`）：

- 默认：天地图卫星影像 `img_w` + 影像注记 `cia_w`；可切换矢量 `vec_w` + `cva_w`。
- `maxNativeZoom: 18`（天地图瓦片最高 z18，z19 由 Leaflet 自动放大 z18 瓦片）、`keepBuffer: 3`（回退缩放不白屏）。
- Token 从 `web/.env.local` 的 `VITE_TIANDITU_TOKEN` 读取，**不提交**。

Pane 层级（从低到高，`MapView.vue onMounted`）：

| Pane | zIndex | 内容 |
|---|---|---|
| tilePane | 默认 | 天地图底图 |
| （影像瓦片） | 3（layer zIndex） | 高分影像，底图之上 |
| editDimmingPane | 350 | 地块编辑遮罩（pointer-events: none） |
| parcelPane | 400 | AI/人工地块 |
| parcelLabelPane | 440 | 地块亩数标签（不可点） |
| annotationPane | 450 | **天地图文字注记置顶**（高于影像、地块、边界；不可点） |

> 硬约束：天地图文字注记必须位于影像、地块和边界之上（annotationPane 450 即为此设计）。

## 9. 面包屑与缩放标签

- `Breadcrumb.vue`：左上角"返回上级"按钮（`store.back()`）+ 层级面包屑；中间层级可点击回跳（`store.backTo(i)`）；当前层高亮。
- 右下角 `Z x.xx` 标签：紧邻天地图版权标识，`zoomend` 后更新，`aria-live` 可读；行政面包屑不重复显示缩放信息。
- 未保存地块/档案时：返回、面包屑回跳、刷新、关闭页面前均守卫提示（`navigationGuard` + `beforeunload`）。

## 10. 数据链路校验：`scripts/validate-data.py`

模拟前端五级下钻逐级校验（退出码 0/1）：

1. 基础文件：manifest.json、rs.json、省界 1 要素、市级 11 要素。
2. 全链路：遍历 manifest，`county/{市}`、`township/{县}` 文件存在且**要素数与 manifest 一致**；`villages/{乡}` 存在；缺失数必须 = 38（11 中心城区街道 + 27 无村级面乡镇）。
3. 演示路径抽查：绍兴/上虞/上浦镇/章镇镇文件存在。
4. 影像覆盖村：bbox 相交粗筛，章镇 + 三界 = **17 村相交**（历史口径；现役有地块产物的是相交 >5% 的 **13 村**，见[地块实现参考](./地块实现参考.md)——两处口径不同是有意为之）。

改动边界数据或下钻逻辑后必跑：

```bash
python scripts/validate-data.py
python scripts/check-codes.py      # 编码归属专项校验
git diff --check
```

## 12. 已知坑与注意点（重犯概率高）

| 坑 | 对策 |
|---|---|
| 村码前缀 ≠ 乡镇码（章镇镇 `330604104000` vs 村前缀 `330604102`） | 村归属一律从 villages 文件按 code 匹配，禁止前缀推导 |
| 区划年代错配（2023 县 vs 2020 乡） | 乡→县用**质心空间归属**，无命中才兜底前缀 |
| 锐多宝 `cuncode` 大量重复不可靠 | 村代码一律以村界 SHP 的 `村代码` 为准 |
| 冗余 `geom` 属性占文件一半体积 | 预处理必须剥离，只留 code+name |
| 中心城区街道无村界文件 | 38 个乡镇无 villages 文件是**预期**，前端 404 静默按空处理 |
| 大区域/小视口 fitBounds 缩放过低 | 贴合后抬升到 `EXIT_ZOOM + 0.25` 并抑制自动退出 |
| 程序化缩放触发自动进退 | `suppressAutoZoom` + moveend 一次性关闭 + 超时兜底 |
| 验证脚本影像覆盖口径（17 相交）≠ 现役地块村数（13） | 校验脚本保留历史口径；涉及"有地块的村"时以 13 村为准 |
