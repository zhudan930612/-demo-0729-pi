## 2. 数据产物规范（效果一致的核心，改前必读）

每个村一个文件：`web/public/data/parcels/{12位村代码}.geojson`。

```jsonc
{
  "type": "FeatureCollection",
  "features": [
    {
      "type": "Feature",
      "properties": {
        "id": 1,             // 村内唯一，从 1 递增；导出顺序即排序
        "area_m2": 1234.56,  // 平方米，保留 2 位
        "area_mu": 1.85,     // 亩 = area_m2 / (2000/3)
        "label_lng": 120.8812345,  // 内部标注点经度（代表点，7 位）
        "label_lat": 29.7712345    // 内部标注点纬度
      },
      "geometry": { "type": "Polygon", "coordinates": [ ... ] }  // EPSG:4326 (WGS84)，无孔单 Polygon
    }
  ]
}
```

硬规则：

1. **坐标系**：EPSG:4326（WGS84），与天地图底图直接叠加，无需纠偏。
2. **几何**：无孔单 `Polygon`；MultiPolygon 必须拆成多个 feature。
3. **ID**：村内唯一、`1..N` 递增整数；前端 `parcelId()` 统一 `String(id)` 后使用。**已有村的 ID、顺序、几何任何时候不得改变**（隐藏记录 `localStorage` 与保单 fixture 都引用这些 ID）。
4. **面积字段**：`area_m2` / `area_mu` / 标注点必须齐全且有限；前端统计、面积标签、详情面板、保单覆盖全部依赖它们。
5. **展示编号（只展示，不存）**：
   - AI 地块：`DK-{12位村代码}-B-{原始ID}`（如 `DK-330604102014-B-67`）
   - 人工地块：`DK-{12位村代码}-M-{display_no}`（村内递增序号，删除后不复用）
   - 实现：`web/src/features/policy/parcelNumber.ts`（`formatParcelNumber`）；要求 12 位村代码，保留源 ID 原样保证单射。

## 3. AI 地块识别链路

### 3.1 环境与工具（已验证）

| 项 | 值 |
|---|---|
| 工具仓库 | 开源：<https://github.com/Lavreniuk/Delineate-Anything>（本机克隆 `C:/Users/zhudan/.cache/delineate-anything/`，仓库外离线工具，**不复制源码/权重入库**） |
| 模型权重 | `weights/DelineateAnythingv2.pt`（125MB） |
| 运行环境 | `C:/Users/zhudan/.conda/envs/delineate-anything/python.exe`（Python 3.11.15，ultralytics 8.3.148，rasterio 1.4.3，GDAL 3.13）——**本机默认 Python 3.14 缺依赖，必须用该 conda 环境** |
| 源影像 | `05-遥感数据/JL1KF02B05_PMS02_20250402113627_200366490_101_0012_001_L3C_PSH.tif`（0.5m、4 波段 UTM；模型读取真彩波段 `[3,2,1]`） |
| 推理耗时 | CPU 约 36 分钟/村（实测 2143~2369 秒） |

### 3.2 脚本：`scripts/prepare-parcel-pilot.py`

三个子命令，全部支持 `--village {村代码}`（默认 `330604102014` 龙江村，向后兼容）：

```bash
# ① 裁片：村界外扩 128m 裁剪源影像
python scripts/prepare-parcel-pilot.py prepare --village 330604102016

# ② 推理（不是本脚本，是 Delineate Anything）：batch yaml 里 include 裁片目录名
python delineate.py -b batch-xxx.yaml        # conda 环境，产出 delineated/{目录名}.gpkg

# ③ 导出：GPKG → 裁回村界 → 过滤面积 → 写前端 GeoJSON
python scripts/prepare-parcel-pilot.py export <模型输出.gpkg> --village 330604102016

# ④ 补面积（数据安全路径：只补字段，不改 ID/顺序/几何）
python scripts/prepare-parcel-pilot.py enrich --village 330604102016
```

路径派生规则（`paths_for()`，禁止硬编码单村）：

| 项 | 路径 |
|---|---|
| 裁片输入 | `05-遥感数据/parcel-pilot/{村代码}/images/{目录名}/` |
| 推理输出 | `05-遥感数据/parcel-pilot/{村代码}/delineated/{目录名}.gpkg` |
| 临时目录 | `05-遥感数据/parcel-pilot/{村代码}/temp/` |
| 前端产物 | `web/public/data/parcels/{村代码}.geojson` |
| 村几何 | 从 `web/public/data/villages/*.geojson` 按 `properties.code` 匹配（**村码前缀 ≠ 乡镇码，禁止前缀推导**） |
| 目录名 | 龙江村保留历史英文 `Longjiang`（兼容旧产物），其余村用**村代码**（避免中文路径与历史产物混淆） |

`export` 关键逻辑：

1. 用标准库 `sqlite3` 读 GeoPackage：GPKG BLOB（`GP` 头）→ 探测合法 WKB 起点 → `shapely.from_wkb`（**不依赖 fiona/GDAL**）。
2. `Transformer`（pyproj）把几何变换到 EPSG:4326；`always_xy=True`。
3. 与村界 `intersection` 裁回；Polygon 直取、MultiPolygon 拆开。
4. 面积用**源 CRS 投影下**计算（`transform_shape(to_source.transform, part).area`），过滤 `200㎡ ≤ area ≤ 10ha`。
5. ID 从 1 递增，写 `parcel_properties()`（代表点用 `shapely` 的 `representative_point()`，保证在面内）。

`enrich` 关键逻辑：用 `pyproj.Geod(ellps='WGS84')` 椭球面积补 `area_m2`；先写 `.geojson.tmp` 再原子替换，**不得改变地块数量、ID、顺序、几何**。

### 3.3 已踩过的坑（避免重犯）

| 坑 | 对策 |
|---|---|
| shapely 2.1 不再 re-export `Transformer` | 从 `pyproj` 导入 `Transformer` |
| fiona 在 Python 3.14 无 wheel 装不上 | `_read_gpkg_geometries()` 用标准库 `sqlite3` 直接解析 GPKG |
| Delineate Anything batch yaml 的 `include` 若为纯数字目录名（村代码）会被 YAML 解析成整数导致不匹配 | 加引号：`include: ["330604102016"]` |
| 中文村名目录与龙江 `Longjiang` 冲突产生重复裁片 | 龙江村保留 `Longjiang`，其余村统一用村代码目录名 |
| 脚本文件名带连字符（`prepare-parcel-pilot.py`）不能直接 `import` | 测试用 `importlib` 或 as 模块加载 |

### 3.4 批量多村操作步骤（新增村的完整流程）

1. 用 `prepare --village {code}` 生成裁片（每村数分钟）。
2. 建/追加 batch yaml，`include` 列出裁片目录名（纯数字加引号）。
3. conda 环境跑 `delineate.py -b`（可分批，每批独立 yaml + log）。
4. 逐个 `export` 导出 `web/public/data/parcels/{code}.geojson`。
5. `enrich` 校验面积字段齐全。
6. 记录每村地块数/总面积，供参保确认与保单造数使用（`prepare-policy-confirmation.py --village` 会校验"覆盖全部地块、参保比例 ≥90%"）。
7. 前端验证：进入该村，地块正常渲染、点击详情正常、统计数字正确。

## 4. 前端展示与交互

### 4.1 加载规则（`MapView.vue` render()）

- **AI 地块只在村级加载**，且与高分影像相交时才请求 `web/public/data/parcels/{村代码}.geojson`；请求失败静默 `null`（无影像村无地块）。
- 进入村级时同步做三件事：
  1. `readManualParcels(村代码)` 读本机人工地块；
  2. `loadHiddenParcelIds(村代码)` 读本机隐藏集合；
  3. `renderParcelLayer()` 渲染。
- 加载到 AI 地块后，用"AI ID + 人工 ID"的有效集合**清理隐藏记录中已失效的 ID**（防串村残留）。
- 渲染器：**Canvas 渲染器**（`L.canvas({ padding: 0.5 })`），百余复杂多边形时比默认 SVG 流畅一个量级。

### 4.2 图层结构（`web/src/map/parcelLayerController.ts`）

一次 `render()` 产出四类图层 + 两类面积标签层：

| 图层 | 内容 | 交互 |
|---|---|---|
| `parcelLayer` | AI 地块 | idle 点击选地块 / filter 点击切换隐藏恢复 |
| `manualParcelLayer` | 已保存人工地块 | idle 点击选地块 / filter 同 AI / batch 点击修形 |
| `pendingManualLayer` | 本批次待保存人工地块 | batch 点击修形 |
| `batchAreaLabelLayer` | 新增模式下的亩数标签 | 不可交互 |
| `parcelAreaLabelLayer` | 正常模式 z≥18.5 视野内亩数标签 | 不可交互 |

- 样式按 `getState()` 实时计算；隐藏集合作用于 AI 与人工两类的显示过滤。
- 面积标签在独立 `parcelLabelPane`（置顶、不挡点击），`zoomend`/`moveend` 时重算。

### 4.3 样式规范（`web/src/features/parcels/parcelStyles.ts`）

| 状态 | 颜色/线型 | 用途 |
|---|---|---|
| 正常（`PARCEL_STYLE`） | 浅蓝 `#93c5fd`/填充 `#60a5fa` 0.26 | 查看态 AI + 人工统一 |
| 编辑（`PARCEL_EDIT_STYLE`） | 青蓝 `#38bdf8`/`#0ea5e9` 0.13 | 筛选/新增模式高对比 |
| 悬停（`PARCEL_HOVER_STYLE`） | 白 `#f8fafc` 加粗 4 / 青 `#22d3ee` | hover |
| 待隐藏（`PARCEL_PENDING_HIDE_STYLE`） | 红橙 `#fb2c36`/`#f97316` | 筛选 |
| 已隐藏（`PARCEL_HIDDEN_STYLE`） | 黄 `#fde047`/`#facc15` 虚线 `8 4` | 筛选 + 新增模式（AI 地块用） |
| 待恢复（`PARCEL_PENDING_RESTORE_STYLE`） | 绿 `#22c55e`/`#16a34a` | 筛选 |
| 人工已保存（`MANUAL_PARCEL_STYLE`） | 紫 `#a855f7`/`#c084fc` | 新增查看态 |
| 人工草稿（`MANUAL_DRAFT_STYLE`） | 紫粉 `#e879f9`/`#c026d3` 虚线 | 绘制中折线/修形 |
| 人工待保存（`MANUAL_PENDING_STYLE`） | 紫粉虚线 | 本批次新地块 |

规则：正常查看态**不区分 AI 与人工来源**（统一浅蓝）；新增模式下已隐藏 AI 用黄虚线、已隐藏人工仍用紫实线；待保存新地块用紫虚线且**不计入正式统计**。

### 4.4 隐藏/筛选（`parcelFilterState.ts` + `parcelHiddenStorage.ts`）

- 状态机：`hiddenIds`（已隐藏）/ `pendingHideIds`（待隐藏）/ `pendingRestoreIds`（待恢复）；点击切换，保存时 `next = hidden + pendingHide - pendingRestore`。
- 存储：`localStorage` 键 `agri-map:parcel-edits:v1`，结构 `{version:1, villages:{村代码:{datasetVersion:'2025-04-02-v1', hiddenIds:[...]}}}`；`datasetVersion` 不匹配即按空处理（**数据集更新后旧隐藏记录失效是预期行为**）。
- 保存失败保留本轮选择，取消不修改已有记录；"全部恢复"只是批量标记待恢复，仍需点"保存更改"。
- 隐藏只影响显示，不修改原始 GeoJSON、不上传服务器。

### 4.5 统计与图示（`ParcelStatusCard.vue`）

- 正常查看态 + 地块图层开启：左下角紧凑卡片显示"当前地块 / 合计面积"（只统计**未隐藏 AI + 已保存人工**，不含草稿/待保存；人工面积缺失时回退 `area_mu`）。
- 新增/筛选模式：同位置换成两列图示说明（颜色/虚实必须与地图一致）；影像说明只在正常态合入统计卡片底部。

## 5. 人工地块（任意村可画）

### 5.1 存储（`web/src/utils/manualParcelStorage.ts`）

- 键：`agri-map:manual-parcels:v1`（notice 提示键 `agri-map:manual-parcels:notice:v1`）。
- 结构：`{version:1, villages:{村代码:[feature,...]}, next_display_no:{村代码:number}}`。
- 属性：`id`（`manual-{uuid}`，跨村全局唯一）、`village_code`、`source:'manual'`、`area_m2`、`area_mu`、`label_lng`、`label_lat`、`created_at`、`updated_at`、`display_no`（村内展示序号）。
- 读取时校验每个 feature（`isManualFeature`）：单 Polygon、外环闭合、`prepareManualGeometry` 通过、字段齐全；无效记录跳过并提示；`display_no` 缺失自动补号，`next_display_no` 单调递增**永不复用**。
- 版本不兼容/读取失败时**停止写入保护原记录**（返回错误提示，不覆盖）。

### 5.2 几何校验（`web/src/utils/parcelGeometry.ts`）

- `normalizeOuterRing`：去连续重复点、去首尾闭合重复、重新闭合外环。
- `prepareManualGeometry` 阻断错误（**禁止加入待保存**）：无效坐标、`<3` 个不同顶点、自相交（turf `kinks`）、面积 `≤ 0.01㎡`（turf `area`）。
- `inspectManualGeometry` 警告（**不阻断，用户确认后可继续**）：与已有地块/同批待保存地块重叠数（turf `intersect`）、越村界（turf `booleanWithin`）、校验失败项数。
- V1 只接受**无孔单 Polygon**：不含切割、合并、挖洞、吸附、自动裁剪、AI 几何修改、导入导出、后端同步。

### 5.3 交互与模式

- 模式：`idle`（查看）/ `filter`（筛选）/ `batch`（新增查看态）/ `drawing`（绘制）/ `editing`（单地块修形）。
- 入口：右下角"地块工具"图标 → 浮窗"新增地块 / 筛选地块"（无可筛选地块时筛选置灰）；两个模式互斥。
- 绘制：查看态按 `N` 或点"绘制"进入；点击加顶点；≥3 个不同顶点后点首点或再按 `N` 闭合；`N` 在 1~2 顶点时提示不足。`Esc` = 取消整批。
- 撤销：优先删开放草稿最后一点，无草稿时删最近闭合待保存地块；`Ctrl/Cmd+Z` 同行为。
- 修形：batch 态点击已保存/待保存地块 → 顶点可拖动，实时重算面积与标注点；选中后地块下方显示"移除"，`Delete` 等价。
- 缩放约束：进入筛选/绘制/修形时视角不动，`map.setMinZoom(15.25)`，禁止自动退回上级；退出恢复默认规则。

### 5.4 保存语义

- **批量保存**（`saveManualBatch`）：新增 + 历史修形 + 移除一次性 `commitManualBatch` 后写 `localStorage`；未闭合草稿阻止保存；失败整批保留不部分生效；保存后清理该批已移除 ID 的隐藏记录与关联种植档案。
- 保存成功才更新正式数量/面积/图层并退出模式；`display_no` 与 `next_display_no` 一并持久化。
- 首次进入新增模式弹出一次性提示"仅保存在当前浏览器"。

## 6. 业务下游（依赖地块的模块，改动地块前注意）

- 参保确认：`scripts/prepare-policy-confirmation.py --village` 读 `web/public/data/parcels/{村代码}.geojson`，要求覆盖全部地块、唯一、参保比例 ≥90%；非龙江村未参保用确定性规则（`id % 17 == 0`，约 5.9% 未参保），**龙江村确认文件受保护不重新生成**。
- 保单/种植档案造数：`scripts/generate-policy-fixture.py --village`，按村输出 `web/src/data/policy-{村代码}.json` 等。
- 详情面板编号依赖 `formatParcelNumber`；**人工地块不关联保单**（详情显示无保单空状态）。

## 7. 硬约束与数据安全

- AI 地块 GeoJSON、裁片、GPKG、影像瓦片**不得公开分发**（私有仓库内可用）；不得描述为确权/承保/测绘成果。
- 重新导出或补面积前**备份当前前端 GeoJSON 与模型 GPKG**，记录文件大小、SHA-256 与恢复说明；补面积不得改变地块数量/ID/顺序/几何。
- 不提交 `web/public/data/`、`web/public/tiles/`、`05-遥感数据/` 派生产物。
- 村是导航终点；不得用村点生成伪村界；不复制 Delineate Anything 源码/环境/权重入库。
