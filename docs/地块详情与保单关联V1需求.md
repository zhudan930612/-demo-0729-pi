# 地块详情、业务标注与保单关联 V1 需求

> 版本：v1.0（2026-07-31）
>
> 状态：核心业务关系已确认，交互与数据细节待定稿
>
> 适用范围：浙江农业保险地图 Demo 村级地块页面
>
> 关联文档：[需求文档.md](./需求文档.md)

## 1. 背景与目标

当前村级地图已经支持普通地块展示、人工新增、修形、隐藏与恢复，但用户只能看到地块几何和面积，缺少农业保险业务信息。

本期目标是在不改变原始地块 GeoJSON、不上传真实业务数据的前提下，增加：

1. 地块详情查看。
2. 当前浏览器内的业务标注。
3. 只读的合成保单及投保清单信息。
4. 保单、被保险人汇总项和地块之间的地图联动。

本期仍为内部 Demo。地块、保单、投保清单和理赔信息均不得描述为真实确权、承保、测绘或理赔结论。

## 2. 核心术语

| 术语 | 定义 |
|---|---|
| 地块 | 地图上的普通地块或已保存人工地块 |
| 投保人 | 在保单层面提出投保申请的个人或组织 |
| 被保险人 | 其种植风险受保单保障的个人或经营主体 |
| 单一被保险人保单 | 一张保单只有一个被保险人，可承保一个或多个地块 |
| 分户清单保单 | 一张保单对应一张投保清单，清单包含多个被保险人汇总项 |
| 清单汇总项 | 投保清单中的一行，代表一个被保险人的承保汇总，可关联一个或多个地块 |
| 地块承保明细 | 地块与保单或清单汇总项之间的关联，记录该地块在本次保险中的承保面积 |
| 业务标注 | 用户在当前浏览器为地块填写的作物、核查状态和备注等信息 |

“个人保单 / 团体保单”不作为本期类型名称，因为单一被保险人也可能是家庭农场、合作社或企业。本期统一使用“单一被保险人 / 分户清单承保”。

## 3. 已确认的业务关系

### 3.1 单一被保险人保单

一张保单只有一个被保险人，可关联一个或多个地块：

```text
保单
├── 投保人
├── 被保险人（唯一）
└── 地块承保明细（1..N）
    └── 地块
```

约束：

- 同一保单下所有承保地块属于同一个被保险人。
- 当前地块只展示其自身承保面积，同时可查看该保单关联的其他地块。
- 被保险人可以是合成农户、家庭农场、合作社或企业。

### 3.2 分户清单保单

一张保单对应且仅对应一张投保清单。投保人通常是村集体、合作社或其他组织；投保清单包含多个被保险人汇总项：

```text
保单
├── 投保人
└── 投保清单（唯一）
    ├── 清单汇总项 A（被保险人 A）
    │   └── 地块承保明细（1..N）
    ├── 清单汇总项 B（被保险人 B）
    │   └── 地块承保明细（1..N）
    └── 清单汇总项 C（被保险人 C）
        └── 地块承保明细（1..N）
```

约束：

- **投保清单每行是一个被保险人的承保汇总，不是“一个被保险人 × 一个地块”的明细行。**
- 每个清单汇总项只对应一个被保险人。
- 每个清单汇总项可关联一个或多个地块。
- 地块先关联到具体清单汇总项，再通过清单汇总项关联到保单。
- 同一被保险人的多块地不得复制成多行清单项。
- 保单汇总由全部有效清单汇总项计算。

### 3.3 地块与历史保单

- 一个地块允许关联不同年度或不同保险期间的多张保单。
- 详情中优先展示当前有效保单，历史已到期保单单独分组。
- 同一保险期间是否允许同一地块重复承保不在 V1 内处理；合成数据不得制造无法解释的重复承保。

## 4. 用户界面与交互

### 4.1 地块选择

仅在正常查看态支持地块详情：

- 点击可见普通地块或已保存人工地块，选中该地块并打开右侧详情面板。
- 选中地块使用明确的主高亮样式。
- 点击地图空白关闭详情并清除高亮。
- 进入新增、绘制、修形或筛选模式时关闭详情，且这些模式下点击地块不打开详情。
- 地块被隐藏或人工地块被删除时关闭对应详情。
- 切换村、返回上级或通过面包屑跳转时关闭详情并清除保单高亮。

### 4.2 详情面板结构

右侧详情面板分为三个区块：

1. 地块信息。
2. 业务标注。
3. 关联保单。

面板在常见桌面宽度下不得遮住主要地块；窄屏方案在 UI 设计阶段确定，但不得产生页面横向滚动。

### 4.3 地块信息

展示：

- 地块编号。
- 地块来源：基础地块 / 人工新增。
- 地块面积：平方米、亩。
- 所属省、市、县、乡、村。
- 人工地块创建时间和更新时间，仅人工地块显示。
- 固定免责声明：“演示地块，不作为确权、测绘或承保依据”。

### 4.4 业务标注

普通地块和人工地块均可编辑以下字段：

- 地块名称。
- 作物类型。
- 种植年度或季节。
- 核查状态：未核查 / 已核查 / 需关注。
- 备注。

保存规则：

- 使用新的独立 `localStorage` 数据，不修改原始地块 GeoJSON。
- 按村代码和地块 ID 隔离。
- “保存”和“取消”分开；取消不覆盖已保存内容。
- 有未保存修改时，关闭面板、切换地块或离开当前村，使用项目内自定义弹窗确认。
- 删除人工地块时同步删除其业务标注，避免孤立记录。
- 清理浏览器数据后业务标注不可恢复，首次使用时应明确提示。

### 4.5 关联保单空状态

地块没有关联保单时显示：

```text
暂无关联保单
当前地块尚未纳入演示承保清单。
```

人工新增地块默认没有关联保单。

## 5. 保单信息展示

### 5.1 保单基本信息

两类保单共同展示：

- 保单号，使用合成演示编号。
- 承保机构。
- 保险产品或险种。
- 保单类型：单一被保险人 / 分户清单承保。
- 保单状态：待生效 / 保障中 / 已到期 / 已退保。
- 保险期间。
- 投保人合成名称及主体类型。
- 总承保地块数。
- 总承保面积。
- 每亩保险金额。
- 总保险金额。
- 保险费率。
- 总保费。
- 财政补贴金额。
- 投保主体或被保险人自缴金额。

### 5.2 单一被保险人保单展示

除保单基本信息外，展示：

- 唯一被保险人合成名称、演示编号和主体类型。
- 当前地块承保面积。
- 当前地块保险金额。
- 该保单关联地块数量及总承保面积。
- “查看该保单全部地块”操作。

### 5.3 分户清单保单的当前地块展示

点击清单型保单关联地块时，默认先展示与当前地块直接相关的清单汇总项，而不是展开整张清单：

- 当前清单项编号。
- 被保险人合成名称、演示编号和主体类型。
- 当前地块承保面积。
- 当前地块保险金额。
- 该被保险人关联地块数量。
- 该被保险人总承保面积。
- 该被保险人总保险金额。
- 该被保险人总保费。
- 财政补贴金额。
- 被保险人自缴保费。
- 清单项状态：正常 / 退保 / 批改。

提供：

- “查看该被保险人全部地块”。
- “查看完整投保清单”。
- “查看整张保单覆盖范围”。

### 5.4 完整投保清单

完整投保清单采用详情面板二级页面或独立抽屉展示，具体容器由 UI 设计确定。

每行展示一个被保险人汇总项：

| 字段 | 说明 |
|---|---|
| 序号 | 清单内序号 |
| 清单项编号 | Demo 内稳定唯一编号 |
| 被保险人 | 合成名称，并明确标注为演示数据 |
| 主体类型 | 农户 / 家庭农场 / 合作社 / 企业 |
| 所属村 | 行政区名称 |
| 地块数 | 当前清单项关联地块数量 |
| 承保面积 | 当前被保险人的汇总承保面积 |
| 保险金额 | 当前被保险人的汇总保险金额 |
| 总保费 | 当前被保险人的汇总保费 |
| 财政补贴 | 当前被保险人对应的补贴金额 |
| 自缴保费 | 当前被保险人的自缴金额 |
| 状态 | 正常 / 退保 / 批改 |

清单顶部展示总户数、总地块数、总面积、总保额和总保费。V1 可按合成名称或演示编号搜索，点击某行可查看该被保险人关联地块。

## 6. 地图联动规则

### 6.1 单一被保险人保单

- 当前地块使用主高亮。
- 点击“查看该保单全部地块”后，同一保单在当前村内的其他地块使用次级高亮。
- 面板显示“该保单覆盖 N 块，共 X.XX 亩”。

### 6.2 分户清单保单

高亮分三级：

1. 当前地块：主高亮。
2. 当前清单汇总项中同一被保险人的其他地块：次级高亮。
3. 用户主动选择“查看整张保单覆盖范围”后，同一保单其他清单项的地块：更弱的第三层高亮。

默认只高亮当前地块和当前被保险人的关联地块，不把同一保单下所有被保险人的地块混为同一组。

通用规则：

- 只高亮当前村内可展示的关联地块。
- 关闭详情、切换保单、切换清单项、切村或进入地块操作模式时清除对应高亮。
- 已隐藏地块不因保单联动而重新显示。

## 7. 金额与面积计算规则

### 7.1 地块承保明细

地块物理面积与承保面积是两个概念：

- 地块面积来自地块几何。
- 地块承保面积来自保单承保明细。
- 合成数据中地块承保面积必须大于 0，且原则上不得超过地块面积。

### 7.2 清单汇总项

```text
清单项承保面积
= 该清单项全部有效地块承保面积之和

清单项保险金额
= 清单项承保面积 × 每亩保险金额

清单项总保费
= 清单项保险金额 × 保险费率

清单项总保费
= 财政补贴金额 + 被保险人自缴金额
```

清单汇总项是计算结果，不得通过复制地块行再人工填写一个不一致的合计。

### 7.3 保单汇总

单一被保险人保单：

```text
保单总地块数 = 有效地块承保明细去重数量
保单总承保面积 = 有效地块承保面积之和
```

分户清单保单：

```text
保单总户数 = 有效清单汇总项数量
保单总地块数 = 全部有效清单项关联地块去重数量
保单总承保面积 = 全部有效清单项承保面积之和
保单总保险金额 = 全部有效清单项保险金额之和
保单总保费 = 全部有效清单项总保费之和
保单财政补贴 = 全部有效清单项财政补贴之和
保单自缴金额 = 全部有效清单项自缴金额之和
```

展示金额统一按人民币格式化。计算精度、四舍五入顺序应全局一致，并由自动校验保证保单总计与明细汇总一致。

## 8. 理赔摘要

保单详情可展示只读理赔摘要：

- 是否出险。
- 报案次数。
- 最近一次报案时间。
- 理赔状态：未报案 / 查勘中 / 核赔中 / 已结案。
- 估损金额。
- 已赔金额。

无理赔记录时只显示“保障期内暂无报案”，不展示一排零值。

V1 不实现报案、查勘、核赔或赔款编辑流程。

## 9. 数据模型要求

保单类型必须显式保存，不能通过是否存在清单临时推断：

```ts
type PolicyInsuredMode = 'single_insured' | 'insured_roster'
```

建议的逻辑实体：

```text
Policy                 保单
Party                  投保人或被保险人合成主体
EnrollmentList         投保清单；清单型保单一对一
EnrollmentItem         被保险人汇总项；投保清单一对多
ParcelCoverage         地块承保明细
ParcelAnnotation       地块业务标注
ClaimSummary           只读理赔摘要
```

关键引用：

- `Policy.insuredMode` 明确保单类型。
- 单一被保险人保单引用唯一 `insuredPartyId`。
- 分户清单保单引用唯一 `enrollmentListId`。
- `EnrollmentItem` 引用唯一 `insuredPartyId`。
- `ParcelCoverage` 必须引用 `policyId` 和 `parcelId`。
- 清单型 `ParcelCoverage` 还必须引用 `enrollmentItemId`。
- 普通地块和人工地块均使用稳定地块 ID 关联。
- 人工地块删除时同步清理业务标注；合成保单默认不关联用户后来新增的人工地块。

## 10. 合成数据与隐私边界

### 10.1 数据要求

- 保单、投保清单、被保险人、理赔信息全部使用固定合成演示数据。
- 使用明显的演示保单号和演示主体编号。
- 合成名称旁显示“演示”或“合成”标识。
- 数据逻辑必须自洽，经得起面积、保额、保费和补贴的加总校验。
- 不上传服务器，不接真实核心业务系统。
- 不修改普通地块 GeoJSON 或人工地块现有存储结构。

### 10.2 禁止进入 Demo 的信息

即使参考投保清单包含以下字段，本期也不得录入、复制或展示：

- 真实姓名。
- 身份证号或其他证件号。
- 手机号码。
- 银行卡号或银行账号。
- 开户行。
- 手写签名。
- 真实保单号。
- 任何能反向识别截图中人员的信息。

截图只能用于理解“每行是一个被保险人汇总项”的表格结构，不能作为演示数据来源。

## 11. V1 演示数据最小覆盖

至少准备以下场景：

1. 单一被保险人、单地块、保障中。
2. 单一被保险人、多地块、已到期或保障中。
3. 分户清单承保、多被保险人，每个汇总项关联 1～5 个地块。
4. 至少一个清单汇总项关联多个地块。
5. 至少一个地块同时存在当前有效保单和历史已到期保单。
6. 至少一个有保单地块具有理赔摘要。
7. 至少一个地块没有关联保单。
8. 人工新增地块默认没有关联保单。

建议首批使用 4 张合成保单，其中 2 张单一被保险人保单、2 张分户清单保单；具体主体名称、险种和金额在数据设计阶段确定。

## 12. 不在 V1 范围

- 编辑、创建、删除或审核保单。
- 编辑投保清单、清单汇总项或地块承保面积。
- 将人工新增地块关联到保单。
- 批单、续保、退保审批和重复投保校验流程。
- 真实投保人、被保险人或银行信息。
- 后端同步、多人协作、权限管理和审计日志。
- 报案、查勘、核赔和赔付操作。
- 修改普通地块几何。
- 给全部 1,533 个地块随机生成保单。

## 13. 验收标准

1. 正常查看态点击普通地块或人工地块可打开详情；新增、绘制和筛选模式不打开详情。
2. 地块信息正确显示编号、来源、面积、行政区和免责声明。
3. 普通地块与人工地块均可保存业务标注；取消不污染已保存数据，刷新后结果保持。
4. 有未保存业务标注时切换地块、关闭面板或离开当前村，会显示项目内自定义确认弹窗。
5. 删除人工地块后，其业务标注不存在孤立记录。
6. 无保单地块显示明确空状态，人工新增地块默认无保单。
7. 单一被保险人保单始终只有一个被保险人，可正确关联并高亮一个或多个地块。
8. 分户清单保单始终只有一张投保清单；清单每行是一个被保险人汇总项，而不是地块明细。
9. 一个清单汇总项可关联多个地块；点击其中任一地块均能定位到同一个汇总项。
10. 清单型保单默认只高亮当前地块及同一被保险人的地块；主动查看整张保单后才显示其他汇总项地块。
11. 当前地块、同一清单项地块和同一保单其他地块的三层高亮可明确区分。
12. 关闭详情、切换村、隐藏地块或进入地块操作模式后，详情和保单高亮被正确清除。
13. 清单汇总项面积等于其有效地块承保面积之和；保险金额、总保费、补贴和自缴金额满足计算公式。
14. 保单总户数、总地块数、面积、保额和保费与清单汇总一致，无重复计算。
15. 同一地块的当前有效保单和历史保单分组正确，状态和保险期间清晰。
16. 有理赔记录时摘要正确；无理赔时只显示“保障期内暂无报案”。
17. 完整投保清单可查看汇总、搜索合成名称或演示编号，并可从清单项联动查看该户地块。
18. 页面和数据中不出现真实姓名、身份证、电话、银行卡、开户行、签名或真实保单号。
19. 合成数据明确标识，不把演示地块描述为真实确权、承保、测绘或理赔成果。
20. 原始地块 GeoJSON、现有隐藏地块存储和人工地块存储格式不被改变。

## 14. 开发前待定项

以下事项不改变上述业务模型，但应在开发计划阶段明确：
