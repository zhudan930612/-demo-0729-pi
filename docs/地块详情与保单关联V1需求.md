# 地块详情、种植档案与保单关联 V1 需求

> 版本：v2.0（2026-07-31）
>
> 状态：业务规则与信息架构已定稿，待制定实施计划
>
> 适用范围：浙江农业保险地图 Demo 村级地块页面
>
> 关联文档：[需求文档.md](./需求文档.md)

## 1. 背景与目标

当前村级地图已经支持普通地块展示、人工新增、修形、隐藏与恢复。V1 在不修改原始地块 GeoJSON、不接入真实核心业务系统的前提下，增加：

1. 地块详情查看。
2. 当前浏览器内的多年度、多季节种植档案。
3. 固定只读的保单、投保清单与理赔摘要。
4. 地块、被保险人汇总项和保单之间的地图联动。
5. 符合 50 亩承保分类规则和空间经营合理性的固定业务数据。

产品展示目标是证明平台已经具备完整的农业保险业务展示能力。业务界面不得出现“演示数据”“合成数据”“虚构示例”等削弱平台完成度的标识。

仓库内部仍须遵守数据安全边界：不得从参考资料复制真实姓名、证件、电话、银行账号、签名或真实保单号；固定业务数据不得包含可识别真实个人的信息。

## 2. 业务基准

| 项目 | V1 口径 |
|---|---|
| 固定业务日期 | `2025-07-15` |
| 当前保险期间 | `2025-05-01` 至 `2025-11-30` |
| 历史保险期间 | `2024-05-01` 至 `2024-11-30` |
| 保险产品 | 水稻完全成本保险 |
| 保险标的 | 水稻；一张保单只承保一种标的 |
| 单位保险金额 | 1,250 元/亩 |
| 保险费率 | 3.2% |
| 总保费 | 40 元/亩 |
| 财政补贴比例 | 80%，即 32 元/亩 |
| 被保险人自缴比例 | 20%，即 8 元/亩 |
| 保单地域范围 | 一张保单只覆盖一个村 |
| 承保机构 | 业务界面不显示机构名称、Logo 或占位信息，保持平台机构中立 |

保单状态根据固定业务日期和保险期间计算，只包含：

- 待生效。
- 保障中。
- 已到期。

状态不得与保险期间矛盾，也不得依赖浏览器当天日期变化。

## 3. 核心术语与实体

| 术语 | 定义 |
|---|---|
| 地块 | 地图上的普通基础地块或已保存人工地块 |
| 地块几何面积 | 由地块几何计算的物理面积 |
| 地块承保明细 | 地块在某张保单中的承保关系，记录该地块本次承保面积 |
| 投保人 | 在保单层面提出投保申请的自然人或组织 |
| 被保险人 | 其种植风险受保单保障的自然人或经营主体 |
| 单一被保险人保单 | 一张保单只有一个被保险人，可承保该被保险人的一个或多个地块 |
| 分户清单保单 | 同村、同年度、同产品和期间内，为符合清单条件的多个被保险人统一生成的一张保单 |
| 投保清单 | 分户清单保单唯一对应的清单 |
| 清单汇总项 | 投保清单中的一行，代表一个被保险人的承保汇总，可关联一个或多个地块 |
| 种植档案 | 地块按年度和季节保存的作物、品种、核查状态及备注 |
| 理赔摘要 | 保单级和被保险人级的只读理赔汇总，不包含逐笔报案或受损地块明细 |

主体类型仅包含：

- 自然人。
- 家庭农场。
- 合作社。
- 村集体。

“个人保单 / 团体保单”不作为类型名称。V1 使用“单一被保险人 / 分户清单承保”，描述实际数据关系。

## 4. 50 亩承保分类规则

### 4.1 汇总范围

分类单位是被保险人，不是单个地块。对同一被保险人在以下范围内的全部参保地块先汇总承保面积：

- 同一村。
- 同一年度。
- 同一保险产品。
- 同一保险期间。

### 4.2 分类阈值

```text
被保险人汇总承保面积 ≤ 50.00 亩
→ 作为一行进入该村唯一的分户投保清单

被保险人汇总承保面积 > 50.00 亩
→ 该被保险人的全部参保地块生成一张单一被保险人保单
```

硬约束：

- 分类依据是承保面积，不是地块几何面积或地块数量。
- 先将该被保险人全部地块承保面积按内部 4 位小数精度求和，再使用四舍五入后的 2 位亩数作为分类面积；分类面积 `≤ 50.00` 亩进入分户清单，分类面积 `≥ 50.01` 亩单独出单。这样页面展示值与分类结果一致，不出现显示 50.00 亩却被单独出单的情况。
- 不得将一个被保险人的地块拆分到清单和单一型保单中规避阈值。
- 不得把前 50 亩放入清单、超出部分单独出单。
- 同一被保险人在同一分类范围内只能采用一种承保方式。
- 同村、同年度、同产品和期间只有一张分户清单型保单。
- 单一型保单数量、分户清单户数和最终参保地块数都由数据归集与面积汇总结果产生，不预设固定数量。

### 4.3 投保人与被保险人

- 单一型保单只有一个被保险人。
- 单一型保单的投保人与被保险人允许不同。
- 分户清单型保单的投保人可以是个人或组织；V1 固定数据使用“龙江村股份经济合作社”。
- 分户清单每行只对应一个被保险人。
- 同一张分户清单内，一个地块只能归属一个被保险人汇总项。
- 分户清单仅保存当前有效汇总项，不设置“正常 / 批改 / 退保”等行状态。
- 分户清单中的自缴保费归属于各被保险人汇总项，保单自缴总额由各行汇总。

## 5. 地块承保与历史规则

### 5.1 地块承保面积

- 地块几何面积与承保面积是两个独立概念。
- 每条承保明细直接保存明确承保面积，不保存承保比例。
- 必须满足 `0 < 承保面积 ≤ 地块几何面积`。
- 承保比例仅由“承保面积 ÷ 几何面积”计算展示。
- 允许部分承保。
- 部分承保时高亮整个地块，并同时展示几何面积、承保面积和比例；V1 不绘制没有空间依据的承保子区域。
- 固定保单数据只关联稳定的基础地块 ID；用户后来新增的人工地块默认没有保单。

### 5.2 同期重复承保

- 同一地块不得出现在保险期间重叠的多张当前有效保单中。
- 三种当前承保关系——单一型保单、分户清单项、其他当前有效保单——对地块必须互斥。
- 历史已到期保单允许与当前保单关联同一地块，用于展示续保历史。

### 5.3 历史快照

- 历史保单保留签单时的主体、清单、地块承保面积、计价参数和金额快照。
- 历史数据不按当前地块面积、当前种植档案或当前年度分组重新计算。
- 每个年度按当年签单时汇总面积保存其承保分类结果，不用当前年度的 50 亩结果反向重分类历史保单。
- 同一地块的当前保单与历史保单在详情中分组显示。

## 6. 固定业务数据生成规则

### 6.1 数据来源与稳定性

- 保单、主体、投保清单、地块承保明细和理赔摘要使用版本化只读 JSON 文件维护。
- 数据固定、可重复生成、刷新不变，不在浏览器首次进入时随机生成。
- 保单不可在 V1 页面创建、编辑或删除。
- 生成脚本使用固定随机种子；相同输入必须产生相同 ID、主体归属和金额。
- 不从参考截图或真实资料抽取主体名称、保单号、金额组合或敏感信息。

### 6.2 参保地块筛选

参保集合采用“规则初选 + 检查地图 + 人工确认 + 固定结果”：

1. 数据源仅使用龙江村基础地块。
2. 排除无效几何、面积字段缺失及明显异常地块。
3. 优先选择空间连续、适合形成经营单元的地块。
4. 以全村基础地块总数为分母，未参保地块数量不得超过 10%；参保地块占比不得低于 90%。
5. 对当前 1,533 个基础地块，未参保地块最多为 `floor(1533 × 10%) = 153` 块，即最多 9.98%；至少 1,380 块进入承保体系。若基础地块总数变化，按新总数重新向下取整，不能沿用 153。
6. 10% 约束按地块数量计算，不按面积计算；生成报告同时记录未参保地块面积及其占全村面积比例，供人工检查面积分布是否异常。
7. 不以固定参保户数或单一型保单数硬凑结果；满足参保比例后，被保险人归属和保单数量由空间归集及 50 亩分类产生。
8. 规则初选后生成检查地图，由项目人员同时确认“是否参保”和“被保险人归属”。
9. 人工确认结果保存为版本化固定清单，至少包含地块 ID、参保状态、被保险人 ID、确认日期和确认人代号；后续生成只能读取已确认版本，不得自动覆盖。
10. 最终结果必须通过自动指标和检查地图复核，页面运行时不重新筛选或分配。

### 6.3 经营单元空间归集

造数顺序必须是：

```text
筛选参保地块
→ 按相邻、近邻和局部空间关系形成经营单元
→ 将经营单元分配给被保险人
→ 确定每块承保面积
→ 按被保险人汇总承保面积
→ 根据 50 亩阈值产生承保方式
```

不得先预设单一型保单，再从村内不同位置拼凑地块超过 50 亩。

空间规则：

- 同一被保险人的多个地块优先直接相邻或近邻。
- 道路、沟渠分隔但距离较近的地块可属于同一经营单元。
- 允许一个主要地块组和少量近距离次要地块组。
- 单一型保单不得依赖远距离孤立地块才能超过 50 亩。
- 如果一个紧凑经营单元不超过 50 亩，不得从远处补地块将其强行变成单一型保单。
- 分户清单中的一户多块同样应形成合理经营单元。

龙江村地块实测基线（2026-07-31）：

| 指标 | 实测值 |
|---|---:|
| 地块数 | 1,533 |
| 地块总面积 | 约 2,867.99 亩 |
| 地块面积中位数 | 1.22 亩 |
| 村域地块范围 | 约 2.2 km × 2.0 km |
| 与其他地块直接接边的地块 | 约 98.1% |
| 紧凑聚合超过 50 亩的中位地块数 | 约 30 块 |
| 紧凑聚合超过 50 亩的中位半径 | 约 114 m |
| 紧凑聚合超过 50 亩的中位最大跨度 | 约 218 m |
| 95 分位聚合半径 / 最大跨度 | 约 190 m / 333 m |

由于 98.1% 地块与其他地块接边，“是否连通”不能单独作为经营单元判据。V1 使用组合验收：

- 单一型保单原则上以一个主要空间地块组为主。
- 主要地块组的承保面积占该被保险人总承保面积原则上不低于 70%。
- 单一型地块最大跨度原则上不超过约 350 m；超过时必须在检查地图中人工确认存在合理的近距离多地块组关系。
- 不允许出现跨越村域主要空间分区的孤立拼接。
- 自动指标只负责发现异常，不替代检查地图的人工确认。

近邻阈值不得作为一个脱离数据的全局常量拍死；生成脚本应基于局部地块尺度和间距扩张，并输出实际距离指标。

### 6.4 部分承保

- 大多数参保地块使用整块承保。
- 少量地块使用明确的部分承保面积，以覆盖部分承保展示和计算场景。
- 不固定部分承保地块数量或统一比例。
- 部分承保不得被用于人为改变被保险人 50 亩分类结果而制造指定数量的保单。

### 6.5 空间与业务校验产物

每次生成必须输出：

- 每个被保险人的地块数、几何面积、承保面积和承保方式。
- 空间地块组数量。
- 主要地块组承保面积占比。
- 最远两个地块的距离。
- 孤立地块列表。
- 50 亩阈值分类检查。
- 当前有效保单地块重复检查。
- 分户清单与单一型保单互斥检查。
- 按被保险人着色的检查地图；单一型、清单型和异常地块使用可区分样式。

最终数量必须作为生成报告记录，不作为需求预设。

## 7. 页面入口与交互边界

### 7.1 地块选择

仅在正常查看态支持详情：

- 点击可见普通地块或已保存人工地块，选中并打开右侧详情面板。
- 当前地块使用主高亮。
- 点击地图空白或按 `Esc` 关闭详情并清除高亮。
- 进入新增、绘制、修形或筛选模式时关闭详情，且这些模式下点击地块不打开详情。
- 当前地块被隐藏或人工地块被删除时关闭详情。
- 用户关闭地块图层时关闭详情并清除高亮；若存在未保存种植档案，先显示确认，用户取消后地块图层保持开启且编辑现场不变。
- 切换村、返回上级或通过面包屑跳转时关闭详情与全部保单高亮。
- 种植档案存在未保存修改时，关闭详情、切换地块或离开当前村须显示项目内自定义确认弹窗。

### 7.2 信息架构

详情采用：

```text
右侧固定详情面板
├── 固定地块摘要
├── 地块档案 / 承保信息（双页签）
└── 完整投保清单（右侧二级宽抽屉）
```

默认页签：

- 有当前有效保单：打开“承保信息”。
- 无当前有效保单：打开“地块档案”。
- 只有历史保单：打开“地块档案”，摘要显示“当前未承保”。

桌面端完整投保清单使用右侧宽抽屉，保留地图可见；窄屏转为全屏二级页，不产生页面横向滚动。

## 8. 固定地块摘要

面板顶部始终可见，至少展示：

- 地块短编号。
- 所属村和地块来源。
- 当前承保状态。
- 地块几何面积。
- 当前作物；无当前档案时显示“未标注”。
- 当前承保面积；无当前保单时显示 `—`。
- 关闭按钮。

当前种植档案的作物与当前有效保单承保标的不一致时：

- 两者分别保留原值。
- 摘要下显示明确提醒，例如“当前标注为小麦，保单承保标的为水稻”。
- 提醒不阻止种植档案保存，不弹出额外选择，也不自动修改核查状态；作物和核查状态均按用户输入保存。

## 9. 地块档案页签

### 9.1 基础信息

展示：

- 完整地块编号。
- 地块来源：基础地块 / 人工新增。
- 地块面积：亩和平方米。
- 所属省、市、县、乡、村。
- 人工地块创建时间和更新时间，仅人工地块显示，可放在“更多信息”折叠区。

### 9.2 种植档案结构

一个地块可保存多个年度、季节记录。每条包含：

- 种植年度。
- 种植季节。
- 作物。
- 品种。
- 种植开始日期。
- 预计或实际结束日期。
- 核查状态。
- 核查时间。
- 备注。

唯一键：`村代码 + 地块 ID + 种植年度 + 种植季节`。

季节枚举：

- 早稻。
- 单季稻。
- 连作晚稻。
- 其他。

约束：

- 同一地块、同一年度、同一季节只能有一条记录。
- 同一年度允许同时存在“早稻”和“连作晚稻”。
- 同一年度的“单季稻”不能与“早稻”或“连作晚稻”并存。
- 品种使用可搜索候选并允许自定义输入；具体候选名单在 fixture 设计阶段确定。
- 种植开始日期和结束日期统一使用 `YYYY-MM-DD`，按自然日比较且起止日均包含在种植期间内；开始日期必须早于结束日期。两者用于判断固定业务日期下的当前档案，不通过“早稻 / 晚稻”等名称猜测日期。
- 核查状态为：未核查 / 已核查 / 需复核。
- “已核查”和“需复核”记录核查时间；V1 不记录核查人员。
- 默认展示固定业务日期对应的当前档案，历史档案折叠显示。

当前档案判定规则：

1. 筛选满足“种植开始日期 ≤ 固定业务日期 ≤ 结束日期”的记录。
2. 同一地块全部种植档案（包括“其他”季节）的种植期间不得重叠，正常数据在任一业务日期最多命中一条。
3. 若异常数据有多条命中，选择种植开始日期最晚的一条作为摘要当前档案，同时在数据校验中报错，不静默接受。
4. 若没有命中，摘要显示“当前未种植”；地块档案仍展示距离业务日期最近的当年记录，并明确其季节和期间。
5. “当前作物与承保标的不一致”只比较当前档案；没有当前档案时不触发不一致提醒。

### 9.3 初始档案与本机覆盖

- 固定版本化 JSON 提供初始种植档案，`localStorage` 只保存用户覆盖和用户新增记录。
- 所有当前有效参保基础地块均预置 2025 年水稻种植档案；部分当前未参保基础地块也预置水稻档案，具体覆盖结果由固定 fixture 记录。该档案覆盖率与“全村未参保地块不超过 10%”是两个独立口径。
- 只有历史保单、当前未承保的地块按当前未参保处理。
- 初始档案覆盖早稻、单季稻和连作晚稻，并包含少量“需复核”状态；初始数据不制造作物与水稻承保标的不一致，作物不一致只由用户后续编辑产生。
- 预置档案不可删除，只能编辑形成本机覆盖或恢复初始值。
- 用户新增的年度、季节记录可以删除。
- 已有记录的年度和季节不可编辑；需要变更时新增正确记录。
- “恢复初始档案”清除当前地块全部本机覆盖和用户新增记录，恢复固定 JSON 中该地块的完整状态；执行前必须二次确认。

### 9.4 查看与编辑

- 默认使用阅读态展示，不让面板长期呈现为录入表单。
- 点击“编辑”后切换为表单。
- 编辑状态下在面板底部固定显示“取消 / 保存”。
- 没有档案时显示空状态和“添加种植信息”。
- 普通地块与人工地块均可保存种植档案。
- 种植档案使用独立版本化 `localStorage`，不修改原始地块 GeoJSON。
- 按村代码和地块 ID 隔离。
- 取消不覆盖已保存内容。
- 删除人工地块时同步删除其种植档案，避免孤立记录。
- 写入失败时保留编辑现场，不部分提交。

## 12. 地图联动规则

### 12.1 高亮层级

1. 当前地块：主高亮。
2. 当前被保险人的其他地块：次级高亮。
3. 用户主动选择“查看整张保单覆盖范围”后，同一保单其他被保险人的地块：更弱的第三级高亮。

默认不把同一清单型保单下所有被保险人的地块混为同一组。

### 12.2 通用规则

- 只高亮当前村内、当前可展示的关联地块。
- 已隐藏地块不因保单联动重新显示。
- 关闭详情、切换保单、切换清单项、切村或进入地块操作模式时清除相应高亮。
- 点击完整清单中的被保险人行时，地图联动到该户地块。
- 查看该户地块后，点击同一被保险人的另一块高亮地块，切换固定摘要和当前地块承保明细，但保持同一保单、同一被保险人上下文和“承保信息”页签。
- 完整清单打开时点击其他地块，关闭宽抽屉并切换到新地块详情。
- 宽抽屉按第一次 `Esc` 返回保单详情，再按一次 `Esc` 关闭详情；未保存种植档案确认优先于这些关闭动作。

## 13. 金额、面积与汇总规则

### 13.1 精度

- 面积内部保留 4 位小数，界面显示 2 位。
- 金额统一按人民币“分”存储和计算，界面显示 2 位。
- 保单和清单汇总直接加总明细的分值，不对展示字符串再次计算。
- 比例使用高精度值计算，界面按统一格式显示。

### 13.2 舍入顺序

统一采用十进制四舍五入，不使用二进制浮点直接计算金额：

1. 每条地块承保面积以 4 位小数亩保存。
2. 每条地块保险金额按“承保面积 × 每亩保险金额”计算并四舍五入到分。
3. 被保险人保险金额直接加总其地块保险金额分值。
4. 被保险人总保费按“保险金额 × 费率”计算并四舍五入到分。
5. 财政补贴按“总保费 × 补贴比例”计算并四舍五入到分。
6. 被保险人自缴使用“总保费 - 财政补贴”，保证两者严格加总为总保费。
7. 保单级金额直接加总被保险人级分值，不用保单总面积重新计算。

页面使用 2 位面积和金额做人工复核时允许出现由展示舍入造成的分级微小差异；自动校验必须使用内部面积和金额分值。

### 13.3 地块承保明细

```text
地块保险金额
= 地块承保面积 × 每亩保险金额
```

### 13.4 被保险人汇总项

```text
被保险人承保面积
= 该被保险人全部有效地块承保面积之和

被保险人保险金额
= 全部地块保险金额之和

被保险人总保费
= 被保险人保险金额 × 费率

被保险人总保费
= 财政补贴 + 被保险人自缴
```

在 V1 统一参数下，也应满足：

```text
每亩总保费 = 40 元
每亩财政补贴 = 32 元
每亩自缴保费 = 8 元
```

### 13.5 保单汇总

单一型保单：

```text
总地块数 = 被保险人有效承保地块去重数量
总承保面积 = 全部地块承保面积之和
```

分户清单型保单：

```text
总户数 = 有效清单汇总项数量
总地块数 = 全部清单项关联地块去重数量
总承保面积 = 全部清单项承保面积之和
总保险金额 = 全部清单项保险金额之和
总保费 = 全部清单项总保费之和
财政补贴 = 全部清单项财政补贴之和
自缴金额 = 全部清单项自缴金额之和
```

所有公式须通过生成时校验和前端单元测试。

## 14. 理赔摘要

### 14.1 粒度

- V1 只展示保单级和被保险人级两级摘要。
- 分户清单型保单的被保险人摘要关联具体清单汇总项。
- 单一型保单的被保险人摘要关联唯一被保险人。
- V1 不声明具体受损地块，不保存逐地块损失分摊，也不展开逐笔报案列表。

### 14.2 状态与金额

理赔状态：

- 查勘中。
- 核赔中。
- 已结案。

无报案不是状态，显示“保障期内暂无报案”。

区块标题固定为“该被保险人理赔摘要”，不得使用“当前地块理赔”或暗示当前地块已出险的措辞；理赔摘要不参与地块高亮。

被保险人有一次或多次报案时展示：

- 报案次数。
- 估损金额合计。
- 已赔金额合计。
- 最近一次报案日期。
- 最近一次报案状态。

处理中至少显示估损金额；已结案显示估损和已赔金额。

### 14.3 保单级汇总

清单型保单显示：

- 报案被保险人数。
- 查勘中、核赔中、已结案的数量。
- 估损金额合计。
- 已赔金额合计。

不得将不同被保险人的理赔进度强行合成一个保单状态。保单级金额必须等于其被保险人级摘要汇总。

## 15. 数据模型要求

保单类型显式保存：

```ts
type PolicyInsuredMode = 'single_insured' | 'insured_roster'
```

主要实体：

```text
Policy                 保单
Party                  投保人或被保险人
EnrollmentList         投保清单；清单型保单一对一
EnrollmentItem         被保险人汇总项；投保清单一对多
ParcelCoverage         地块承保明细
CultivationRecord      地块种植档案
ClaimSummary           保单级或被保险人级理赔摘要
```

关键引用：

- `Policy.insuredMode` 明确保单类型。
- 单一型保单引用唯一 `insuredPartyId`。
- 分户清单型保单引用唯一 `enrollmentListId`。
- `EnrollmentItem` 引用唯一 `insuredPartyId`。
- `ParcelCoverage` 必须引用 `policyId` 和 `parcelId`。
- 清单型 `ParcelCoverage` 还必须引用 `enrollmentItemId`。
- 普通地块和人工地块使用稳定地块 ID；固定保单 fixture 只引用基础地块。
- `ClaimSummary` 引用保单；被保险人级摘要额外引用 `insuredPartyId` 或 `enrollmentItemId`，不引用地块。
- `CultivationRecord` 使用村代码、地块 ID、年度和季节组成业务唯一键。

只读保单 JSON 和本机种植档案必须各自包含 schema 版本。具体文件路径、`localStorage` key、损坏数据兜底和迁移实现由实施计划确定，不改变本需求的数据边界。

## 16. 数据安全与界面表达

### 16.1 业务界面

- 不显示“演示数据”“合成数据”“虚构示例”等标识。
- 姓名、主体名称和保单信息按正常业务形式展示。
- 不显示承保机构名称、Logo 或“某保险公司”占位。
- 不把 AI 或人工地块描述为确权、测绘结论。

### 16.2 内部数据治理

以下信息不得进入 fixture、页面、日志或截图产物：

- 从参考资料复制的真实姓名。
- 身份证号或其他证件号。
- 手机号码。
- 银行卡号或银行账号。
- 开户行。
- 手写签名。
- 真实保单号。
- 能反向识别参考资料中人员的信息组合。

允许使用自然、真实感的姓名和组织名称，但必须由独立名单生成，不能从现有资料抽取。保单号使用项目内生成的 22 位编号。

参考投保清单只用于理解“每行是一个被保险人汇总项”的业务结构，不作为数据来源。

## 17. 不在 V1 范围

- 创建、编辑、删除或审核保单。
- 编辑投保清单、被保险人汇总项或承保面积。
- 将用户人工新增地块动态关联到保单。
- 批单、退保、续保审批和缴费流水。
- 后端同步、多人协作、权限管理和审计日志。
- 报案、查勘、核赔和赔付操作。
- 逐笔报案列表和逐地块损失明细。
- 承保子区域几何。
- 修改普通地块几何。
- 在页面运行时随机生成业务数据。

## 18. 验收标准

### 18.1 详情与种植档案

1. 正常查看态点击普通地块或人工地块可打开详情；新增、绘制、修形和筛选模式不打开详情。
2. 固定摘要正确显示地块、当前作物和当前承保信息；页签默认规则正确。
3. 地块档案默认阅读态，点击编辑后可保存或取消；写入失败时保留现场。
4. 一个地块可保存多年度、多季节记录；年度与季节唯一性、单双季互斥及种植期间不重叠规则生效。
5. 固定业务日期只命中一条当前档案；无命中时显示“当前未种植”，异常多命中时校验失败且摘要采用开始日期最晚记录兜底。
6. 当前作物与承保标的不一致时分别展示并提示，不阻止保存。
7. 有未保存档案时切换地块、关闭详情或离开村，显示项目内确认弹窗。
8. 删除人工地块后没有孤立种植档案。

### 18.2 承保分类与计算

9. 每个被保险人按同村、同年度、同产品和期间汇总承保面积。
10. `≤ 50.00` 亩的被保险人全部进入唯一分户清单；`> 50.00` 亩的被保险人全部地块生成单一型保单。
11. 同一被保险人不同时存在于分户清单和单一型保单，不能拆分规避阈值。
12. 每条承保明细满足 `0 < 承保面积 ≤ 地块几何面积`。
13. 同期当前有效保单不重复承保同一地块；历史保单允许关联续保地块。
14. 地块、被保险人、清单和保单的面积、保额、保费、补贴与自缴汇总满足公式和精度规则。
15. 状态由固定业务日期计算，签单日期、保险期间和状态一致。

### 18.3 空间合理性与固定数据

16. 同一被保险人的地块优先相邻或近邻，检查地图不存在为超过 50 亩而跨村域远距离拼凑的单一型保单。
17. 单一型保单主要地块组承保面积占比原则上不低于 70%；最大跨度超出约 350 m 时有明确人工复核记录。
18. 每次生成输出空间组数、主要组占比、最大距离、孤立地块、分类和重复承保检查结果。
19. 规则初选后经人工确认的固定清单包含地块 ID、参保状态、被保险人归属、确认日期和确认人代号，生成脚本不自动覆盖确认版本。
20. 当前基础地块未参保数量不超过全村基础地块总数的 10%；当前 1,533 块数据最多 153 块未参保、至少 1,380 块参保，并同时报告未参保面积占比。
21. 固定随机种子和相同输入产生相同业务 ID、归属和金额；最终主体数和保单数记录在生成报告而非预设。
22. 参保集合中同时存在单一型、清单型和暂无承保地块，能够覆盖三种详情状态。

### 18.4 面板、清单与地图联动

23. 详情使用固定摘要和双页签；有当前保单默认打开承保信息，无当前保单默认打开地块档案。
24. 完整投保清单在桌面端使用右侧宽抽屉，窄屏使用全屏二级页，无横向页面滚动。
25. 完整清单每行是一户汇总，支持名称和主体编号搜索、每页 20 条分页；搜索和分页不改变整单汇总，理赔列只显示次数和最近状态。
26. 当前地块、同一被保险人其他地块、同一保单其他被保险人地块的三级高亮可明确区分。
27. 点击同户其他地块时切换当前地块但保持被保险人和承保页签上下文；宽抽屉的两级 `Esc` 行为正确。
28. 已隐藏地块不因保单联动重新显示；关闭详情、切村、关闭地块图层或进入地块操作模式后高亮清除，未保存确认取消时地块图层保持开启。
29. 无当前保单地块显示明确空状态；人工新增地块默认无保单。
30. 历史保单显示签单时快照，不按当前面积、档案或分类重新计算。

### 18.5 理赔与机构中立

31. “该被保险人理赔摘要”显示次数、估损、已赔、最近日期和最近状态，不展开报案列表、关联受损地块或暗示当前地块出险。
32. 清单型保单显示分状态户数和金额汇总，且与被保险人级摘要加总一致。
33. 无报案时只显示“保障期内暂无报案”，不展示一排零值。
34. 业务界面不显示承保机构、Logo、演示/合成/虚构标识，也不出现被禁止的个人敏感字段。
35. 原始地块 GeoJSON、现有隐藏地块存储和人工地块存储格式不被改变。

## 19. 实施计划需确定的技术项

以下不再作为产品需求待定项，由实施计划依据现有架构确定：

1. 只读业务 JSON 的目录、拆分粒度和 schema 文件。
2. 种植档案 `localStorage` key、版本、迁移和损坏数据兜底。
3. 详情面板和宽抽屉的精确尺寸、颜色、图标与动效。
4. 地图三级高亮的具体 Leaflet pane 和样式 token。
5. 水稻品种搜索候选名单。
6. 生成脚本依赖、固定随机种子、检查地图格式和报告路径。
7. 空间异常人工复核记录的存储格式。
