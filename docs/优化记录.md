## 2026-08-31：巴威村级风险时序演示优化

### 问题

原演示数据在巴威影响期间反复使用同一批数百个风险村，导致低、中、高风险分布和地图聚合变化不明显；若简单扩大数量，又会增加村界绘制压力。

### 修复方案

- 离线生成器在 `26/71～43/71` 的 18 个影响节点，按由南向北的空间中心和稳定排序生成风险迁移；历史轨迹、降雨和灾损计算数据仍保留。
- 中/高风险峰值限制为 600 村，至少 12 个节点具备不同村级状态；影响段以 1000ms/节点展示，其余无风险段 250ms/节点快进。
- 村界图层维持差量更新，单帧高亮不超过 250 村；省、市级继续只渲染区县聚合徽标。
- 校验器增加影响节点范围、风险峰值、状态变化和确定性重算检查；面板数据随预警产物离线重算。

### 结果

新产物覆盖 18/71 个影响节点，峰值节点为 2026-07-11 11:00：高 280 村、中 320 村、低 270 村，中/高合计 600 村；全窗口累计曾预警村 5,451 个。运行期仍读取静态 JSON，不新增网络请求。

## 2026-08-31：预警聚合徽标等级缓存修复

### 问题

演示播放到 `39/71（2026-07-11 16:00）` 时，右侧面板显示高风险 `163` 村、中风险 `281` 村，但地图上 `161`、`98`、`22` 三个中风险区县徽标沿用红色。正确状态应为：高风险徽标 `86 + 10 + 5 + 62 = 163`，中风险徽标 `22 + 98 + 161 = 281`。

### 根因

预警图层为避免高频播放时逐帧重建图层，旧缓存仅比较中/高风险村的编码集合。相邻节点中村集合不变、风险等级发生中/高切换时，缓存误判为无变化，跳过重绘；面板逐节点重新统计，因此出现面板与地图颜色不一致。

### 修复方案

- 缓存签名改为排序后的 `村编码:风险等级`，中/高风险村任一等级变化都会触发重绘。
- 区县徽标仍保持既有口径：数字为该县中/高风险村总数，颜色为该县当前最高风险等级。
- 新增单元测试，锁定“村集合不变、等级变化时签名必须变化”的回归场景。

### 全节点审计

基于 `web/public/data/disaster/warnings.json` 对 71 个节点的相邻状态进行扫描，发现旧缓存会漏刷 3 组节点：

| 相邻播放节点 | 时间 | 等级变化（中/高风险村数） |
|---|---|---|
| 28/71 → 29/71 | 2026-07-11 05:00 → 06:00 | 中 380 / 高 281 → 中 217 / 高 444 |
| 38/71 → 39/71 | 2026-07-11 15:00 → 16:00 | 高 444 → 中 281 / 高 163 |
| 41/71 → 42/71 | 2026-07-11 18:00 → 19:00 | 高 163 → 中 163 |

新签名在上述三组节点均发生变化，因此会重新绘制聚合徽标和村级边界样式。

## 维护规则

- 每项新增优化必须记录：用户可见问题或目标、根因、修复范围、验证命令及实际结果。
- 性能优化不得改变风险统计和地图呈现口径；如改变口径，先同步对应现役需求与验收清单。
- 运行产物不入 Git 的数据问题，应同时记录生成命令和数据校验结果，避免将 HTML 回退错误误判为业务 JSON。
